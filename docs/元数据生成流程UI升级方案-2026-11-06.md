# 元数据 BMF 生成流程 UI 升级方案

日期：2026-11-06  
状态：已实施，关键回归及真实组件联调已验收。第 2 节保留实施前诊断；实测数据、截图与全仓门禁限制见 [实施验收](D:/AItool/winapp/nc-workbench/docs/元数据生成工作台实施验收-2026-11-06.md)。

## 1. 推荐方案与范围

将现有「生成中心」升级为 **当前 BMF 的产物工作台**。用户一次查看这份 BMF 的整套启用产物，在同一页完成配置、选择、差异检查和文件写入。

主流程：**已保存的当前 BMF → 配置 → 产物与差异 → 写入确认 → 结果与下一步**。

步骤条表示当前进度，文件清单和预览始终留在工作区，用户可以随时回到配置和检查阶段。首次沿用 BMF 推导的代码风格，减少必填项；调整配置后统一「更新产物」。

本轮主要升级生成体验、写入契约和性能。已有生成器继续负责产物内容，后续扩充产物种类沿用现有能力路线。

| 当前真实能力 | 页面应如何表达 |
| --- | --- |
| Java VO、聚合 VO、枚举 VO | 根据模型及启用选项形成清单 |
| 可选接口、查询 VO、测试桩 | 高级配置中明确启用条件；测试文件标注为测试桩 |
| 8 种 SQL 方言 | 每次生成选择一种方言，明确显示当前值 |
| `meta/{component}.registry.json` | 标为「注册建议清单」，说明用途和后续操作 |
| 目录对比、手改保护、覆盖前备份、生成清单 | 在逐文件状态、写入确认和结果中呈现 |
| `sourceRefs`、`dependsOn`、编码、换行、SHA | 用于来源与依赖查看、文件属性和预览核对 |

菜单、单据/查询/打印模板、元数据发布 SQL 等新生成能力，仍按 [UAP 生成能力路线](D:/AItool/winapp/nc-workbench/docs/NCForge-对标UAP-Studio-生成能力-方案-2026-11-05.md) 单独实施。页面按实际出现的产物分组。

## 2. 现状与需要优先修复的问题

现有页面已有分组清单、文本预览和专用样式，元数据未保存时也已有进入生成的保护。主要问题是操作顺序、状态保持和写入结果不够清楚。

| 现状 | 对使用的影响 | 升级处理 |
| --- | --- | --- |
| 配置、校验、目录、覆盖开关、文件、DDL 执行和结果纵向堆叠 | 低窗口中频繁滚动，关键操作和上下文分离 | 分区工作台，内部滚动，固定底部操作 |
| 每次配置输入立即生成，生成期间禁用配置；新计划重置选择 | 连续输入中断，反复勾选和找文件 | 配置草稿＋统一更新，按稳定 ID 恢复选择 |
| 目录每个字符变化触发对比 | 重复请求，检查结果容易落后于当前目录 | 防抖并标记检查版本，过期响应丢弃 |
| 有状态标签，缺少现有文件与新文件的文本差异 | 用户难判断修改内容和覆盖风险 | 逐文件只读差异，窄区域使用行内模式 |
| 清单缺搜索、状态筛选和折叠组 | 产物较多时难以定位 | 搜索、筛选、组勾选、可见区渲染 |
| 来源与依赖数据未有效呈现 | 产物与元数据模型脱节 | 来源入口与依赖列表，回到编辑页可定位 |
| 默认展示解析/图/渲染耗时和「预算 10s」 | 主流程被诊断信息占据 | 收入可展开的诊断区 |
| 切换元数据工具会卸载生成组件 | 配置、选择和活动文件丢失 | 在当前 BMF 的工作区会话中保存轻量状态 |
| 选中 DDL 就在主页面展开执行区 | 文件生成与数据库执行混在一起 | 生成完成后的独立后续动作 |

### 必须先统一的写入契约

1. **空选择零写入。** 当前前端「全不选」传空数组，后端把空数组作为全部产物处理；按钮也没有检查选中数量。前后端都要修正。全选明确传全部产物 ID；兼容旧调用时，显式空数组与历史省略参数的语义必须分开。
2. **「待更新」确实能够更新。** 当前状态判断允许写入 `outdated`，底层 `overwrite=false` 又跳过所有已有文件。应根据文件归属和旧基线判断允许的更新，分别处理正常更新与手改覆盖。
3. **写入与预览绑定。** 当前写入会重新读取 BMF 并生成，没有校验用户刚刚查看的版本。源文件、配置、目标路径或目标文件变化后，需要重新检查再写入。
4. **对比完成是写入前提。** 目录无效、对比失败、检查结果过期或仍在检查时，操作栏给出具体原因，停止写入。
5. **结果和清单反映实际操作。** 当前清单依据整个计划生成，异常可能在部分文件已经写入后直接返回。新契约须保留逐文件成功、跳过和失败结果，并以真正写入的内容更新基线。

## 4. 五步交互

### ① 打开当前 BMF

沿用已保存草稿的入口保护。首次用当前 BMF 推导默认配置，自动生成一次预览；顶部显示真实的加载/校验状态。

同一个 BMF 切到图形、属性表或校验页再返回，保留配置草稿、勾选、活动文件、筛选和滚动位置。恢复时核对 BMF 版本；源已变化则将预览标为过期。

### ② 配置

- 「常用」展示代码风格、一个 SQL 方言、包根和输出目录；「高级」展示聚合/枚举、接口、查询、测试桩、外键、仅扩展表等现有选项。
- `basePackage` 继续表达**包根**；非空值会追加组件名称，旁边展示实际生成包名和源码路径。
- 初始继续沿用 BMF 目录下的 `gen`，源码根沿用现有 `src/public`、`src/test`；最终路径明确到文件。
- 配置输入保持可编辑，修改后显示「配置已修改，预览待更新」，禁用写入；点击「更新产物」一次应用草稿。生成期间的新输入不能被旧响应覆盖。
- 输出目录输入建议防抖 300ms，失焦或回车立即检查。仅输出目录改变时重新计算路径和对比，复用当前生成内容。
- 校验错误提供「回到元数据修复」入口；警告显示摘要，可展开详情。耗时放在诊断区。

### ③ 选择产物与检查差异

首次勾选当前启用产物，注册建议清单保持可选；手改和冲突默认保留。配置更新后，已有稳定 ID 保持勾选和活动状态，新出现项使用默认规则，消失项清除。

| 文件状态 | 默认实际行为 | 可用操作 |
| --- | --- | --- |
| 新建 | 选中则创建 | 预览、取消选择 |
| 已一致 | 跳过，计入已检查 | 查看内容和路径 |
| 待更新 | 确认仍与上次生成基线一致后更新 | 查看差异、取消选择 |
| 已手改 | 保留原文件 | 看差异；逐文件选择「覆盖并备份」 |
| 冲突/无可信基线 | 保留原文件 | 查看冲突原因；确认差异后逐文件覆盖并备份 |
| 旧产物 | 保留并列在独立组 | 查看路径和历史归属 |
| 未检查/检查失败 | 阻止写入 | 修正目录或重新检查 |

选择控制写入范围，文件决策控制对已有文件的处理。全选不会把手改文件变成强制覆盖；筛选后组勾选应明确标为「选择当前筛选项」，底栏始终计算总选择。

「与现有文件比较」必须读取对应目标文件，并显示原内容与本次生成内容。编码无法可靠解码时说明原因，保持保留决策；编码和换行按产物契约展示，写入校验使用原始字节。

「来源与依赖」先展示现有数据能定位的实体/枚举。点击来源可回到元数据并定位，返回后恢复生成状态。依赖未选中时提示用户检查并提供勾选入口；未掌握项目依赖信息时不能断言代码一定无法编译。字段级溯源等生成器尚未提供的数据按后续能力扩展。

### ④ 写入确认

底栏主操作随状态变化：

| 当前状态 | 主操作/反馈 |
| --- | --- |
| 配置或源预览已过期 | 「更新产物」 |
| 校验错误、对比失败或目录无效 | 显示可定位的原因，写入禁用 |
| 选中 0 个文件 | 「请选择产物」，写入禁用 |
| 全部一致或全部保留 | 显示「没有需要写入的文件」 |
| 已就绪 | 「检查并确认写入」 |
| 正在写入 | 「写入中…」，冻结本次执行配置 |
| 完成 | 「查看结果」和打开文件/目录入口 |

确认层只集中展示最终输出目录、选中范围、新建/更新/保留数量，以及逐文件覆盖和备份决策。普通文件不用逐个确认；涉及手改覆盖时，确认层明确列出文件。

确认后再次核对源、配置、路径和目标文件版本。任一发生变化，则指出变化项并返回检查，用户重新确认。即使前端被绕过，后端也执行空选择、路径、版本、编码和逐文件决策检查。

### ⑤ 结果与下一步

- 汇总真实新建、更新、跳过和失败数量，逐文件展示原因；可打开实际存在的文件、输出目录、清单和备份。
- 中途失败时保留已完成结果，明确剩余项；重新检查后重试剩余项。
- 清单记录本次真实操作，未选中或保留文件继续使用原基线。失败文件不能被标记为已更新，清单自身写入失败也单独报告。
- SQL 作为独立后续动作进入执行界面，或在数据库工作台建立待执行文档。继续沿用现有测试库限制和执行确认，保留 BMF 来源及方言上下文。
- 进度只显示真实阶段和已返回的文件结果。后端尚无进度事件时使用不定进度提示。

## 5. 接口与状态调整

### 前端

将生成状态分为配置草稿、有效预览、目录检查、文件选择/决策、执行结果。使用集中 reducer 或现有会话机制管理相关状态，避免拆成大量独立 effect。

建议职责：工作台容器、配置面板、产物树、活动文件预览、写入确认/结果。组件和 Hook 遵守项目单文件 ≤300 行及现有状态/effect 门禁；按实际职责拆分。

保留当前 BMF 会话的轻量配置和导航状态；大段文本与差异只在活动预览中按需保留，切到其他 BMF 时释放或采用有界缓存。请求带版本标识，旧响应不更新当前页面；卸载后不回写状态。

### 后端

建议将计划、规则校验和目录对比组合为一次预览调用，或先在内部共享已解析的模型和计划，保留旧命令适配。首次预览解析一次；切文件、搜索、勾选不重新生成。

| 契约 | 必要调整 |
| --- | --- |
| 预览输入 | 已保存 BMF、完整生成配置、输出目录、生成范围 |
| 预览输出 | 计划、校验问题、目标状态、来源/依赖、预览版本和诊断耗时 |
| 写入输入 | 显式产物 ID、逐文件决策、预览版本、目标文件期望版本 |
| 写入前检查 | 重新读取可信源，复用同一模型完成校验/生成；核对所选产物的内容、路径和字节版本，再写入 |
| 写入结果 | 逐文件真实新建/更新/跳过/失败，详细原因、实际路径、备份及清单结果 |

**指纹的实际含义：**当前 `inputSha256` 是组件 namespace/name、BMF 原始字节和内容配置指纹的组合，不能当成单独的 BMF 文件 SHA；`profileSha256` 刻意排除了源码根等路径字段。见 [指纹实现](D:/AItool/winapp/nc-workbench/desktop/src-tauri/src/bmf_gen_types.rs)。

因此，写入核对须同时涵盖源输入、完整生效配置、生成范围、最终路径映射、所选产物，以及目标文件的原始字节 SHA/不存在状态。产物文本 SHA 与按 GBK/UTF-8、CRLF 编码后的落盘字节 SHA 分开处理。

第一版采用显式的预览版本和期望状态即可，不必新增长生命周期缓存服务。写入时可以重新生成可信计划一次，但必须与预览一致；目标内容在实际替换前再次核对，新建项处理目标已出现的情况。

单文件沿用现有原子写入与备份能力，结果承认整批可能部分成功。实际发生创建还是替换决定结果标签，避免全局覆盖标记把新文件误报为已覆盖。

## 7. 验收标准

### 正确性

1. 空选择、重复/无效 ID、越界路径、校验未完成和对比失败不会写入文件；后端有覆盖这些行为的测试。
2. 新文件正常创建，未经手改的旧生成文件正常更新，一致文件跳过；默认保留手改和无基线冲突项。
3. 逐文件覆盖仅影响明确选择的项，并能找到备份；结果区新建和替换标签准确。
4. 预览后修改 BMF、包根、源码根、输出目录或目标文件，都能阻止沿用旧确认写入。
5. 编码不可表示、文件占用、备份失败或清单写入失败时，逐文件结果准确，已成功文件不被遗漏；未选中/保留文件的生成基线不被错误推进。
6. 切换工具、更新配置、搜索和组勾选不意外丢失选择；配置变更后旧结果不能恢复写入就绪状态。

### 使用体验

- 用户能直接找到「当前 BMF 会生成什么、写到哪里、改变哪些现有文件」三类信息。
- 校验问题、手改保护和过期检查都有具体原因及处理入口，常用生成无需展开高级选项。
- 在 1920×1080、1366×768、1280×720、1024×640 和低高度窗口中检查深浅主题、较大系统缩放、长路径及多产物；主操作可见、分区可滚动。
- 键盘可完成搜索、移动文件焦点、勾选、差异导航、打开配置和确认，弹层关闭后焦点正确返回。
- 选中 DDL 文件只切换预览；执行走独立动作。

### 性能

以下为原定验收目标，实际测量覆盖范围和数据见实施验收记录：

| 场景 | 验收目标 |
| --- | --- |
| 连续修改配置 | 输入期间不发生成请求，点击更新只应用最新配置 |
| 连续输入目录 | 防抖后检查一次，过期响应不污染当前结果 |
| 切文件/搜索/勾选 | 不读取 BMF、不生成计划；常用规模下交互反馈 P95 ≤100ms |
| 首次预览 | 共用一次解析和计划完成校验/对比；对真实小、中、大 BMF 报告端到端 P50/P95，并与现有页比较 |
| 较大清单 | 用约 1000 项合成清单验证可见区渲染；作为 UI 压力测试单独报告 |
| 内存和加载 | 单活动编辑器；多次切换后检查编辑器/model、文本缓存及监听器释放；遵守现有包体门禁 |

交互反馈指标与大文件差异计算耗时分开记录。较大文件异步准备差异，并明确显示真实等待状态；暂不把未经基线测量的生成秒数作为达成结论。
