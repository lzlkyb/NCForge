## 主要用户风险与旅程

熟练 SQL 开发者的风险是快捷键形成的惯性：执行范围被隐藏时，经验不能替代可见反馈；部分结果排序也不能等同于服务端排序。

跨测试和生产工作的 NC 实施人员，需要持续核对当前会话、结果来源、待提交状态以及基线。当前信息分散，使多标签核对与输出容易反复确认。

四条旅程的改进目标：

1. 写 SQL → 执行：目标、schema、当前会话模式与执行范围可见，执行/停止/错误定位形成闭环。
2. 查数据 → 检查：从数量、完整性到本地筛选/排序、续取/失效都有稳定说明。
3. 固定 A → 比较 B：来源与范围可见，按唯一键对齐、阅读变化、导出差异。
4. 选区 → 输出：行列范围、格式、预览、实际完成摘要一致，切换上下文不改变任务。
