# NC 服务与控制台升级方案

日期：2026-11-06。状态：用户已确认交互稿，P0/P1 已实施；产品验收与全仓门禁限制见 [实施验收](./NC服务与控制台实施验收-2026-11-06.md)。保留代码，不打安装包、不自动提交。

本方案针对截图中的代码工作台底部 NC 服务面板，同时覆盖中间件、Swing 客户端、启动任务、元数据投送与运行日志。目标是让 NC 开发者快速判断「哪一个进程处于什么状态、下一步能做什么、异常在哪里」，沿用现有浅深主题、玻璃与实色材质，以及停靠工作台结构。

## 2. 当前问题及源码依据

1. **日志正文被上方内容挤压。** 工具条、中间件卡、客户端卡、投送条、来源标签和筛选条连续纵向叠放，底部面板最小 360px 并不能保证正文可读。截图里服务区域很宽，正文却仅显示一两行。
2. **普通启动文字被误判成异常栈。** `serverLog.parseLine()` 只要没解析到时间、线程或级别，就设置 `stack=true`。启动横线、Java 命令行、NC 普通 stdout 也进入异常栈样式；CSS 再加 216px 左边距与空的时间 / 线程 / 级别列，造成截图中的大段空白。
3. **日志入口有歧义。** 跟随最新用了 download 图标，容易理解成下载；换行、复制、清空均为无文字图标。复制提示写「当前显示」，实际复制已加载的全部匹配行，范围不一致。
4. **查找和过滤混在一起。** Ctrl+F 现在聚焦关键字过滤，匹配之外的上下文会被隐藏。缺少高亮、匹配位置、前后跳转与「查看上下文」的直接入口。
5. **历史阅读受限。** 内存保留 4000 行，但 DOM 固定只挂最后 500 个匹配行；更早的已加载匹配行无法正常向上滚动到达。切换日志来源通过 key 重建组件，日志偏移与位置重置；日志表单又是两来源共用一份。
6. **健康状态表达超过证据。** ServiceChain 中 DB 灯来自工作台数据库连接，与 NC 服务自身的数据库健康无关；「NC 应用就绪」主要依据端口状态，尚不能证明业务模块或登录链路完全可用。
7. **运行细节抢占主操作。** PID、JDWP、classpath 计数长期展开，主类与路径却截断；启动的具体等待原因和最近输出时间不够突出。

已存在的能力应复用：防重复启停锁、独立进程控制、增量日志读取、500ms 轮询、4000 行内存上限、软换行、级别过滤、停止后的日志尾部补读、运行中清屏保留磁盘文件，以及 NC 编译 / 投送 / 重启任务链。

## 3. 两种方向

| 方向 | 收益 | 代价 |
| --- | --- | --- |
| A：保留横条，折叠指标并重排工具栏 | 改动较少，可快速恢复日志高度 | 两个服务与多个操作仍分散在横条中，后续运行会话与诊断更难扩展 |
| B：左侧服务列表 + 右侧控制台，支持紧凑 / 展开模式（推荐） | 选中对象与操作、状态、日志一致，横向空间得到利用；能覆盖独立启停和组合启动 | 需要调整布局与来源 / 会话状态管理，但可复用现有启停和读日志接口 |

采用 B。底部仍是日常入口；一键展开时临时扩大阅读区，恢复后回到原编辑器和面板尺寸，不新增常驻主导航页。

## 4. 推荐布局与视觉

正常底部模式：

```text
NC 服务                                            展开阅读  关闭
┌ 服务列表 ────────────┬ 控制台 ──────────────────────────────┐
│ 中间件  启动中       │ 中间件 · 等待监听      停止  调试  更多│
│ PID 82064 · :80      │ 全部 / 警告 / 错误    查找…   跟随   │
│                      ├──────────────────────────────────────┤
│ 客户端  已停止       │ 12:04:01  正在准备 classpath           │
│ 连接目标未就绪       │ 12:04:03  正在投送元数据               │
│                      │ 12:04:05  JVM 已启动，等待端口监听      │
│ 运行详情 / 启动配置  │ ...                                  │
│ 元数据投送           ├──────────────────────────────────────┤
│                      │ 已加载 420 行 · 最新输出 2 秒前        │
└──────────────────────┴──────────────────────────────────────┘
```

这是结构示意，时间与文本为设计样例，不代表当前后端已经提供这些阶段事件。

- 左侧约 180–220px，只显示两个服务的名称、状态和重要端点；右侧承担运行操作与日志阅读。
- PID、Java 路径、NC home、classpath、JDWP 详情放在按需面板；保持可复制、可查看完整值。
- 元数据投送保留状态摘要及入口，展开后再显示自动投送设置、预览、执行和结果，不长期占据日志上方。
- 正常 360px 高面板以日志正文至少 220px 为目标。更矮或更窄时收起服务详情，用紧凑来源选择，优先保留正文、搜索和主操作。
- 浅色用稳定实底和细分隔线，深色用清晰分层的深灰实底；玻璃效果保留在外壳。状态仅用小徽标和必要的语义色，避免大面积绿色或告警底色。
- 正文等宽字体建议默认 13px，提供字号调节；统一按钮高度和文字对比，数字使用等宽数字。

## 5. 启动与服务控制一起升级

### 操作对象与按钮

选中中间件，工具栏就只控制中间件；选中客户端，同位置控制客户端。两者仍可独立启停，不因其中一个启动就锁死另一个的全部操作。

| 状态 | 主操作与反馈 |
| --- | --- |
| 状态读取中 / 读取失败 | 明确「读取中 / 状态未知」，提供重试，不伪装成已停止 |
| 已停止 | 「启动」分体按钮：普通启动 / 调试启动，显示当前配置摘要 |
| 正在准备 | 原位置显示等待与当前阶段，可取消准备；不能提前说进程已停止或已运行 |
| JVM 已创建、端口未就绪 | 显示 PID、实际监听目标、等待用时、最近输出时间；提供停止与启动日志 |
| 端口由本进程监听 | 表述「端口监听中」或「可尝试连接」，提供重启 / 停止 / 可用的调试附加 |
| 启动失败 / 异常退出 | 显示失败原因与退出码，定位本次错误上下文；配置保持，可重试 |
| 停止中 / 重启中 | 明确当前动作，限制冲突操作，原位置完成状态变化，避免按钮跳动 |

调试开关描述为「下次启动带调试」，当前运行是否可附加以实际 JDWP 端口为准。重启后自动附加可做成显式可选项，不把开启配置当成当前已经附加。

### 真实启动阶段

建议为已有启动流程补阶段事件：检查环境 → 准备 classpath → 按配置投送元数据 → 创建 JVM → 等待监听。仅有开始 / 完成事件时显示等待动画和已用时间，不虚构百分比。

启动耗时较长时显示「仍在等待端口，最后输出距今 N 秒」与查看日志、检查端口、停止入口。无新日志不直接判定卡死；超出提示阈值也不自动宣称失败。

删除工作台数据库连接作为服务健康链路节点的表达；单独标为「工作台数据库」。只有补齐真实、适用于该 NC 版本的只读探测后，才增加「NC 应用可用 / NC 数据库正常」。没有探针时明确未验证。

### 可选组合启动

提供「开始开发」配置，复用已有 NC 任务执行与操作反馈：可选编译 → 元数据投送 → 启动中间件 → 等待客户端实际连接目标可达 → 启动客户端。

中间件 HTTP 监听和客户端的实际连接目标不能混为同一个端口。前一步失败或取消，后续不启动；中间件已运行时按配置复用。直接启动客户端仍保留，未就绪时给清楚提示。组合失败说明已经运行了哪些对象，不擅自关闭原本就在运行的服务。

## 6. 控制台阅读与排查

1. **原文与结构化区分。** 普通 stdout 左对齐，不预留空字段；只有明确的 `at ...`、`Caused by`、`Suppressed` 等堆栈特征及上下文才归属异常。日志保留原文，结构化字段用于阅读和过滤，不改写复制 / 导出的原文。
2. **查找不等于过滤。** Ctrl+F 打开高亮查找，Enter / Shift+Enter 或 F3 / Shift+F3 前后跳转，显示匹配数；过滤是另一个明确入口。筛选后无匹配时可一键清除，错误记录可查看前后上下文。
3. **跟随是显式操作。** 用「跟随最新 / 已暂停」文字和箭头表达；向上滚动自动暂停，新日志不拉走阅读位置。暂停时显示「新增 N 行，回到最新」。固定来源避免另一服务启动抢走当前控制台。
4. **长行和长栈可读。** 保留软换行按钮并显示状态；过长启动命令行默认摘要，可展开、复制完整命令。异常按一组折叠 / 展开，优先突出错误标题与根因，提供完整原文及源码定位；不自动折叠所有业务信息。
5. **复制范围清楚。** 区分复制选区、复制当前异常、复制已加载匹配日志；导出窗口说明范围。读取完整文件是单独动作，有等待与取消，不把 4000 行缓存标成全部文件。
6. **清屏和文件操作区分。** 常用按钮为「清屏」，提示磁盘日志保留；停机后的归档清空放在更多菜单并说明对象。动作失败保留原日志与筛选，不出现虚假的已完成反馈。
7. **可回看。** 用虚拟列表让全部已加载行都能到达，替代只展示最后 500 行；保留 4000 行有界缓存。更早日志通过有界的文件分段读取或现有排查入口按需访问，明确范围。
8. **按来源 / 本次运行记忆。** 中间件和客户端分别保存过滤、位置、跟随和换行状态；重启生成新运行身份，旧数据不串入新日志。本次 / 上次运行可按需选择，历史文件不全部预加载。
9. **诊断与源码联动。** 点击 Java 堆栈中的文件 / 行号跳源码；不确定映射时先让用户选择，不打开错误的同名类。应用级日志排查复用现有 LogTab，并明确 stdout 文件与 `nclogs` 是不同来源。

## 7. 分批实施与验收

| 批次 | 内容 | 验收 |
| --- | --- | --- |
| P0：恢复可读与清晰操作 | 推荐布局、紧凑 / 展开模式、详情与投送按需显示、普通输出误分类修复、实证状态表达、显式跟随 / 换行 / 清屏、查找定位、范围正确的复制、来源状态保持 | 360px 面板正文目标至少 220px；普通输出无大空白缩进；长命令和异常可完整阅读；用户向上滚动不被新日志抢走；按钮与选中服务一致；两来源切换不丢设置 |
| P1：启动与排查闭环 | 启动阶段事件、失败定位、可选组合启动与调试附加、异常分组 / 源码跳转、全部已加载行的虚拟滚动、按需历史读取和导出 | 启动取消后不误起客户端；端口冲突 / 创建进程失败 / 异常退出有对应提示与日志；4000 行可回看且 DOM 有界；轮转 / 切工程 / 晚到响应不串来源；完整文件读取可取消 |

双主题验收覆盖浅深 × 玻璃 / 实色；尺寸覆盖正常工作台、1024×540 低窗口、683×512 等效 150% 缩放视口、窄面板和展开阅读。日志样本包含原始启动行、超长命令、中文、普通结构化日志、嵌套异常、无匹配、读失败和连续新增日志。

性能重点是读取与渲染范围：增量读取、防重复请求、有界缓存、仅可见窗口渲染、非活动面板停止轮询；不因为「暂停跟随」而停止必要的数据接收，也不在后台反复全量解析文件。长文件按需操作有最大范围、取消和资源清理。尽量复用现有组件和日志排查能力，不为只读 stdout 引入完整终端或新的大型图表依赖。
