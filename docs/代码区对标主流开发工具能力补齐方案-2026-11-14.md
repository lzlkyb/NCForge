# 代码区对标主流开发工具能力补齐方案

日期：2026-11-14。范围：IntelliJ IDEA、Eclipse 中与 Java / NC 日常开发相关的代码区能力，并纳入调试、测试、工程依赖及高级工具的后续路线。本轮交付方案，未修改功能代码。

## 1. 目标与状态口径

用户截图的核心需求是：在接口、类或方法处，通过鼠标操作直接打开声明和实现，不必复制名称再搜索。扩展目标是让代码区达到“读得懂、跳得准、写得快、改得安全、能验证”的日常 IDE 体验，同时继续收敛工具栏。

本轮按当前源码核对，旧能力台账仅作线索。状态分为：

- **已有基础**：实现与调用入口可指认，本轮未逐项真机验收；安排复用、完善及验收。
- **部分支持**：已有实现，但明确存在范围或体验限制。
- **待新增**：本轮核对未找到对应可用入口或完整实现，先进入开发路线。
- **需能力验证**：依赖语言服务、调试适配器、JDK 或工程配置，先验证再确定实现方式。

不把菜单、Provider 或测试桩当成完整功能；也不重新开发已经存在的能力。此前台账中暂不做的便利功能、测试和高级工具，依据本次用户诉求重新纳入路线。

## 3. 第一批：把截图里的代码导航做完整

### 3.1 用户交互

鼠标停在类、接口、方法、字段、变量上时，保留现有签名和说明，并按目标性质出现精简动作区：

| 光标目标 | 首要动作 | 其他动作 |
| --- | --- | --- |
| 类名 / 接口名 | 打开声明、打开实现 | 查看继承关系、找引用、复制完整类名 |
| 方法名 | 打开声明、打开实现 | 打开父方法、找引用、查看调用关系 |
| 变量 / 字段 | 打开声明、打开声明类型 | 找引用、查看读写位置 |
| NC 服务接口 / `lookup(接口.class)` | 打开声明、打开实现 | 查看 NC 服务装配、打开 UPM 注册文件 |

动作出现后可把鼠标移入并点击，不因离开文字就立即消失。按 Ctrl 时强调可导航目标，Ctrl+单击打开声明；右键提供同一组动作。快捷键跟随用户选择的 IDEA/Eclipse 方案，菜单同步显示键位；跳实现优先提供 IDEA 的 Ctrl+Alt+B，Eclipse 映射在确认当前冲突与惯例后确定，允许自定义。

仅当前符号适用的动作显示为主要项；其他导航动作放进右键的“导航”分组。保留普通编辑右键功能，避免中英文重复条目。先验证 Monaco 中文化和扩展方式，再选择最小改动的方案。

### 3.2 跳转规则

1. **单个准确目标**：直接打开并定位。
2. **多个准确目标**：显示轻量选择浮层，支持输入过滤；每项展示完整类名、方法签名、模块、源文件或 JAR 路径。
3. **就地预览**：允许先看目标代码，再决定打开标签；可在右侧编辑器打开。
4. **没有结果**：区分没有实现、索引未完成、依赖不在类路径、服务未就绪和目标加载失败，并提供对应恢复入口。
5. **返回**：后退到原文件、选区和滚动位置；分屏时归属活动编辑器组。
6. **准确性**：以解析出的符号与来源定位，不按简单类名任意选一个；同名 JAR、内部类、泛型与重载方法必须区分。

### 3.3 源码、JAR 与 hyext 的边界

- 当前工程及依赖工程源码：打开可编辑文件，定位真实声明。
- JAR 有匹配源码附件：优先源码；否则显示反编译代码，并明确来源及只读状态。
- hyext 中的 JAR 与散放 class：复用本会话建立的准确来源索引，能从搜索进入，也能作为导航目标打开。
- **搜索范围不等于 Java 类路径**：目录中能搜索的类可能未进入编译与语言服务类路径。语义导航先按有效类路径解析，额外候选单独注明；不能把目录中所有 JAR 无条件塞进工程。
- 从反编译文档继续跳方法、引用等，需要单独验证文档身份与语言服务支持；不把显示成功等同于完整可编辑源码能力。
- 有源码附件才能保证源码行号语义；反编译行号不能直接当作原始源码行号用于断点或异常堆栈。

### 3.4 第一批验收

用截图中的 `IEyepriceguideMaintain` 和 `NCLocator.lookup(...)` 场景验证；实际工程中若类名不同，则选同结构的真实服务接口：

- 接口打开声明，打开实现列出正确实现；有多个实现时不会任意跳一个。
- 在实现方法上打开父方法，能进入对应接口方法或父类方法；变量的声明类型不会误跳成父类。
- 当前工程、依赖工程、JAR、hyext JAR、散 class、内部类及重载各有案例。
- 未保存编辑后仍以当前内容查询；切换工程或文件后旧请求不会导航到错误位置。
- 鼠标、右键、命令、键位四种入口行为一致；后退、分屏及只读目标正常。
- 索引中、缺依赖和无结果有明确说明；不新增常驻工具栏按钮。

## 6. 架构与性能安排

1. **第一批先复用现有底座**：Monaco 编辑器、JDT 查询、文件会话、导航记录、库来源索引及 UPM 查询；不整体重写编辑器。
2. **统一目标解析与打开**：保留文件 URI、JDT URI 和库 URI 的真实来源，区分源码、源码附件、反编译与配置目标；各入口使用同一套位置及来源转换规则。
3. **统一上下文快照**：查询绑定工程代次、活动编辑器组、文档版本和光标位置；请求支持取消和过期丢弃，响应不能跨工程误用。
4. **统一改动预览与保护**：复用现有重命名、替换及历史保护；复杂重构需先形成跨文件改动计划，保护未保存内容与外部修改，保留编码/换行。服务端只返回编辑计划，由应用管理应用和保存。
5. **按需查询与后台索引**：悬停不在每次鼠标移动时扫描整个工程/JAR；共享符号与依赖缓存，明确结果上限及截断信息；大量结果用筛选和分批展示。
6. **语言服务能力先验证**：当前使用 jdt.ls 0.57、Java 8 配置。高级重构、内联提示及测试接入要逐项探测，不以透传接口作为支持证明。需要升级时先隔离验证 Java 8/NC 类路径兼容、内存和包体增量，不能阻塞第一批导航完善。
7. **模块保持小而清楚**：公共逻辑归现有 `lib/` 分层，组件/Hook 遵守仓库体量门禁；不把所有导航、重构、测试状态堆回一个编辑器组件。

## 7. 交付与验收方式

每批形成能力台账：当前状态、入口、覆盖范围、限制、代码落点与真实验收证据。已有能力也要通过相同验收后才称完成。

涉及界面变更的批次，先出基于现有代码区的一比一 HTML 稿：第一批覆盖悬停、右键、多实现选择、JAR 只读目标及失败状态。随后实施，补有价值的单元与交互回归，并在真实 NC 工程验证整条链路。

公共回归覆盖当前工程/依赖工程/JAR/hyext、未保存内容、外部修改、索引中/失败、中文/GBK/CRLF、分屏、键位方案、主题与缩放。索引热/冷耗时、重复触发、内存增长及旧请求取消分别记录，不凭感觉宣称性能达标。

建议执行顺序：第一批导航 → 第二批代码关系与 NC 联动 → 第三批编辑生成 → 第四批重构检查 → 第五批调试测试 → 第六批工程工具。每批先完成可独立使用的一条真实工作流程，再进入下一批；尚未验证的服务器能力先做小范围验证，不并行启动多个重构底座。
