# 元数据编辑工作台升级方案

日期：2026-11-05。实施更新：2026-11-06。状态：三阶段实施与自动验收已完成。

第 2 节保留方案制定时的源码检查，作为设计依据。累计实施结果与测量边界见 [三阶段实施验收](元数据后续实施验收-2026-11-06/实施验收记录-2026-11-06.md)。

用户已选择“图形与属性表联动”。推荐在 NCForge 现有深青工作台内，把元数据页升级成一个连续的编辑工作区：左侧找组件，中间看模型与字段，右侧改当前对象。图、表、检查器共享选中状态，避免每次编辑都重新找位置。

交互原型：[元数据编辑工作台](../design/元数据编辑工作台-交互原型-2026-11-05.html)。原型中的收费项目、组织参照、接口映射与校验提示均为示例数据；编辑和保存仅在网页内演示。

## 1. 从 UAP 原型中保留什么

参考图展示的是 UAP MDP 建模工作台，不只是数据库 ER 图。应保留它的业务表达能力，重新组织界面与操作。

| 原型中的能力 | NCForge 的设计方向 |
| --- | --- |
| 模块、BMF 资源树 | 保留“来源 → 模块 → 组件”，区分工作区与依赖工程；支持检索、折叠、最近打开 |
| 多个模型文档 | BMF 文档标签保存选中对象、滚动位置、画布位置和待处理修改 |
| 实体与主子关系 | 显示中文名、技术名、主实体、主键与关键字段；关系落在字段端点上 |
| 接口、枚举与参照 | 使用明确的对象类别，不把业务接口当作普通实体；接口映射与枚举项分别编辑 |
| 底部属性表 | 作为高频操作区，与画布同时可见；兼顾键盘、筛选和大字段量 |
| 右侧属性面板 | 按“基本 / 类型与约束 / 数据库映射 / 参照 / 高级”分组，随选中对象变化 |
| 大纲与缩略图 | 大纲用于直接定位实体、字段、接口；缩略图用于导航，低高度时按需展开 |
| 依赖、继承、组合、关联、实现 | 先明确各类 BMF 标签和写入语义，再开放对应编辑；不能只换连线样式 |

不照搬旧式黄色节点、密集图标和长属性清单。沿用现有工作台颜色、系统字体、公共按钮、菜单、弹窗和主题。

## 2. 当前实现与真实缺口

已阅读 `MetaTab`、`MetaViewPanel`、`MetaTree`、`MetaDetails`、`MetaCanvas`、节点与布局代码，以及 BMF 类型和统一编辑弹窗。以下基于当前源码，不沿用旧调研中“没有 BMF 解析”的结论。

| 当前已经具备 | 本次需要改善 |
| --- | --- |
| BMF 索引、来源分组、检索、解析失败提示与缓存统计 | 树分组目前展开平铺；增加折叠、大纲和大量条目的可见区渲染 |
| 实体、字段、枚举、关系的查看与编辑 | 字段检查器位于长表下方；选中字段后滚动到检查器，操作位置易跳动 |
| 实体画布、字段端点、拖节点、拖把手建关系、重排 | “结构”和“画布”是互斥视图，选中状态分别持有；缺少图表联动、缩放导航与键盘移动替代 |
| 对比、历史、引用、校验、生成、导入导出、发布 POC | 9 个平铺标签分散编辑注意力；保留能力，按主编辑与上下文工具组织 |
| 编辑操作先预览 diff；保存时核对 SHA-256 并备份 | 新布局继续调用这条链路；草稿和批量修改需要明确的事务边界 |
| `AggregationRelation`、`Reference`、`busiitfconnection` 关系类型 | 现有新增关系的两端限定为组件内实体；完整业务接口对象、属性映射与多重性尚无独立前端契约 |
| 未识别标签在解析/写回体系中保留 | 未建模语义不能通过 UI 猜测修改；高级区明确只读并显示未识别项 |

现有画布有 50 个实体可拖动的行为测试，但这不是帧率或性能基准。新界面的速度验收需另外测量。

## 3. 三种布局及选择

| 方向 | 优势 | 取舍 |
| --- | --- | --- |
| 图形与属性表联动，已选择 | 保持关系上下文，字段编辑不离开模型，最贴合现有实现 | 需要共享选中状态与面板尺寸管理 |
| 大画布为主、属性按需打开 | 拖拽建模空间大 | 连续修改字段要反复展开面板 |
| 字段表为主、图形辅助 | 批量录入最快，小窗口友好 | 复杂主子、接口与参照关系不够直观 |

采用第一种，并提供“联动 / 模型 / 字段”三个工作模式。同一份模型、同一选中对象在三种模式间连续保留。

### 宽屏布局

```text
现有标题栏与全局导航
┌────────────┬──────────────────────────────────────┬──────────────┐
│ 来源 / 模块 │ BMF 文档标签 · 中文名称 · 上下文工具    │ 属性检查器     │
│ 组件资源树  ├──────────────────────────────────────┤ 当前对象       │
│            │ 模型图：实体、字段端点、接口与主子关系  │ 分组编辑       │
│            │ 选择 / 新建 / 关系 · 缩放 / 重排       │ 基本、映射等   │
│            ├──────────────────────────────────────┤ 校验提示       │
│ 模型大纲    │ 实体切换 · 字段 / 接口映射 / 参照 / 问题│ 应用与撤销     │
│            │ 字段表，内部滚动、表头固定             │               │
└────────────┴──────────────────────────────────────┴──────────────┘
来源、编码、待保存状态与当前对象
```

- 资源栏约 224px，检查器约 280px；生产实现允许拖动调整并保存宽度。
- 模型与字段区域的分隔可拖动；双击分隔条恢复默认比例。
- 文档标题突出中文名，技术名和路径作为次级信息；保存、校验始终容易找到。
- 不增加顶部宣传区或统计卡片。停靠区连续排列，靠表面和细边界分组。

### 窗口适配

| 可用视口 | 默认安排 |
| --- | --- |
| ≥1480px，且高度充足 | 资源树、模型+字段、检查器同时显示 |
| 1101–1479px | 保留资源树和中间工作区，检查器按需抽屉打开 |
| ≤1100px | 资源树也改为按需抽屉，优先留给模型和字段 |
| 高度 ≤660px，或宽度 ≤720px | 默认字段优先；一键切到模型，保留选中与位置 |

这些断点是原型起点，正式实施以工作区真实可用尺寸判断，不能只看整个窗口宽度。字段表内部横向滚动，禁止把整个窗口撑宽。辅助抽屉应可关闭、返回原焦点，不覆盖无法找回的主操作。

## 4. 关键交互

### 图、表、检查器同步

1. 点实体：切到该实体的字段，检查器显示实体与表/类/访问器信息。
2. 点字段：图上高亮对应字段，表里保留选中行，检查器显示该字段。选中字段若超出节点摘要上限，优先将它放入摘要或给出定位入口。
3. 点关系：突出两端与具体端点，检查器显示关系类型及源/目标属性；不让字段表和检查器各指向不同对象。
4. 点业务接口：显示接口属性 → 实体字段映射，未绑定、重复或类型不匹配用文字说明；映射行可反向定位字段。
5. 点校验问题：直接定位对象与属性，保留问题列表的返回入口。

筛选不能把检查器悄悄指向另一行。原选中字段被筛掉时，显示“当前字段不在筛选结果中”，提供清除筛选/定位。切实体、切标签、刷新详情时按稳定 ID 恢复；对象已删除才清理选中。

### 高频编辑

- 第一阶段：检查器内编辑常用字段，应用到当前操作草稿；不再反复滚到表格下方。
- 实体基本信息、枚举项、关系保持明确的编辑入口；删除仍要展示影响范围。
- 第二阶段之后：支持表格 F2 编辑、多选、批量设置与带列映射的粘贴。主键、引用、类型变化等操作须校验兼容性，不能按字符串随意批改。
- 新建字段从当前实体上下文进入；中文名、技术名、类型、列名和约束在一处完成。
- 模型节点移动只改变视图位置，不写 BMF、不制造文件脏状态。视图位置以规范化路径+对象 ID 保存。

### 保存与外部冲突

保留现有“预览后保存”的保护，同时把操作呈现得更清楚：

```text
编辑 → 输入校验 → 操作草稿 → 校验/影响检查 → 新鲜 diff 预览
     → 用户确认保存 → SHA-256 核对 → 备份并写回 → 刷新并恢复选中
```

- 第一阶段优先复用单次操作的 `MetaOpDialog` 和 `bmfEditPreview` / `bmfEditSave`；检查器只是更好的入口。
- 原型演示了跨字段汇总草稿的目标体验。正式开放多操作草稿前，须验证当前 writer 是否支持同一批操作中引用新对象、操作排序、删除依赖与失败原子性；通过后再接入，不能只把弹窗 ops 拼起来。
- 改表单后旧 diff 立即失效。提交错误时保留输入和草稿，避免重新填写。
- 外部修改出现冲突时展示重新加载/对比入口；不能静默覆盖。未保存文档关闭时保留继续编辑、放弃、先预览保存的选择。
- 文件编码、BOM、换行、未知节点和不相关字节保持现有写回契约。

### 键盘与边界状态

- 保留全局“元数据”快捷键 Ctrl+6；不抢占现有应用快捷键。
- 字段表方向键移动、Enter 打开检查器、F2 编辑；Ctrl+S 进入预览保存，Escape 退出临时编辑/抽屉。
- 拖节点和创建关系都提供按钮/表单替代；拖把手不是唯一途径。
- 空组件、纯枚举/纯接口、索引中、解析失败、保存失败、只读来源、大文件加载分别有可恢复提示。
- 支持减少动态效果。选中立即反馈，面板过渡沿用 100/170/180ms，不用连续动画装饰数据区。

## 5. 实施分期

| 阶段 | 累计交付 | 源码状态 |
| --- | --- | --- |
| 第一阶段 | 图表检查器联动、多文档、停靠与抽屉、窗口适配 | 已实现 |
| 第二阶段 | 业务接口、属性映射、参照、访问器参数、多重性与继承校验；四份原始 NC 1909 BMF 夹具 | 已实现 |
| 第三阶段 | 文档事务草稿、撤销重做、批改与粘贴预检、字段模板、长表与大树虚拟化、500 节点视区裁剪、源码按需读取 | 已实现 |

### 第一阶段：把现有能力变好用

交付联动布局、停靠检查器、来源树折叠、文档状态、模型/字段模式、字段定位、问题跳转、上下文工具分组与窄/低窗口适配。

复用现有字段、实体、关系与枚举编辑路径，不扩大写入语义。原有 9 个视图全部保留入口：主编辑整合结构和画布，校验/引用在字段区，比较/历史/生成/导入导出/发布 POC 放上下文工具。

验收：切换实体或字段后图表检查器一致；刷新/切文档恢复对象；长表不跳到页面底部；原编辑和保存保护不回归。

### 第二阶段：补齐 UAP 模型语义

增加业务接口、接口属性、映射、访问器参数、关系多重性等明确类型。依赖、继承、组合、关联、实现按真实 BMF 样本逐类补齐解析、校验与写入。

先读取与定位，验证无损 round-trip 后开放编辑。此阶段需要实际 UAP 导出的代表性 BMF 夹具；截图只能证明 UI 与概念，不能证明 XML 格式和写入规则。

验收：带接口/枚举/参照/主子聚合的样本可完整显示；映射可双向定位；未支持的语义明确只读；编码与未知节点不损失。

### 第三阶段：批量效率与大模型

开放经过事务验证的多操作草稿、批量修改、粘贴预检与字段模板。根据采样补大树/长表虚拟化、画布视区裁剪和增量布局。

验收：错误粘贴不产生部分写入；失败可修正并重试；大模型切换、筛选、拖动达到性能目标。

## 6. 前后端接线建议

以 `MetaTab` 作为文档协调入口，保留现有 `pickSeq` / `scanSeq`、规范化路径与迟到响应过滤。每个文档保存对象 ID、搜索、滚动、视图位置和操作状态；不要复制多份完整 BMF 详情到三个面板。

建议按责任拆分，遵守新组件/Hook ≤300 行、`useState`+`useEffect` ≤8 的门禁：

| 位置 | 责任 |
| --- | --- |
| `MetaTab` / 文档状态 Hook | 索引、活动文档、稳定对象选中、刷新恢复、异步竞态 |
| 联动编辑工作区 | 面板布局和模型/字段模式；不包含写入逻辑 |
| `MetaCanvas`、节点/边、`canvasLayout` | 复用 SVG/节点结构，增加外部选中、缩放导航、键盘操作 |
| 字段表与检查器 | 拆开目前 `MetaDetails` 中的表与下方检查器，复用编辑表单 |
| 现有编辑弹窗与 `MetaOpDialog` | 输入约束、差异新鲜度、保存冲突与备份 |
| `lib/bmf.ts` / Rust 模型与 writer | 第二阶段新增 UAP 契约；第三阶段验证批量事务 |

大图编辑器库暂不引入。先利用既有画布、公共控件和 Tauri 命令；只有实测证明现有路线不足，才比较依赖体积、渲染成本与无损模型接入。

## 7. 轻量化与速度验收目标

以下保留方案设定的验收目标。三阶段生产组件的浏览器采样结果见累计验收记录，原生 WebView 帧耗时和内存目标仍需实机验证。使用相同机器、构建、夹具、主题和缓存状态记录中位数/P95，区分冷打开与热切换。

| 场景 | 目标与策略 |
| --- | --- |
| 选中字段/实体 | P95 反馈 ≤100ms；共享 ID 状态，只更新相关节点、行和检查器 |
| 热切文档 | 常规夹具 P95 ≤200ms；详情有界缓存，校验结果按 SHA 缓存，禁止重复全量解析 |
| 50 实体、100 关系拖动 | P95 帧耗时 ≤16.7ms；每帧只改移动节点及相连路径，不扫描所有字段/重算整个布局 |
| 1000 字段表、1500 组件树 | 仅挂载可见区和缓冲行；检索不阻塞输入，折叠节点不渲染子项 |
| 500 实体的大模型 | 默认摘要、视区裁剪、分组展开；布局任务可取消，详情按需展开 |
| 内存 | 常规夹具新增工作区功能的常驻增量目标 ≤40MB；反复打开关闭后没有持续增长 |
| 包与启动 | 不新增大型画布依赖；低频工具按需加载，记录元数据入口及懒加载块 gzip 差异 |
| 后台 | 没有新增常驻轮询；隐藏/关闭页面取消不必要工作，详情缓存有淘汰上限 |

启动、最低、结束可用内存都要记录。按仓库资源规则串行执行重测试，Rust 使用 `desktop/scripts/rust-gate.mjs`，浏览器保持 headless。

## 8. 验收清单

- 同时检查宽屏、1280×900、1024×768、1024×540、819×614、683×512、560×900 的明暗主题；后两种缩小视口只是可用空间等效，不代表真实 Windows DPI 已验收。
- 图点字段、表点字段、关系定位、接口映射定位、问题定位，都能到达同一对象。
- 表格与面板各自滚动，窗口无外部横向溢出；低高度字段区仍可操作。
- 切文档、刷新、字段过滤、对象删除、外部修改、保存失败后的状态符合上述规则。
- 差异预览失效、SHA 冲突、备份、编码/未知标签无损、只读来源与删除依赖有回归测试。
- 拖动与关系创建有键盘/按钮替代；弹窗焦点可恢复，减少动态效果有效。
- 通过相应前端门禁、语义夹具与性能采样后，才视为实现完成。

## 9. 本轮原型交付边界

HTML 可体验文档/实体/字段联动、字段筛选、模型与字段模式、检查器编辑、新建字段、草稿撤销、差异预览与模拟保存；接口映射、校验定位和上下文工具提供示例流程。

布局分隔拖动、真实 BMF 解析写回、正式批量事务、真实接口契约、生成/发布执行和大数据性能均不由该 HTML 验证。它用于确认界面与流程；三阶段生产实现及验收结果以累计记录为准。

原型界面与示例流程已完成检查，见 [原型验收记录](元数据原型验收-2026-11-06/验收记录-2026-11-06.md)。

第一阶段生产 UI 的历史检查见 [第一阶段实施验收记录](元数据UI实施验收-2026-11-06/实施验收记录-2026-11-06.md)。第二、三阶段的前后端实现和四份真实 BMF 样本已加入累计验收；原生 WebView 性能、Windows DPI、UAP Studio 发布及 NC65 运行的实机边界见三阶段记录。
