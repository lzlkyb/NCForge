# SQL 语法高亮升级实施与验收

本次已把查询编辑器、只读 SQL 查看器、设置中的格式化预览接到同一套词法与查询作用域识别。重点是 Oracle / NC 阅读体验和可靠补全，不宣称已经达到完整数据库 IDE 的语义分析能力。

## 已实现的行为

| 场景 | 结果 |
| --- | --- |
| Oracle `q` / `nq` 字符串 | 支持配对及自定义分隔符、内部单引号、跨行及未完成输入；内容中的 SQL 词不会误高亮或触发字段查询 |
| 绑定变量与提示 | `:name`、`:1`、`/*+ ... */` 单独显示；PostgreSQL `::` 不被当成绑定变量 |
| 其它应用方言 | 共用识别器，按方言处理 PostgreSQL dollar 字符串、SQL Server 变量与引用名字、MySQL 引用与转义 |
| 分页和层次查询 | Oracle `rownum`、`level`、`connect by`、`prior` 等可识别 |
| 同名表别名 | 内层别名遮蔽外层；相关子查询可查找外层；同一层重复别名不给错误字段或别名链接 |
| CTE 和派生表 | 补全明确的输出列；显式 CTE 列列表优先；不会把内层物理表所有字段带到外层 |
| 不确定的输出 | `*`、未命名复杂表达式、表函数的未知结果不猜测列名 |
| 脚本边界 | 查询分支与分号之间的别名、CTE 隔离；后声明的普通 CTE 不提前可见 |
| 表名跳转 | 复用查询作用域；保留物理表 DDL 跳转，CTE 与字符串内伪表名不误打开物理表 |
| 方言切换 | 跟随连接或现有手动方言偏好，更新当前 model 的语言；保持编辑器实例与撤销记录 |
| 大脚本 | 20 万字符以上跳过全文补全/链接/语义分析，Monaco 保留逐行词法高亮；React 预览退为完整普通文本，避免生成大量节点 |

默认配色用关键字、表名、函数、字符串、参数建立层次，字段保持正文色，减少颜色干扰。浅深色共用 CSS 颜色 token，Java 的规则使用独立命名，不受 SQL 高亮规则影响。

## 主要接线

- `desktop/src/lib/sqlLex.ts`：容忍未完成输入的词法识别，纯函数，逐行状态可复制。
- `desktop/src/lib/sqlScope.ts`：查询层级、CTE、输出列、别名可见性及语义角色。
- `desktop/src/lib/sqlScopeLinks.ts`：查询层级内的物理表链接。
- `desktop/src/lib/sqlHighlight.ts`、`sql-highlight.css`：共用分类与浅深色 token。
- `desktop/src/lib/monacoSql.ts`：各方言的词法/语义 provider、版本与方言缓存。超过 512 个查询 scope 时保留词法分类、跳过语义推断。
- `desktop/src/lib/sqlProviders.ts`：补全、签名和链接注册到全部 8 个应用语言 ID。
- `desktop/src/hooks/useSqlDialect.ts`、`useSqlEditorDialect.ts`：连接/偏好到当前 model 的语言更新。
- `SqlEditor`、`SqlCodeViewerEditor`、`SqlHighlightedText`、`SqlFormatPreview`：三个生产入口。

没有引入新运行时依赖，设置预览不会导入 Monaco 编辑器。SQL 使用文本节点渲染，不使用 `dangerouslySetInnerHTML`，不修改 SQL 原文或自动执行。

## 验证证据

相关 14 个测试文件、102 项测试通过，覆盖词法状态、查询作用域、表名链接、Monaco 接线、真实字段补全、方言更新、文本安全以及原有编辑器/查看器/排版功能。

类型检查、ESLint、组件体量和设计 token 门禁通过；前端 Vite 生产构建通过。最终 JS 产物为 1,696 KB gzip / 5,800 KB raw，最大 chunk 3,139 KB raw，均在现有预算内。

真实浏览器验收：

- CTE `x(id, title)` 在 `x.` 后正确显示 `id`、`title`，不依赖数据库连接。
- 浅深色下，查询编辑器、只读查看器、React 预览的 `bd_project`、`nvl`、`:dr` 实际计算颜色逐一相同。
- 760px 窄窗口中两个编辑器上下排列，页面无横向溢出；编辑器保留独立水平滚动。
- 浏览器未出现错误或警告。

性能采样是本机单次结果，不作为跨机器保证：
