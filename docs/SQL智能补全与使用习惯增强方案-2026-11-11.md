# SQL 智能补全与使用习惯增强方案

日期：2026-11-11。状态：三期能力已接入正式源码，实施与验收见《SQL智能补全实施与验收-2026-11-11》。

## 目标与建议

让 SQL 输入区逐步熟悉用户常用的表、字段和查询方式，同时根据当前语句给出准确建议。用户感受到的变化应该是“刚用过的表下次就在前面”“输入中文也能找到表”“写到这里，正好提示我接下来需要的内容”。

建议以本地元数据、SQL 上下文和使用记录实现首版。默认假设：以现有 NC 数据库工作流为主，沿用 Monaco 提示框和现有界面；优先提升输入效率，首版不依赖大模型服务。未来自然语言写 SQL 可以作为单独能力评估。

## 当前实现依据

- `desktop/src/lib/sqlProviders.ts` 已提供表名、NC 中文名、字段类型和主键提示，表名使用 `5${lower}` 排序，尚未结合个人使用记录。
- `desktop/src/lib/sqlScope.ts` 已识别别名、可见 CTE、派生查询输出及作用域；字符串、注释等位置会抑制普通补全，可以继续复用。
- 通用位置补全通过 `sqlSourcesAt(...).slice(0, 3)` 读取字段，第四张及后续来源表的字段不会进入这一分支；指定别名的字段补全走独立分支。
- `desktop/src/lib/sqlComplete.ts` 的关键词列表是固定集合，包含 Oracle 常见函数。后续应随实际 SQL 方言选择候选。
- `desktop/src/lib/dbHistory.ts` 按连接保存本机最近 500 条执行历史，相同 SQL 会合并，条目没有执行时的 schema。因此历史不能直接当作执行次数，也不能把未限定表名直接归到当前 schema。
- `desktop/src/lib/dbSnippets.ts` 已有本机 SQL 片段；`desktop/src/lib/dbRelations.ts` 和 `dbApi.relations` 已有外键、NC 类引用等能力，可供后续复用。
- 当前来源解析保留的是限定名称的末段。跨 schema 补全与使用记忆接入前，需要保留物理表的完整身份，并区分 `schema.` 与 `alias.`。

以上是当前工作区代码观察，不代表已经完成运行验收。

## 第一期：先让工具记住用户

### 1. 用户输入过的表，下次优先出现

不仅记录执行过的 SQL，也记录未执行但已明确使用的表：

| 行为 | 如何学习 |
| --- | --- |
| 从提示列表接受一张表 | 立即记为一次明确选择；下一次符合条件的补全可以前移 |
| 手动输入完整表名 | 标识符输入完成并离开该词后，若能解析、匹配当前元数据，记为较弱使用信号；无需执行 |
| 粘贴 SQL | 完成解析后，已确认的物理表可进入“本次使用”；整段粘贴只产生弱信号 |
| 成功执行 SQL | 增加该语句所引用物理表的使用强度，按执行时的连接与 schema 归属 |
| 只是浏览候选或移动选中行 | 不学习，不把显示次数当作偏好 |
| 接受后立即撤销或删除该表引用 | 撤回这次接受带来的加权，避免误选成为偏好 |

同一编辑过程中的同一表去重，接受补全引发的文本变更不再重复计数。短时间反复执行、脚本中数百条同表语句应合并或封顶，避免一次批处理淹没长期习惯。失败执行本身不增加成功使用分；已验证的手动输入仍可以保留较弱信号。

CTE 名、临时别名和拼写未完成的词不进入长期物理表记忆。不能可靠解析的输入先不学习。

### 2. 排序同时尊重输入意图和个人习惯

采用分层排序，避免一个综合分把不相关的热门表顶上来：

1. **限定候选范围**：按语法位置、可见作用域、连接、schema 及元数据过滤；别名后只给对应来源字段。
2. **比较匹配质量**：完整名称精确匹配优先，其次名称前缀、中文名匹配、缩写或模糊匹配。中文输入时以中文匹配质量排序。
3. **同等匹配内个性化**：手动固定优先，其次近期明确使用与经时间衰减的使用频率；给明确接受和成功执行更高权重。
4. **稳定兜底**：分数相同按名称稳定排序。可见 CTE 与同名物理表的遮蔽关系按 SQL 语义处理，不能被使用频率覆盖。

没有输入前缀时，“最近使用 + 常用”承担主要排序；输入具体名字后，匹配质量优先。例如输入 `bd_proj`，不匹配的热门表 `bd_material` 不应排到前面。

最近一次使用能迅速产生反馈，长期不用的表逐渐降低权重；固定项保持固定。加权只影响相关候选，不隐藏普通表。

### 3. 中文也能找表和字段

利用已有中文元数据，输入“物料”能找到 `bd_material`，输入字段中文说明也能找到真实字段名。候选显示中文，接受后插入真实 SQL 标识符。

一期支持英文名称、前缀和中文名；拼音首字母、复杂模糊匹配可后续增加，避免缩写撞名让首屏失去准确性。中文输入法组词期间不抢按键、不提交候选、不学习未完成词。

### 4. 提示框让用户看懂推荐原因

保留现有编辑器补全框。建议每行展示“标识符 + 中文说明 + 一个简短原因”，例如：

```text
select * from bd_|

bd_material       物料          最近使用
bd_project        项目          常用
bd_customer       客户
```

这是交互示意，名称与顺序不代表用户当前真实使用记录。字段行展示类型与来源，多表重名字段使用别名区分。详细说明中再展示 schema、主键和推荐依据，主列表不堆叠多个徽标。

方向键选择、Tab/Enter 接受、Esc 关闭沿用编辑器约定；补全关闭时按键保持原意，Ctrl+Enter 仍执行 SQL。用户已移动候选选中项后，异步元数据到达不能改变所选对象。使用权重从下一次提示开始生效，当前列表不因学习事件重新洗牌。

设置只增加少量控制：开启/关闭“根据使用习惯排序”、清除当前连接的补全记忆。表项可通过编辑器动作菜单“固定优先提示”或“忘记这张表的使用记录”，无需另造大型管理页面。忘记只移除加权，表仍可正常搜索；清除后不立即从旧历史自动恢复。

### 5. 记忆归属准确、重启仍有效

记忆按稳定连接身份、数据库/schema、物理对象名隔离。连接配置被改到另一数据库时不能沿用旧偏好；具体连接身份复用并检查现有连接身份机制，不包含密码。未加引号和带引号标识符按对应方言的大小写规则处理。

内存中排序，合并写入本机存储，重启恢复。只保存排序所需的对象身份、计数、时间与固定状态，不为补全复制 SQL 正文、条件值或查询结果。记录设容量上限，长期不用的低权重项可淘汰。

一期默认从新行为学习。已有历史可用于有限冷启动，但只采纳能确认物理对象归属的记录：不补造执行次数，不把旧记录套到当前 schema。元数据失效后移除对应推荐，存储失败则退回当前会话学习与普通补全。

## 第二期：让工具理解现在正在写什么

| 输入位置或行为 | 建议体验 |
| --- | --- |
| `FROM` / `JOIN` 后 | 优先提示表、视图、可见 CTE；JOIN 位置再结合已有来源评估相关表 |
| `m.` 后 | 只提示 m 对应来源的字段；常用字段可以在相同匹配质量内前移 |
| `SELECT` 字段列表 | 当前查询来源字段、可用函数；多表同名字段提供带别名的候选 |
| `WHERE` / `ON` | 当前可见字段、比较运算及适用片段，减少无关表名干扰 |
| `GROUP BY` / `ORDER BY` | 按方言支持范围提示字段和可见投影别名，不跨作用域借用名称 |
| `UPDATE ... SET` | 当前目标表字段；已经赋值的字段降低优先级 |
| 输入函数名称与括号 | 当前方言函数、参数说明和插入后可跳转的参数占位 |
| 输入已有片段的名字或缩写 | 搜索现有片段库，展示预览，明确接受后插入 |

字段学习按“物理表 + 字段 + 子句用途”区分。例如常用于 WHERE 的字段不应因此统治 SELECT 列表。

补齐多表字段候选，不再静默截取前三个来源。使用缓存、并发限制与延迟加载控制代价；未加载的来源保留可发现入口，用户指定别名时优先读取该表。未知的派生字段保持未知。

可补充两个明确触发的小动作：“展开当前 `*` 为字段列表”“按已有字段生成带占位值的 INSERT 模板”。沿用现有大小写、格式化和撤销机制。

## 第三期：让工具懂 NC 业务中的下一步

1. **关联条件候选**：用户已经写出两张表和别名，在 ON 位置依据外键或 NC 元数据生成条件，并标明“来自外键”或“来自 NC 引用”。复合关系保留所有关联列；多条关系并列供选。相同字段名不足以确认关系。
2. **历史关联复用**：经用户反复使用、且字段仍存在的 JOIN 条件可以作为较低优先级候选，标记“历史写法”。查询执行成功只说明可执行，不等于业务关系必然正确。
3. **枚举值提示**：字段确有 NC 枚举映射时，同时展示实际值和中文含义。没有元数据就不猜。字面值补全走专门上下文，普通字符串内仍不弹表名。
4. **常用条件片段**：用户常用的组织过滤、逻辑删除过滤等可保存为片段，接受后插入。不要假设每张表都存在 `dr`，也不要默认添加 `dr = 0` 改变查询语义。
5. **参数化查询复用**：先复用用户已保存的片段；随后再评估从多次相似查询提炼模板，变化值变成占位符，避免带回旧客户、组织或单据值。

这部分的核心体验是“建议恰好有依据”。需要多字段或整段 SQL 插入时先看候选预览，由用户接受，不自动执行。

## 实施切分

| 阶段 | 主要接入位置 | 可交付结果 |
| --- | --- | --- |
| 一期 | 扩展 `sqlScope.ts` 对象身份；新增独立使用记录/排序纯逻辑；接入 `sqlProviders.ts`、`SqlEditor.tsx` 和成功执行回调；最小设置入口 | 用过的表前移、中文可查、连接隔离、重启保留、顺序稳定 |
| 二期 | 扩展上下文分类、字段候选、方言候选；复用 `dbSnippets.ts` | 不同子句给不同提示，多表字段完整可发现，片段随输入调用 |
| 三期 | 复用 `dbRelations.ts`、NC 元数据与已验证历史模式 | 有来源的关联条件、枚举与业务片段提示 |

排序逻辑与 Monaco 映射分开，便于单测。继续使用现有词法/作用域分析，不另起正则解析器；当前旧 `sqlComplete.ts` 中的简化别名解析不能作为新学习入口。

Monaco 自身会执行匹配、排序和候选记忆，不能只修改 `sortText` 就假定实际显示顺序正确。中文需要检查 `filterText`、替换范围和候选标签的配合；最终顺序、接受后的 SQL 与键盘行为必须在真实编辑器验收。

## 验收标准

1. **立即变顺手**：同一连接/schema 下，接受 `bd_material` 后重新输入相同前缀，该表在同等匹配候选中前移；手动完整输入后无需执行也能获得较弱加权。
2. **不压过明确意图**：常用表不能压过更准确的名称匹配；CTE 遮蔽、别名作用域、多语句和同名不同 schema 的结果正确。
3. **学习真实行为**：浏览候选、注释、字符串、临时别名和拼写中间态不增加表使用；重复变更、一次批处理不会无限加权；立即撤销接受可撤回对应奖励。
4. **记忆可控**：重启保留，换连接/schema 不串；关闭学习排序恢复普通排序；清除/忘记后不被历史回填立即恢复。
5. **中文与插入正确**：中文能命中，接受后写入正确标识符；覆盖中文输入法、引号标识符、schema 限定名称与部分词替换。
6. **多表准确**：二期至少覆盖四表 JOIN、重名列、嵌套查询和 CTE；通用位置能发现第四张来源表字段，别名限定补全不受无关表干扰。
7. **交互稳定**：方向键选择过程中候选不会突然换对象；Esc、Tab、Enter、Ctrl+Enter、撤销均按预期工作，浅色/深色及高 DPI 不截断关键说明。
8. **性能有证据**：以一万张表的固定元数据样本测量，热缓存情况下从请求到可用建议的 P95 目标低于 100ms；这是待验收目标，不是现有实测结果。冷缓存先响应已有候选，不等待全库列信息；快速输入或切换连接时丢弃过时异步结果。

先用纯逻辑测试验证身份、学习和排序，再用 provider 集成测试验证作用域/缓存/取消，最后在真实 Monaco 检查显示顺序、中文接受及键盘操作。使用固定任务比较增强前后的目标表首屏/前三名命中和选择按键数；不能仅以“补全弹出了”作为验收。

一期完成即可形成明显、持续的体验收益。建议按“表记忆与匹配 → 子句和字段 → NC 关联建议”的顺序实施。
