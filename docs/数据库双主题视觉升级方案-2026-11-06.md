# 数据库双主题视觉升级方案

用户要求改善数据库页的视觉舒适度和廉价感，并同时优化两个主题。范围按浅色、深色两套主题，以及它们各自的柔光玻璃、实色材质制定。

## 当前问题

依据现有数据库组件、`db-console.css`、`db-workbench.css`、共享主题 token，以及真实 React 页的本地模拟数据截图：

1. **同一排控件缺少主次。** 连接、执行、事务、对照、结果比较等操作同时带边框；高频操作与辅助操作的视觉重量接近。普通按钮、胶囊、图标按钮、标签和筛选控件的组合方式也不一致。
2. **横带堆叠。** SQL 工具条、连接上下文、快捷键说明、结果工具条与来源信息分别占用一行。在低窗口中，操作说明挤占编辑器和结果表的空间。
3. **连接与状态重复。** 连接名、环境、用户在文档标签、连接选择、上下文和结果来源里反复出现，状态、小圆点、橙色标签底线又竞争注意力。
4. **阅读节奏不足。** 当前数据库字号包含 10.5 / 11 / 12 / 13px，多处局部字号覆盖；网格为 26px 行高、34px 表头。字段英文名、中文名、值和辅助元信息没有完整的一套排版规则。
5. **框线和区域底色过于均匀。** 每一层横带都用类似边框；浅色内容区大面积纯白，深色各区域又接近相同的灰黑，用户难以快速分辨当前操作与阅读内容。
6. **附属界面风格分散。** 新建连接、条件编辑、历史、片段、列布局、结果对比、修改复核和错误区需要统一标题、滚动、按钮、底部操作与反馈规范。

本地模拟截图只用于验证视觉结构，不接真实业务数据库。早期 SQL 截图探针的结果字段缺失已修正；该探针问题不作为软件缺陷。

## 三个方向

| 方向 | 表现 | 收益与取舍 |
| --- | --- | --- |
| A：专业清晰的工作台（推荐） | 保留现有 NCForge 深青身份；轻柔导航、安静操作区、清晰数据阅读面，减少重复边框和信息 | 最适合长时间写 SQL、看表和核对数据；保留工作台熟悉度，实现以现有组件和样式整理为主 |
| B：宽松阅读 | 更大的控件、字号与行距，辅助信息大幅折叠 | 大屏更舒适，小屏显示行数减少；更偏向查看数据，操作密集度下降 |
| C：极简高密度 | 灰阶为主，更少装饰，紧凑工具栏与表格 | 适合熟练用户和低分辨率窗口；信息辨识与触控宽容度要求更高 |

推荐 A，并把紧凑密度保留下来。已有全局密度偏好优先复用，不再新增数据库专属偏好开关。预览稿中的 30px / 26px 是用于对比的设计参数。

## 统一视觉规则

### 浅色与深色分别调校

| 层面 | 浅色主题 | 深色主题 |
| --- | --- | --- |
| 导航外壳 | 保留淡青灰柔光，降低饱和度，连接树使用稳定背景 | 使用低饱和蓝灰，减少纯黑块和高亮装饰 |
| 编辑器和数据 | 内容面保留清晰底色；辅助横带用轻灰分层，减弱网格框线 | 编辑器、表头、工具条用有限灰阶分层；数据字色略柔和，避免刺眼白字 |
| 文字 | 正文深灰，辅助信息保持可读；不以过浅灰色制造“高级感” | 正文与辅助信息分别提亮，保留明确对比，不整体降低透明度 |
| 强调色 | 深青用于执行、选中项与焦点 | 浅青用于执行、选中项与焦点，按钮文字使用相应深色 |
| 状态色 | 环境、错误、未提交事务才使用语义颜色 | 分别配套浅色墨色，不直接复用浅色主题的深红或深橙 |

玻璃应用在窗口与导航外壳，SQL、表格和长文阅读区域使用稳定底色。实色材质保留相同的间距、排版和交互层级。

### 密度、排版与控件

- 操作区普通控件保持约 30px；图标命中区域至少 28px，表头约 40–44px，舒适网格约 30px，紧凑网格维持 26px。
- 常规操作文字 12–13px、字段值 12–13px、辅助信息 11–12px。SQL 使用现有 Monaco 等宽字体设置，不换成展示字体，不强制覆盖用户字号。
- 中文名和英文列名使用固定上下关系；类型默认留到提示或详情。数字右对齐，时间使用等宽数字，NULL 使用中性的文字样式。
- 每个操作组只突出一个主按钮。历史、片段、筛选等使用文字与图标组合的轻按钮；仅图标的控件必须有名称、提示与键盘焦点。
- 文档标签统一深青选中指示。环境用明确“开发 / 测试 / 生产”标识，避免用不同环境色装饰每个标签。
- 边界按区域设置，避免一行叠加多条边框、阴影、胶囊。表格竖线减弱，行分隔与选区边界保持可辨。

## 各区域怎么改

### 连接树

统一“数据库”标题与新建、更多操作。筛选输入和跨对象查找仍保留各自明确的范围。连接主行显示名称、环境，次行显示用户与数据库；收藏、表、视图和其他对象使用一致的分组与计数样式。

收藏使用说明移到空收藏状态或提示，正常工作时不长期占据两行。状态圆点与文本避免重复；完整连接状态在当前上下文中显示。长连接名与长表名允许省略，焦点或提示可查看完整内容。

### SQL 工作区

调整为文档标签、连接上下文、操作条、编辑器、结果区。连接选择器在上下文里只出现一次；执行与停止固定在同一位置，当前语句 / 选中 SQL / 整个脚本的实际范围可见。快捷键放在相关操作旁，完整说明按需查看。

历史、片段、工具归为右侧辅助操作，窄窗口使用已有菜单收纳。独立会话与事务模式始终可确认，未提交修改时出现专门事务条；不改变提交、回滚、停止和生产写操作确认语义。

编辑器继续使用真实 Monaco，保留补全、光标语句高亮与生产 CSP 修复。分隔条保持克制默认样式，悬停和键盘聚焦可辨；结果高度沿用已修复的拖动、键盘与持久化机制。

### 表数据与筛选

表名主要由文档标签承担，数据 / 结构 / 索引 / DDL 统一选中状态。默认只显示筛选摘要和查询主按钮，完整条件按需展开。

条件编辑按“字段、运算符、值”分组对齐，保存与清空为辅助操作；未应用条件与已应用条件明确区分。低窗口中编辑条件在自身区域滚动，查询按钮不离开可见区域。

### 结果表格

SQL 与表页共用一套结果操作层级：结果 / 输出 / 计划是视图切换，搜索 / 列布局 / 复制 / 导出是内容操作，对照与高级操作归到相关分组或更多菜单。隐藏辅助按钮时，菜单中必须能找到原功能。

采用轻行分隔、有限的交替行底色、一致表头与明确选区。默认列宽结合类型与示例值，保留现有用户列布局；不把短数据列任意拉满，也不将全部列压缩到左上角。

来源与查询耗时整理成简短元信息。底部常驻“已取 N 行 / 可继续读取 / 当前加载范围”等关键信息；完整 SQL、来源库和读取时间在详情中仍可达。表数据与独立 SQL 会话的事务来源保持准确。

### 弹窗、抽屉与状态

- 新建连接：基础字段成组，JDBC 与主机字段沿用现有联动逻辑；引擎、事务、SID、备注等完整可达。固定头尾，正文内部滚动，测试和保存各自显示等待、成功与失败结果。
- 历史与片段：标题、搜索、筛选、条目、操作使用同一套阅读密度；SQL 摘要与时间、耗时、结果分层。保持真实软件单击填回、双击执行语义。
- 列布局、快照对比、关联记录、修改复核、导入导出：统一间距、选择状态、错误说明、关闭与底部确认。
- 加载：连接树 / 结构读取使用骨架或局部状态；执行显示进度与停止状态，旧结果何时保留沿用实际查询行为。
- 空结果与错误：就地给出条件或定位 SQL 的下一步。不会自动重放写操作；长错误与 SQL 可阅读、可复制。
- 交互：按钮按下约 70ms，局部显示隐藏约 160–180ms；无周期性装饰动画，减弱动效和后台暂停沿用全局规则。

## 实施结构与顺序

1. **基础与主工作区**：整理数据库局部排版、颜色角色和控件样式，连接树、文档标签、上下文、SQL 工具条与结果区一起接入。
2. **数据浏览**：表页筛选、结构 / 索引 / DDL、选区、列布局与结果底栏统一。
3. **附属流程**：连接配置、历史 / 片段、错误、事务、对照、关联、会话、导入导出、修改复核和数据库字典统一收口。
4. **真实页面验收**：两套主题 × 两种材质，正常 / 加载 / 空 / 错误 / 未提交 / 生产状态，以及窄窗、低窗与缩放。

优先复用 `Icon`、`Modal`、现有按钮与菜单，保留 dbStore、dbActions、dbApi 和事务边界。必要时按真实共用行为抽出结果工具条；不为纯装饰新增重型库。

网格行高必须同步 `ResultGrid` 的 `ROW_H`、表头高度、滚动计算与 CSS；不能只改样式，否则虚拟滚动会错位。任何布局拆分保持组件体量门禁，避免把整页堆进一个组件。

## 验收标准

- 四种主题 / 材质组合均检查正文和辅助文字对比度，普通文本目标 ≥4.5:1；选中、悬停、聚焦、禁用、加载与错误均可分辨。
- 1280×840、1024×600、560×700，以及 125% / 150% 等效窗口；无外部横向溢出，表格在自身区域滚动，停止、查询、提交与关闭可达。
- 长连接名、长 SQL、多标签、50+ 列、1000+ 已加载行；调整密度后选区、滚动、编辑框、冻结列与列宽保持对应。
- UI 升级后的执行、复制、导出、筛选、编辑、提交、回滚和错误恢复测试保持通过；不以示例原型替代真实业务回归。
- 正式实施后检查 TypeScript、ESLint、组件体量、UI / token 门禁、生产前端构建、体积预算，以及生产 dist 在安装版 CSP nonce / hash 约束下的浏览器回归。
- 不改版本号，不自动提交，不构建 exe / 安装包；确认后完成源码与前端验收。
