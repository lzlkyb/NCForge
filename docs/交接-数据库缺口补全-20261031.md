- 判定「需要回落」的语句形态边界在方案文档 1.6；改写失败必须回落 JVM 桥执行原语句，不是报错——这条要写进验收。

### 问题 2：取消延迟是否确认为「不投入」？

探针已结论：计算类 ~0.2s、等待类最坏 ~3s（服务端块边界，与上游一致）。建议确认「不投入」，并把判据写进验收清单 H 组「已知限制」：「等待类语句的取消最坏 ~3s，19c 服务端行为，与 JDBC/python-oracledb 一致」，避免以后有人重复挖。

## 4. 复跑探针的方法（换库/换版本时才需要）

```bash
# 0. VPN 先连（用户会告知）；不通就别跑，浪费一次编译
timeout 8 bash -c 'exec 3<>/dev/tcp/10.200.22.144/1521 && echo 可达'

# 1. Rust 侧（在 desktop/src-tauri 下；cargo 不在 PATH，必须先 export）
cd desktop/src-tauri && export PATH="$HOME/.cargo/bin:$PATH"
cargo test --test db_break_probe     -- --ignored --nocapture --test-threads=1
# R1-R11；整轮约 12s。R11 会连跑 400 次 return_result（4s 左右），专门看游标泄漏
cargo test --test db_refcursor_probe -- --ignored --nocapture --test-threads=1

# 2. Python 侧（环境已就绪：Python 3.13 + oracledb 26.1.0 thin）
python desktop/scripts/probe-cancel-python.py
python desktop/scripts/probe-refcursor-python.py      # 隐式结果集 / OUT 绑定对照
```

已知环境事实（省得重新踩）：

- 服务端 19.3.0.0.0；探针默认连接串/账号写在探针文件里，**不设环境变量也能跑**。
- `aier633` 账号有 `user_tables`（如 `WORKER_202308`，等锁场景用它造行锁；表空则锁不生效，探针会打印「锁没堵上？」）。
- `connect by level <= 30000000` 会报 `ORA-30009: CONNECT BY 操作内存不足`（~4.4s），10M 约 3.8s 成功——设计 CPU 基线时用 10M，别用 30M 做「必须成功」的断言。
- 探针文件顶部有 `#![allow(non_snake_case)]`（场景名用中文，否则 clippy 的 snake_case 在 `-D warnings` 下挂）。
- ⚠️ clippy 1.99 新 lint **`doc_lazy_continuation`**：doc 注释里编号列表后**直接跟段落**会报错，必须空一行 `//!` 隔开（本轮踩过，已修）。

## 5. 验证门禁口径（与 CI 一致，缺一不可）

**Rust**（在 `desktop/src-tauri/`）：

```bash
export PATH="$HOME/.cargo/bin:$PATH"
cargo clippy --all-targets --no-default-features -- -D warnings   # 双 feature 口径都要跑
cargo test  --no-default-features                                  # 🔴 默认 fail-fast：lib 单测挂了集成测试根本不跑
cargo fmt --check
```

- 探针是 `#[ignore]`，不进 CI 执行，但 `--all-targets` 会编译它们——改探针同样要过 clippy。
- CI 的 clippy 版本可能比本地新（1.96 < 1.99 踩过），本地过了不代表 CI 过。
- **`cargo test` 别与 vitest 重活并行**（worker 超时会显示 passed 但实际没跑；核对测试文件数）。
- `motion:check` 第 8 项（getAnimations 关键帧断言）是已知 flaky，失败先 `git stash` 做基线对照。
- macOS 专属行为（路径语义、平台键）本地验不了，只能靠 CI；推送前本地双口径 + 逐条推演。

**前端五步**（在 `desktop/`）：check-component-size / eslint / tsc / vitest / vite build。组件 ≤300 行、`useState+useEffect` ≤8 是机器门禁（棘轮，存量只许变小）。

**本机环境坑**（memory 原文，照抄可用）：

- Bash 里 cargo 不在 PATH：先 `export PATH="$HOME/.cargo/bin:$PATH"`。
- PATH 里的 GNU tar 不支持 zip；bsdtar 在 `%SystemRoot%\System32\tar.exe`；tar 不接受带盘符路径。
- gh CLI 在 `C:\Program Files\GitHub CLI\gh.exe`（PATH 没有）；git 是 WorkBuddy PortableGit，本机无独立 Git for Windows。
- curl 直连 github.com/releases/download 间歇 000，验收走 gh-proxy 或 gh api。
- PowerShell 的 `/tmp/x.log` 解析成当前驱动器根；判原生命令成败用 `$LASTEXITCODE`（`2>&1` 会置 `$?` 为 false）。
