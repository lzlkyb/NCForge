# 全软件页面与交互升级方案

日期：2026-11-11。范围：设置之外的 NCForge 页面，以及它们共用的工作台导航、操作反馈和窗口适配。

建议按“入口与上下文 → 日常开发 → 验证与交付 → 专业工具”的顺序升级。核心目标是让用户始终知道：正在处理哪个对象、当前能做什么、为什么暂时不能操作、执行完成后去哪里查看结果。

本文是待确认方案，不代表已实施。依据当前工作区源码及已有验收记录形成，并查看了 2026-11-06 的服务控制台明暗主题截图；历史截图仅辅助理解布局，不能作为当前界面的运行验收。旧数据库、代码审查报告中的缺陷需要逐项对照当前实现，不直接认定为仍然存在。

## 1. 升级目标与设计方向

- 面向 NC 开发者的桌面工作台，优先支持找代码、改代码、编译、运行验证、查日志、查数据、审查改动和打包补丁。
- 沿用现有青灰主题、系统字体、Monaco 和设计 token，重点调整信息层级与操作流程。
- 同一类操作采用相同规则；不同性质的操作采用准确名称。例如“保存 SQL 文件”“写回数据库”“提交事务”“提交 SVN”应明确区分。
- 把已有能力呈现得更直接。数据库结果来源、元数据草稿预览、补丁生成确认、服务真实状态等已有机制继续复用。
- 用户切换页面、窗口布局或查看错误时，应保留有效草稿、筛选、选中对象和阅读位置。后台完成不能抢走正在阅读的页面。

## 3. 导航与公共布局

### 3.1 已确认的导航结构

按后续确认采用方案 A：保留代码、版本控制、数据库、元数据四个主导航，不新增“运行与诊断”。NC 服务强化现有入口，继续底部停靠，并支持展开阅读；调试紧贴代码工作台。日志排查保留独立工具页面，支持从服务或错误进入以及返回来源页面。

界面需要显示真实服务状态、当前工程与 NC 目录。打开服务、展开阅读、进入日志及返回原页共享同一份执行状态，避免重复启动或两处展示不同结果。

```text
主导航
  代码            文件 / 搜索 / 当前文档
  版本控制        审查改动 / 打包补丁
  数据库          连接对象 / SQL / 表数据 / 比对
  元数据          编辑 / 生成 / 导入导出

全局辅助入口
  NC 服务（底部停靠 / 展开阅读）、日志排查、工程选择与关联
  命令面板、操作记录、设置
```

旧页面 key、命令入口与 Ctrl+1～6 的既有映射保持兼容；快捷键方案按现有冲突检查机制配置。

### 3.2 页头表达“对象与操作”

各页沿用一致的层级，展示内容按实际任务裁剪：

1. 页面和当前对象：工程、模块、连接与 Schema、BMF 组件、服务或补丁目标。
2. 主要操作：通常 1 个主要动作，必要的停止、撤销和恢复直接可见。
3. 当前状态：待保存、运行中、失败、部分完成、结果过期等。
4. 辅助操作：历史、导出、高级筛选和低频设置。

短名称常显，完整路径或长对象名可展开、复制。作用目标、关键禁用原因和风险不能只藏在鼠标悬停提示中。低频工具可以进入“更多”，完成主任务所必需的条件应直接可见。

### 3.3 窗口空间

- 代码保持编辑器为主区，搜索支持侧栏查看和展开阅读；问题面板随错误定位展开。
- 服务展开阅读使用现有面板；恢复停靠和返回原页时恢复原来的资源树和面板布局。
- 数据库、元数据保留自身的对象资源栏，避免再叠加一套全局文件树。
- 面板收起不丢状态；用户主动调整的宽高与布局锁定继续生效。
- 断点按实际内容区域宽度判断，考虑导航栏、分屏和 Windows DPI，不能仅按整窗宽度推断空间足够。

## 4. 各页面升级内容

### 4.1 代码、搜索与编译

主要流程：选择工程 → 找文件或类型 → 查看与修改 → 保存 → 编译 → 定位问题或继续运行验证。

- 资源区明确区分文件名过滤、工程内容搜索、类型查找，避免三个入口看起来都像同一个搜索。
- 顶部“任务”改为更明确的“开发任务”，展开后列出实际步骤；运行前说明当前工程与执行范围。
- 编译操作显示当前模块或范围，清理重编等操作与普通编译区分。没有当前模块时显示可执行的替代动作或选择模块入口。
- 搜索按文件内容、依赖符号、源码注释标明来源。分组不改变原有搜索范围；只读 jar 结果不会露出替换与写入动作。
- 结果跳转到文件后，返回搜索恢复关键词、范围、命中项与位置；展开阅读与侧栏视图使用同一份结果。
- 代码改动显示比较基线：SVN 基线或本轮快照。“已审”“无诊断”“尚未检查”明确区分，避免局部结果被理解为工程验证完成。
- 编译结果优先展示成功/失败、影响模块、错误数及下一步；原始输出保留在详细区。
- 已有预览标签、草稿标识、外部修改冲突、只读提示等机制统一视觉与术语，并保留现有行为。

验收示例：从搜索命中打开 Java，保存后编译失败，定位到错误文件，再返回原搜索；草稿、查询条件、命中位置都仍然存在。

### 4.2 NC 服务与运行控制台

主要流程：确认工程与 NC 目录 → 选择中间件或客户端 → 启动/调试启动 → 查看阶段与日志 → 停止或重启。

- 服务页首屏常显当前工程、NC 目录、中间件/客户端、真实运行状态及主要动作。
- 普通启动、调试启动、附加调试分别表达，不让一个“调试”词承担多个不同操作。
- 将已有“开始开发”流程用步骤摘要说明：编译、投送、启动等以真实任务定义为准；可跳过项与不可执行项明确标注。
- 当前步骤、已用时间、失败步骤和恢复入口常显。只能确认到“进程运行”或“端口监听”时，不升级文案为“业务正常”。
- 启动设置显示“下次启动生效”，运行详情显示本次真实目录、端口和参数；避免把已保存配置当作运行事实。
- 控制台区明确当前来源、本次/历史运行、是否跟随最新、是否有新日志；用户手动向上阅读时不自动拉回底部。
- 启动失败、端口冲突、热替换未完成等提示提供相关入口，进入详情后可回到原任务位置。

验收示例：客户端与中间件切换不会显示错来源；启动失败能定位对应运行日志，离开页面后再次返回仍显示同一轮任务和阶段。

### 4.3 日志排查

主要流程：选择来源与时间 → 选择问题归因或全文检索 → 查看结论与原文 → 追 callid / 跳源码 → 返回原记录。

- 显式区分“问题归因”和“全文检索”，切换时说明有效的筛选条件。
- 归因模式突出异常类型、慢 SQL、可确认的线索；全文模式突出命中词、来源与时间，不把归因筛选误认为全文条件。
- 来源与时间范围常显，其他筛选折叠后仍显示已启用条件摘要和清除入口。
- 详情按“结论与证据 → 相关记录 → 完整原文”组织；无法归因时如实显示，不生成没有证据的原因。
- 文件只读尾部、达到记录上限、索引过期等覆盖范围信息直接可见。
- 搜索、选中记录、追踪链与源码跳转支持返回；清空检索不误清除用户需要保留的来源条件。

验收示例：切换全文模式后，用户能直接看出“仅问题”和慢 SQL 阈值是否适用；修改范围后结果过期提示明确，重搜后消失。

### 4.4 版本控制与补丁

主要流程：查看改动 → 审查差异 → 选择本次交付内容 → 检查依赖与产物 → 生成补丁 → 查看产物。

- 继续采用“审查改动 / 打包补丁”两个视图，提升跨视图的下一步入口。
- 明确区分正在查看的文件、标记已审的文件、SVN 待提交文件和补丁勾选文件；四种状态不借用同一个勾选标记。
- SVN 提交和生成补丁是不同的交付动作。页面分别说明对象与结果，不把它们合并成一个含糊的“提交”。
- 补丁提供出包摘要：目标目录、文件数、产物新鲜度、附带 SQL、未纳入项目及阻断原因。
- 输出目录直接可见并支持展开编辑。草稿尚未保存时提供“保存目录”的明确动作，保留已有阻止误出包的规则。
- 阻断项可定位到相关文件或配置；有后端依据时提供编译后刷新入口，检查完成前不展示“可以交付”。
- 生成成功展示包路径、清单和打开位置；取消、失败或部分结果分别表达。回滚及文件还原显示实际覆盖范围。

验收示例：从差异审查进入打包，勾选状态有明确来源；输出目录修改未保存时不能误出包；生成成功后无需重新找文件夹。

### 4.5 数据库

主要流程：选择连接和对象 → 写 SQL / 查看表数据 → 执行与阅读 → 编辑或固定比对 → 写回/提交/导出。

- 主执行按钮显示“执行当前语句”或“执行选中内容”，与已有范围提示对应；整脚本执行保持独立选择。
- 常显连接、环境标识、Schema、只读状态与事务模式。当前编辑上下文与旧结果来源分开表示，复用已有结果快照。
- 表页与 SQL 结果网格统一可编辑标记、改动数量、撤销和写回反馈；文件保存、网格写回、事务提交使用准确名称。
- 待写回和待提交事务分开计数；部分成功、已回滚、停止待确认等状态按真实结果展示。
- 对长值预览、NULL、只读连接或不可编辑结果，给出对应说明与已有替代入口。
- 筛选、加载更多、列操作、比较 A/B 和复制导出按任务组织；常用操作直接可见，少用操作收纳到菜单。
- 导出确认区显示真实输出范围：当前页、已加载行或全部查询结果，以及是否包含筛选、选区和完整长值。
- 切换 Schema、连接、查询或关闭文档时，验证已有草稿和事务保护；不能为了减少点击移除数据安全流程。

验收示例：执行一条 SQL，修改结果网格，查看更多行，再写回并处理事务；每个阶段的目标、待处理数量和结果一致。

### 4.6 元数据

主要流程：选择组件 → 查看模型与字段 → 编辑草稿 → 校验与预览保存 → 生成/导入导出 → 检查目标与产物。

- 提升“编辑、生成、导入导出”的任务入口；联动、模型、字段作为编辑任务内的视图选项。
- 当前组件、实体、选中字段与属性检查器的关系可见；切换实体不会让用户误以为属性仍属于旧字段。
- 延续现有草稿步骤、撤销重做、预览保存机制。将“应用到草稿”和“写入文件”的文案与状态明确分开。
- 生成中心先选择产物和目标，再展示预览、冲突与最终写入；未保存草稿时提供去保存的入口。
- 导入显示文件识别、字段映射、校验与确认步骤；错误可定位到对应内容，失败保留映射与有效输入。
- 校验、对比、生成结果支持回到原字段或实体；不通过校验时仍可查看证据与修正草稿。
- 发布 POC 继续标为实验能力，不与成熟的生成、保存和文件写入呈现成同等级默认动作。

验收示例：修改字段、暂时切换到问题列表、回到编辑、预览保存，再进入生成中心；每个阶段使用的组件和版本清楚可核对。

### 4.7 关联工程、对象查找、历史、调试与其他辅助工具

- 工程关联显示当前工程、关联目标、可用状态及路径；明确搜索范围与编译/SVN 作用范围的区别。
- 文件查找、类型查找、命令面板保留快捷键和历史，显示结果类型与来源，避免只能凭图标辨认。
- 数据字典和数据库对象查找显示连接与 Schema，定位后返回原查询或表文档。
- 调试区按停止原因、线程/调用栈、变量、监视组织；未开启调试、未附加、运行中和暂停中使用不同空态。
- 本地历史、SVN 历史、改动时间线明确各自基线与覆盖范围；还原前核对目标版本和未保存修改。
- 调用层级、类型层级、待办和书签按需出现，可继续固定到面板；入口名称与命令面板保持一致。

## 5. 全局交互约定

| 类别 | 统一约定 |
| --- | --- |
| 文本、数字、路径与多字段表单 | 草稿先校验；按现有业务语义明确保存；失焦不触发高影响操作；失败保留输入 |
| 布尔选项与简单筛选 | 按该选项的实际即时行为反馈，不额外增加无意义的保存步骤 |
| 保存与执行 | 保存文件、保存配置、写回数据、提交事务、提交 SVN、生成文件分别命名 |
| 长任务 | 显示对象、阶段、耗时和可用动作；进度与取消能力只来自真实后端契约 |
| 失败 | 原位说明发生了什么、保留了什么、如何继续；toast 只补充结果，不承担唯一说明 |
| 禁用 | 关键动作旁显示原因和下一步；禁用按钮的悬停提示不作为唯一解释 |
| 结果 | 区分未执行、已完成、部分完成、已取消、失败、过期和未检查 |
| 草稿保护 | 页面切换保留草稿；切换作用目标、关闭或丢弃时核对影响范围，不静默覆盖 |
| 恢复 | 恢复布局、清除筛选、撤销本次编辑、回滚文件使用准确范围，不共用模糊“重置” |
| 键盘 | Tab 顺序可预测，方向键切换同组项目，Esc 关闭当前层或按字段规则还原；中文组词时不抢 Esc/Enter |
| 返回 | 返回搜索、日志记录、差异或生成预览时，恢复选中对象与阅读位置 |
| 后台任务 | 完成后给可回到来源的提示，不自动切页；旧任务结果不能覆盖新的工程、连接或文档 |

不要求所有页面拥有相同按钮数量或同一种三栏布局。统一的是操作语义、状态和恢复规则。

## 6. 实施顺序与交付物

| 批次 | 范围 | 可审阅交付物 | 验收点 |
| --- | --- | --- | --- |

| 4 | 版本控制与补丁 | 审查到出包的流程和产物摘要 | 查看/已审/提交/打包状态分明，阻断可处理，路径与产物可核对 |

每批采用“现有行为盘点 → HTML 交互稿 → 实现 → 相关回归 → 场景验收”。界面实施前先审阅交互稿，确定入口和状态语义；在所有批次结束后做一次完整回归。数据库与元数据已有旧审查项先核对修复状态，需要涉及正确性修复的条目另列清单，不夹带在纯布局修改中。

阶段安排比固定日期更可靠。确认导航方案并完成第一批后，再按真实组件改动量估算工期；原生验证、真实服务与数据库环境单独列依赖。

## 7. 验收标准

### 可发现与可理解

- 从任意主页面，进入 NC 服务、全工程搜索和补丁打包的典型路径不超过两次点击。
- 每个主流程首屏可确认目标对象、主要动作、当前状态和关键阻断原因。
- 用户无需记住图标或悬停提示即可完成主任务。
- 选中、已审、待保存、执行完成和未检查的表达可区分。

### 操作与恢复

- 覆盖正常、空数据、首次使用、读取失败、执行失败、取消、部分完成、过期及目标变更。
- 覆盖返回、切页、切工程/连接/组件、关闭、重试和恢复布局。
- 保存失败、查询追加行、后台任务结束等动作不能静默清除有效草稿。
- 关键执行参数和 UI 显示的工程、Schema、文件范围、NC 目录与输出路径一致。
- 键盘能完成主流程，菜单和抽屉关闭后焦点合理返回；输入法组词不触发页面操作。

### 视觉与窗口

- 明暗主题与标准/舒适密度。
- 建议窗口样本：1920×1080、1366×768、1024×768、800×600；另验证分屏后的实际内容宽度。
- Windows 100%、125%、150% 原生缩放；不能仅用浏览器 viewport 代替。
- 主要操作与关键状态不溢出、不被裁切、不依赖整窗水平滚动；数据表本身可以水平滚动。
- 长路径、长 SQL、长日志、较多标签、大文件列表和错误详情仍可阅读、定位与复制。

### 验证与性能

- 每批补充有意义的状态与参数回归，覆盖保护草稿、执行范围、失败恢复及跨目标隔离。
- 完成组件体量、设计 token、UI 约定、ESLint、类型与契约检查；最终相关生产构建与体积预算、完整 Vitest 回归。
- 重任务串行，Vitest 按内存控制 worker；每批主要流程用一次组合检查和一次必要复验，不反复全量打包。
- 服务、日志和数据库的隐藏页面停止非必要轮询；切换布局不增加后台任务与重复查询。
- 浏览器模拟 IPC 验证界面与参数；原生选择器、真实 NC 启停/调试、数据库事务和文件输出单独验证，并记录边界。

## 8. 推荐决策

采用导航方案 B，先完成公共入口与开发流程，再升级服务日志、版本交付、数据库和元数据。每批先呈现完整操作链，审阅通过后实施，沿用现有业务状态与命令。

完成后的重点变化应当是：关键入口找得到，作用对象看得清，失败后继续得下去，完成后能确认结果。
