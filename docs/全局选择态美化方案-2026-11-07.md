# 全局选择态美化方案

本轮为方案与源码盘点，不实施选择态视觉修改。以用户提供的数据库截图为当前视觉依据；性能优化改动独立验证。

## 已定位的直接原因

1. `index.css:769` 对普通 input / textarea / select 统一设置 2px outline。`db-workbench.css` 中 Schema 搜索框由父容器承担布局，但 input 本身没有对应圆角与外框语义，因此焦点线出现在内部，形成截图中的生硬矩形。
2. `db-console.css:232` 对所有 `.dbx-gc[data-cell]` 设置 2px outline；`ResultGrid.tsx` 将每个选中格都标记为 data-cell，导致一个范围被画成多格粗框。
3. 表格同时使用当前整行背景和单元格选区背景，焦点、当前行、选区三个含义重叠。
4. Schema 菜单当前项以文字加粗与勾标记表达，悬停项使用强调底色；文件树、其他列表和设置项又使用不同强度的底色、描边、阴影。

自动扫描清单见 `选择态样式清单-2026-11-07.json`。此清单覆盖当前产品 CSS / TSX 的选择与焦点标记，排除测试和历史 design-preview；命中需要按具体控件语义复核，不能批量替换所有 data-active。

## 统一视觉方向

采用中性控件边框、浅青绿选中底色、清晰的当前项标记。强调色集中用于活动单元格、明确选中项和必要焦点；避免每个控件同时出现强调底色、粗边、阴影与加粗。

状态优先级：错误与冲突标记独立保留；编辑态优先于活动格；活动格优先于范围底色；范围底色优先于 hover。焦点用于说明键盘输入去向，不替代选中状态。

| 状态 | 建议规范 |
|---|---|
| 默认 | 中性底色与 1px 弱边框，尺寸不随状态变化 |
| 悬停 | 轻微中性底色，不增加强调描边 |
| 当前项 | 浅强调底色，配勾或活动标记；正文保持正常字重 |
| 键盘焦点 | 一条清晰焦点环，跟随控件圆角；不叠加父子两层 |
| 非活动选中 | 中性灰底，仍保留选中语义与可读性 |
| 编辑 | 仅实际输入单元格出现完整编辑边界与文本光标 |
| 禁用 | 保持可读对比，移除交互反馈；不能与非活动选中混淆 |

不要直接降低全部焦点线透明度。键盘焦点仍需与相邻颜色有足够对比；高对比度模式使用系统色并保留明确轮廓。

## 两个截图问题的具体方案

### 搜索框、输入框与下拉搜索

- 搜索图标、输入区域与清除按钮组成完整控件，由外层统一绘制 6px 圆角、1px 中性边框。
- 聚焦时同一边框转强调色，外围最多增加一层轻微辅助光晕；输入节点不再单独描边。
- 菜单内搜索高度 30–32px；上下与菜单边缘留 8px 间距，清除按钮不压缩输入区。
- 键盘焦点和文本选择分别表达；不要把输入框全底色染成选中状态。
- 菜单当前 Schema 保留尾部勾，悬停项用更浅的中性底，方向键候选项具有独立焦点标记。
- 恢复默认项保留底部分隔，作为动作项，不伪装成普通 Schema 候选。
- 普通下拉框与带搜索下拉框统一触发器外观。原生 select 的弹出项受系统绘制限制；需要完全一致的列表外观时，复用一套可访问的 Select / Listbox，而不在各页分别自造菜单；方向键、Enter、Esc、首字母定位与禁用项语义必须保留。

### 表格范围选择

- 多格范围只铺一块连续的浅色背景，范围内恢复普通细分隔线。
- 范围仅外周绘制 1px 边界；活动格单独保留 1–2px 清晰轮廓，其余选中格不描粗框。
- 行号与列头轻微联动高亮，避免整条当前行与矩形选区争抢。
- 切出表格焦点后，范围变为中性灰选中态；返回时恢复活动态。
- 进入编辑时只为编辑格绘制输入边界。脏数据、错误与 NULL 仍保留各自语义，不被选区底色完全覆盖。
- 绘制按逻辑选区边界计算，兼容冻结列与行列虚拟化；屏幕外的边界不能误画在当前视口边缘。
- 拖选不使用补间动画，保持即时跟手；不增加额外定时器或逐格布局测量。

| 全局导航与设置目录 | index.css、appearance.css、native-workbench.css、settings-center.css | 当前页保持轻量选中底；键盘焦点独立 |

`glass-material.css`、`appearance.css`、`interaction-density.css` 会覆盖部分以上规则，必须一起复核，不能只改基础样式后让材质或密度层覆盖回去。

## 实施顺序与验收

P0：先修组合搜索框双框与表格逐格粗描边。

P1：统一列表/树/菜单、标签和分段选择；清理同一组件分散的选择态覆盖。

P2：补齐失焦、深色、高对比度、错误叠加与编辑态细节，统一动效。

- 鼠标 hover / 选中 / 键盘焦点 / 编辑态能明确区分。
- 任一输入控件最多一个可见焦点边界，边界与控件圆角一致。
- 6×6 与跨屏大范围选区不出现逐格粗框；单格活动位置清晰。
- 冻结列、横向滚动、虚拟行、Shift 扩选、复制与编辑行为保持正确。
- 选中、失焦、重新聚焦时，不改变控件尺寸，不引发内容位移。
- 浅深色与两种密度下完整验证；100% / 125% / 150% 缩放边线清晰。
- 减少动态效果模式可用；表格拖选即时，普通 hover / 焦点色变约 100–140ms。
- 复杂选择不新增逐格 DOM 测量，不降低已经实现的行列虚拟化收益。

确认本方案后，下一步制作同屏“现状 / 改造后”交互对照稿，优先覆盖 Schema 搜索、6×6 表格选区、树多选、菜单与设置分段控件，再进入产品实施。
