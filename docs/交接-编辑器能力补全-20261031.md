## 0. 为什么会有这个主题

用户的原话是「控制台报错点击报错行跳转到对应类的地方，类似功能都要补全」，并且明确两条约束：

1. **轻量化，要考虑性能**；
2. **别堆快捷键，用户记不住**。

第 2 条直接决定了实现方式：新能力的主入口是**右键菜单 + 命令面板**，快捷键只给已经在无数编辑器里形成肌肉记忆的那几个（`Alt+Enter`）。

### 三条踩过的坑（改这块前必读）

1. **要注册的是 provider，不是右键菜单。** Monaco 在 provider 注册后会自己往右键和命令面板里加项
   （`Find References`、`Quick Fix`、`Format Document`……）。再 `addAction` 一遍就是右键里中英各一条，
   比没有更烦人。所以本批**没有做中文右键菜单**——想做的话必须先解决「怎么去掉内置英文项」，
   否则就是重复。（可行方向：给 Monaco 注入 zh-cn 的 NLS，未验证。）
2. **`ask()` 的第三参从「超时」改成了「params」。** 改签名时 `langProviders` 里补全那一处漏改，
   数字被当成 params 静默丢掉超时；`tsc` 会报出来，别只跑 vitest。
3. **`editor.addCommand` 返回 command id，不是 disposable。** 写成返回值再 `dispose()` 直接类型错。

### 日志行跳转的边界（`lib/logLink.ts`）

只认两种：ecj 的 `N. ERROR in <路径> (at line M)`、前端追加的 `路径:行号`。

**Java 堆栈 `at x.y.Z(Foo.java:42)` 刻意不认**——只有文件名没有目录，工作区里同名类可能有多个，
按名字猜必然指错。要支持它得先接 `fileIndex` 反查，属后续。
`路径:行号` 那条正则的路径段排除了空格与括号：不排除的话堆栈行会被解析成一个叫
`at com.nc.Foo.bar(Foo.java` 的文件（这条是单测逼出来的，不是想到的）。

## 3. 性能约定（轻量化这条约束的落点）

- **provider 是按需的**：Monaco 只在用户触发时才调，编辑器空闲时零请求。
- **引用结果截断 400 条**并说明。全塞给 peek 会白卡几秒，而且人看不完。
- **日志解析用 `useMemo` 整批算一次**，不在 JSX 里逐行跑正则：编译时会连续推几百行。
- **符号数据已有缓存**（`symbols.ts` 按 path 缓存），结构面板接上去不用再请求一遍。
- 大文件（>2000 行）的降级机制已存在（`heavy`），新加的 provider **没有**再单独判一次：
  补全那边已按 2000 行放弃请求，引用/格式化在超大文件上要实测（见 §5）。

## 4.1 第二批落地记录（2026-10-31 第十三~十四轮）

**搜索替换**：`search_workspace` 旁边加 `search_replace`，与搜索共用 `collect_candidates`
（同一份范围，不会「搜得到换不到」）。混合换行 / 编码不能无损往返的文件**跳过并报数**
（`skippedUnsafe`）——按检测编码写回会把原文件里原本就有的乱码字节规范化，等于破坏别人文件。
确认框明说「直接改磁盘、只能 SVN 还原」，running 阶段不可关闭（遮罩 / Esc 同样失效），
改完提示「搜索结果过期」并给「重新搜索」按钮，不自动重搜。

**本地历史**：存**原字节**（不做编码 / 换行转换）→ GBK / 混合换行 / 带 BOM 的文件原样进、
原样出；SHA-256 去重；`{config_dir}/local-history/{slug}/index.json` + `{id}.bin`；
单文件 20 版、总量 512MB / 500 文件整份淘汰。抓取时机三路：**保存前**（`fileSave.saveOne`
里 await `capture`，晚了就只能抓到新内容）、**切文件 / 关编辑器**（`useLocalHistorySweep`
的 cleanup）、**每 5 分钟兜底**（外部工具改了磁盘也能抓一版）。恢复是破坏性操作但后端会先把
当前内容归档一版，所以确认框里敢承诺「可再退回来」；`expectedMtimeMs` 防「磁盘被改过还覆盖」。

**diff 自己写**（`lib/textDiff.ts`）：掐公共前后缀 + LCS 一维 DP，`MAX_SIDE_LINES=4000`、
中间段面积上限 400 万格；`collapseDiff` 把长相同段折成「⋯ N 行相同 ⋯」，否则 3000 行文件
改 1 行也要渲染 3000 个节点。比的是**磁盘现状**而不是编辑器未保存内容——恢复写的是磁盘。

**FilesTab 被拆**（本轮两次顶到体量门禁）：编译 → `hooks/useModuleCompile.ts`，
命令登记 → `hooks/useFilesTabCommands.ts`，面包屑行 → `components/workspace/EditorNavRow.tsx`。
两个弹层开关合成一个 `panels` state（两个布尔会顶穿 ≤8 个 hook 的上限）。

### 本批的坑（后来者必读）

1. **`replacePreview` / `textDiff` 必须独立文件**：不 import tauri 的纯函数才能进 node 单测，
   并进 `localHistory.ts` / `searchStore.ts` 会把 `@tauri-apps/api`（后者还会拖 Monaco）拖进 jsdom。
2. **命令面板防闭包过期**：`useFilesTabCommands(deps)` 每帧覆写 ref，`run/enabled` 从
   `live.current` 读；`registerCommands` 只在挂载时跑一次。
3. **组件测试用 Harness**：静态 props 快照下 `update` 写不回去，组件永远拿旧值
   （`ReplaceBar` / `HistoryPanel` 都因此返工过一轮）。
4. **验证强度纪律**（用户明确要求，起因是全量 `cargo test` 会把机器跑蓝屏）：
   禁全量 `cargo test` / 全量 `vitest run`；Rust 用 `cargo test --no-default-features --lib <模块>::`；
   前端 `npx vitest run <指定文件>`；clippy 只 `--lib --bins`；rustfmt 只格式化本次文件；
   `vite build` 等重活留给用户。详见 `.workbuddy/memory/2026-10-31.md`。
