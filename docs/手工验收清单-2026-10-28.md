# NCForge 手工验收清单

> 2026-10-28 生成。自动测试（Rust 221 项 / 前端 194 项）覆盖不到的都在这里：要么需要真实 NC 环境、
> 真实 SVN 工作副本、真实 Oracle，要么需要人眼看布局。
>
> 一共 **8 组 68 项**。全做完约 100~120 分钟（不含等服务启动的等待）。

## 怎么用

1. 从上往下做。顺序是按「风险递增 + 依赖关系」排的，跳着做容易返工（比如补丁要等编译产物）。
2. 每项前面是复选框，做完打勾；失败的**不要打勾**，在旁边写一行 `实际 = ...`，需要截图就存临时目录。
3. 标 🟥 的会改真实数据、占端口或吃内存 —— 做之前确认这台机器上没别人在等 NC 服务。
4. 全部做完把这份文件发我，或者直接说「哪几项挂了」，我按编号修。

| 标记 | 含义 |
|---|---|
| 🟩 | 纯界面，随时可做，不影响别人 |
| 🟨 | 只读，但慢 / 起进程 / 连库 |
| 🟥 | 会改真实数据或占系统资源 |

**建议顺序**：A → B → C → D → E → F1 → G → F2

理由：F2（提交）是唯一会改远端仓库的，放在最后；G 起服务要占 80 端口和 4G 内存，排在 F2 前面先做掉、测完停掉。

## B. 文件与编辑 🟩（约 12 分钟）

- [ ] **B1** 打开 `newar` 里任意一个 `.java`：能滚动、能编辑，`Ctrl+S` 后标题上的未保存标记消失
- [ ] **B2** 改一行不保存就切到别的文件，再切回来 —— 改动还在（Monaco model 没丢）
- [ ] **B3** 编码标记：找一个 UTF-8 含中文的文件，文件树上带 `U8` 标记，打开不乱码
- [ ] **B4** GBK 文件（多数老文件）打开不乱码
- [ ] **B5** 混合换行文件（`MIXED`）：打开是只读 + 有提示条，选「统一为 CRLF」后能编辑，保存后换行统一
- [ ] **B6** 超大文件（如 `VoucherBO.java` 6433 行）打开：有降级提示条，内容能读、能搜
- [ ] **B7** 右键新建文件 / 新建目录：名字带 `\ / : * ? " < > |` 或叫 `CON` 时被拦下，并说明原因
- [ ] **B8** 只改大小写的重命名（`abc.java` → `Abc.java`）：成功，内容不丢
- [ ] **B9** 删除文件：有二次确认，确认后树里消失、标签页同步关掉
- [ ] **B10** 搜索页搜一个类名（如 `CrossBorrowBill`）：出结果，点结果能跳到文件并定位到行附近

## C. 编译 🟨（约 10 分钟）

- [ ] **C5** 有未保存文件时点编译：应弹提示，不能默默编旧内容
- [ ] **C6** 编译过程中切到别的页面再切回来：进度不丢，也不会重复起编译

## D. 补丁打包 🟥（约 20 分钟，会写本地正式目录）

> 前置：C3 通过（有新鲜 class）。

- [ ] **D1** 左栏列出未提交改动并按模块分组；每个文件有 `M`/`A`/`?` 字母 + `hyext`/`标准`/`upm`/`网页` 标签 + `2 class`/`未编译`/`过期` 三者之一
- [ ] **D2** 输出目录：**第一次打开时应显示**「继承 nc-patch 脚本」或「自动找到」，路径是 `D:\NC技术文档\爱尔文档\补丁\待上线补丁`。
      如果显示橙色的「建议目录 · 还不存在」，说明自动探测没命中 —— 请记下来，这是要修的
- [ ] **D3** 右栏「落位预览」：根上有 `CHANGES.md`，下面是 `replacement/modules/<模块>/...`；点一个文件名能看详情卡（模块 / 产物 / 落位 / 层判定依据）
- [ ] **D4** 勾 `ic` 的 crossborrow 那批（6 个 java）→ 写改动描述 → 点「生成补丁包」
- [ ] **D5** 打开生成的 zip，与手工出的那份**逐条对比目录**：条目数、落位层、`.java` 与 `.class` 和 `$1` 内部类是否并排
- [ ] **D6** 再生成一次同名包：提示旧包已备份成 `.bak-<时间戳>`，去目录里确认 `.bak` 真的在
- [ ] **D7** 挂一个 SQL 文件（绝对路径）：生成后 SQL 在 zip 根；`CHANGES.md` 里有「`SQL（需人工执行…）`」一行
- [ ] **D8** 故意勾一个「未编译」的文件：底部出现阻断计数，出包成功后去 zip 里确认它**不在**包里
- [ ] **D9** `CHANGES.md` 页：五节手写内容能写进包；自动段只读且格式对（`打包日期` / `落位层` / 每个文件的 `新增 N 行 / 删除 M 行` 与 `涉及方法`）
- [ ] **D10** 点「表结构核对」tab：第一次应显示「还没拉过表结构」空态。点「连库并拉表结构」→ 若还没输过密码，提示去数据库页；去数据库页连一次再回来，点同一按钮应在几秒内拉完（两千多张表），显示「缓存 N 张表 · 刚刚」
- [ ] **D11** 有缓存后点「开始核对」：应给出文件数、表数、字段引用数。**重点看有没有误报**——把「字段在表里找不到」逐条点开对照代码，确认不是抽取归属算错。误报一条就要停下来告诉我（判定过严比漏报更伤）
- [ ] **D12** 故意在 SQL 里写一个不存在的表名（如 `from bd_materia`）→ 核对应报「表在库里找不到」并给出相近名；此时点「生成补丁包」，第一次只变橙色按钮 + 提示，第二次才真出包
- [ ] **D13** 编辑器里把鼠标停在 SQL 字符串里的表名上（如 `pam_equip`）→ 应弹出该表的字段与类型表格，带「表结构缓存 · 几小时前」。**注意**：MyBatis 那种把表名写在 XML 里的、或表名是变量的（`from " + tableName`）不会弹，这是设计如此
- [ ] **D14** 数据库页改连另一个库（或在设置里改 `db_url`）→ 核对面板应显示「还没拉过表结构」而不是拿旧缓存核对（缓存按「连接串 + 用户」分文件）

## H. 已知未做（这些不用测，测了也没有）

不是 bug，是这轮有意没做的。想加的时候再说。

| 位置 | 缺什么 | 为什么没做 |
|---|---|---|
| 编译 | 点问题行不跳到出错行号 | 等 M4 的 jdt.ls 索引 |
| 编译 | `aim` 模块 46 个错误未查清 | 类路径里同名 `StringUtils` 挑错版本，成因未定 |
| 编译 | NC home 路径写死 `D:\ncc\1909home` | 按内容探测的方案排到 M8 |
| 数据库 | SQL 编辑区是朴素 textarea | Monaco 的 SQL 语言包要额外接 |
| 数据库 | 「历史 / 格式化」按钮没有 | 没有后端支撑，不做假按钮 |
| 数据库 | 只支持单条语句，不能跑整个脚本 | 只读面板不承担这个职责 |
| 版本控制 | 目录级展开不列里面的文件 | 未纳管目录只显示一行 |
| 版本控制 | 提交面板不显示「上次提交说明」 | 要多调一次 log，等有需要再加 |
| 版本控制 | 冲突面板只做三选一，不逐块合并 | 逐块合并要自己做 merge 算法 |
| 补丁 | 暂不支持自定义产物根之外的探测策略 | 已够用，先看真实使用 |
| 表名核对 | 悬停卡片是 Markdown 表格，不是设计稿里的自定义卡片样式 | Monaco 的 `provideHover` 只收 Markdown / 纯文本，喂不进 DOM |
| 表名核对 | 不判「字段长度够不够」 | 真实代码里值基本是拼接变量，静态判不出长度，硬做只会满屏误报；长度在悬停卡片里显示，由人判断 |
| 表名核对 | 表名写在 XML（MyBatis）里、或表名是变量拼的，不参与核对与悬停 | 只认 Java 字符串字面量里的表名，宁可漏不误报 |
| 表名核对 | 运行时才建的表会被报「库里找不到」 | 如 `EquipSysAction` 里的 `SBMC`/`AierSQ`（先 `create table` 再 `insert`）。静态核查看不到运行期建的表，这类会出现在结果里，人工忽略即可。还没做「忽略名单」 |
