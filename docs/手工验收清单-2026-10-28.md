## 怎么用

1. 从上往下做。顺序是按「风险递增 + 依赖关系」排的，跳着做容易返工（比如补丁要等编译产物）。
2. 每项前面是复选框，做完打勾；失败的**不要打勾**，在旁边写一行 `实际 = ...`，需要截图就存临时目录。
3. 标 🟥 的会改真实数据、占端口或吃内存 —— 做之前确认这台机器上没别人在等 NC 服务。
4. 全部做完把这份文件发我，或者直接说「哪几项挂了」，我按编号修。

| 标记 | 含义 |
|---|---|
| 🟩 | 纯界面，随时可做，不影响别人 |
| 🟨 | 只读，但慢 / 起进程 / 连库 |
| 🟥 | 会改真实数据或占系统资源 |

**建议顺序**：A → B → J → C → D → F1 → G → F2 → I → K

理由：A/B/J 是纯界面或只读，先做掉拿到信心；F2（提交）会改远端仓库、K（K9~K12）会写测试库，都需要你明确同意后再点；
G 起服务要占 80 端口和 4G 内存，排在 F2 前面先做掉、测完停掉；I 起 650MB 的 jdt.ls，放后面一次性做完再关。
