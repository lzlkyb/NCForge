# SQL 智能补全实施与验收

日期：2026-11-11。

## 正式接入

三期能力使用正式应用的 Monaco 和数据库 API；原型示例不参与生产排序。

| 阶段 | 已实现 |
| --- | --- |
| 一期 | 中文找表与字段；接受、完整手输、粘贴及成功执行的使用信号；同等匹配内按固定、近期、衰减频率排序；连接/schema 隔离；本机持久化；撤销回滚；IME 组词保护 |
| 二期 | SELECT、WHERE、ON、ORDER/GROUP、SET 等子句上下文；来源和重名字段限定；已赋值字段降权；当前方言函数与参数占位；复用本机 SQL 片段，`{{参数}}` 转为可跳转占位；右键展开投影 `*`、生成 INSERT 模板 |
| 三期 | 外键及 NC 显式类引用条件；真实枚举值和中文含义；已验证 `dr` / `pk_org` 字段的可选条件；重复成功执行且字段仍存在的历史 JOIN 写法，使用当前别名 |

“更多 → 补全记忆”提供搜索、固定、忘记、关闭学习和清除当前连接/schema 的记录。清除包含历史关联；确认捕获原 scope，切换连接/schema 后不会误清其他记录。设置 → SQL 格式化中提供学习排序开关。

自动提示只提供候选，接受或生成模板均不执行 SQL。函数、组织过滤和 INSERT 值必须由用户填写或确认。

## 正确性与资源控制

- 复用现有词法与查询层级，不从去重的旧执行历史补造频率。
- 表来源保留完整 owner、对象引用与别名原文；CTE 和临时别名不作为物理表学习。
- 匹配等级先于使用权重；中文接受替换完整输入词，光标位于单词中间也不残留旧后缀。
- 当前候选是一次快照，学习和后到元数据不会在用户选择过程中重排对象。
- 字段读取共享全局两路闸门，队列最多 16 项。普通多表补全最多预热 32 个来源，所有其他来源保留别名入口，输入 `alias.` 优先读取对应表。
- 冷字段或 NC 元数据超过 120ms 时先返回可用快照，后台缓存预热；下一次输入或 Ctrl+Space 使用新结果。
- 切换 schema、修改连接身份或重连时作废补全元数据；请求在排队、读取和响应时检查冻结连接/schema/缓存代际，丢弃过时结果。
- NC 元数据只允许独立会话，不回退用户主会话，保护查询续取游标。
- 一次执行脚本按 run token 合并同表奖励；成功结果的学习使用执行时冻结的身份。清空代际阻止迟到的学习回填。
- 只存对象、字段对、计数与时间；连接身份使用双哈希，不保存 SQL 正文、参数值或结果到补全记忆。
- 投影展开只处理独立通配符，`COUNT(*)` 和 `price * quantity` 均不会被改写。

## 当前边界

- NC 关联和枚举要求当前普通物理表的元数据可读；权限、结构或完整性不足时不猜测。
- 现有后端和字段缓存仍会对引用对象折叠大小写。带引号物理表可保留身份和接受记忆，但其字段读取、展开与历史关联学习保守跳过，避免查到同名错误对象。带引号别名按原文生成 SQL。
- 列表接口仅提供当前 schema 的对象。输入其他 schema 前缀时不会借用当前清单；已写出的普通完整限定表名可按其身份读取字段。
- 多表裸 `*` 要求先使用明确的 `alias.*`；避免误把一张表字段当成整个投影。
- 参数复用以用户保存的片段为依据，没有自动提炼或携带过去的客户、组织及单据值。
- 不更改版本号、不生成安装包；本次审查后按用户授权提交 SQL 补全及必要依赖，其他工作区改动继续保留。
