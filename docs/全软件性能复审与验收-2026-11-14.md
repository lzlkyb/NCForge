# NCForge 性能复审与验收 · 2026-11-14

本轮以修改前的工作区为对照，包含当时已有的未提交改动。覆盖了应用启动和切页、代码与搜索、数据库、构建、服务日志、版本控制、元数据和后台进程的主要执行路径。代码审查、浏览器模拟和真实进程测量采用不同口径。

## 已实施

| 路径 | 发现与改动 | 验收口径 |
| --- | --- | --- |
| 快速导航 | 面板原本通过语言服务静态引入 Monaco。命令与普通文件搜索现在独立加载，符号、类型回退和 JDT 跳转按需加载语言服务。保留原有面板预热。 | 包含入口共享依赖在内，面板静态 JS/CSS 从 4.41 MB 降至 1.07 MB，减少 75.7%。gzip 从 1.19 MB 降至 0.35 MB。 |
| 数据库复制与导出 | 单格复制和打开右键菜单原本创建整表快照。现在快捷复制只读取实际参与输出的行，按需复制含草稿的行。高级复制与导出仍创建独立快照，原值和编辑值共用未改动的快照行。 | 单格测试将未选中的行设为读取即报错，验证复制仍成功且保留 NULL 草稿。生产页面验收覆盖剪贴板、后台导出、取消和重试。 |
| 数据库结果内存 | 筛选和比对的计算状态会引用旧输入。结果替换、清筛选和清比对键时丢弃过期计算状态。默认等高网格直接按行号计算位置，省掉两份随行数增长的高度数组。换行时达到八行高度即停止测量。 | 测试覆盖替换数据、旧 Worker 回调、固定和可变行高、选择与键盘定位。 |
| 构建与服务日志 | 编译日志最多 5000 行，流式追加时曾整段重新解析来源链接。现在仅解析虚拟窗口。服务日志的测高刷新复用行索引，避免为未变的 4000 行重复建键集合。 | 测试覆盖日志链接、追加和淘汰时的阅读位置、跳转、跟随和隐藏时清理。 |
| 空闲后台 | 文件监听从 350 ms 定时复查改为按文件事件唤醒。搜索包线程从 300 ms 轮询改为按入队与脏标记唤醒。搜索命令把读包和未保存文本准备移到阻塞任务线程。版本和平台共用进程内缓存，移除主界面每 30 秒读一次版本的调用。 | 两个线程均启动且无工作时，从理论合计约 371 次定时唤醒/分钟降为零。该数字只统计这两个循环，尚未采集整机 CPU 或功耗。 |

## 浏览器对比

Windows，i7-11800H，约 16 GiB RAM。使用 Edge 运行生产构建，应用命令由内存数据模拟。帧间隔是同一机器上顺序执行的单次前后采样，每项 179 帧。排除与其他构建或测试重叠的首次采样。

| 场景 | 修改前 P95 | 修改后 P95 |
| --- | ---: | ---: |
| 宽表水平滚动 | 16.8 ms | 16.8 ms |
| 宽表垂直滚动 | 33.4 ms | 33.4 ms |
| 宽表斜向滚动 | 33.4 ms | 33.5 ms |
| 文件树滚动 | 16.8 ms | 16.8 ms |
| 服务日志滚动 | 16.8 ms | 16.8 ms |

宽表模拟输入 10000 行 × 100 列，结果预算下实载 4035 行。三种滚动均未采到空白单元格，结束时挂载 21 行和 14 个表头。斜向滚动中位数仍约 33 ms。服务日志这组样本中超过 25 ms 的帧从 8 帧降至 0，P95 持平。

启动到代码工作台后立即打开命令面板，各测 5 次。输入框可见的中位耗时为 159.1 → 147.5 ms，样本有限。5 秒后主动回收再读取的页面 JS 堆中位数为 60.44 → 60.50 MiB，两组代码工作台都已加载 Monaco。该数据不能代表整个 Windows 进程树内存。最终生产 JS 体积 6042 KiB，gzip 1785 KiB，最大块 3129 KiB，均在当前预算内。

## 回归验证

- 前端 526 个测试文件、3830 项测试通过。构建辅助脚本 56 项通过。TypeScript 检查及本轮改动源码的 lint 通过。
- Edge 生产构建通过宽表筛选、DOM 数量和结果释放验收。复制导出生产场景覆盖浅色、深色、两种材质、剪贴板和原生保存模拟。

- Rust 搜索、内容包和文件监听 89 项单元测试与 1 项建包队列集成测试通过。真机搜索延迟用例按默认设置跳过。

## 剩余瓶颈与待验证范围

| 优先级 | 路径 | 本轮证据与下一项验收 |
| --- | --- | --- |
| 高 | 宽表滚动、列宽和换行 | 斜向滚动仍是实测瓶颈。默认滚动期间节点挂载与卸载次数未下降。应按 React 更新、布局与绘制分段采样。首次宽表仍在界面线程测量列宽，换行时也会测量全部加载行，需要单独记录 50 ms 以上任务和输入延迟。 |
| 高 | 整应用长期内存 | 已有搜索内容包 320 MiB、编辑器正文 64 MiB、SQL 单结果 16 MiB 和多结果 64 MiB 的各自预算。这些阈值不包含全部索引元数据、撤销栈、渲染器或外部 JVM。需要真实 WebView2 与 Java 子进程合计的峰值和回收后私有内存，并重复打开、查询、释放和切工程。 |
| 高 | 大工程冷启动和首次搜索 | 工作区监听仍在桌面启动流程同步登记，首次读包仍会竞争磁盘。预热入口有共享门闸，但内容包构建和 SVN 预热仍有独立执行路径。需要真实冷盘、网络盘以及编辑器恢复和索引并发时的首屏和首次输入采样。 |
| 中 | 文件名快速搜索 | 普通模糊搜索在界面线程扫描文件索引并排序候选。当前结果上限限制渲染量，排序之前的成本仍随文件规模增长。应测一万、五万、十万文件，包含连续输入。 |
| 中 | 数据库比对和导出 | 大结果比对主体已走 Worker，差异字段筛选与 TSV 全量拼接仍在界面线程。生产浏览器测试使用模拟连接，真实 Oracle、JDBC 桥、查询取消和大对象需联测。 |
| 中 | 编译、SVN、元数据和资源安装 | 已有日志限额、SVN 状态缓存、元数据可见区域裁剪及下载流式写盘。全量编译诊断列表、慢盘本地历史、版本控制大 diff、复杂元数据图和组件解包的运行时峰值未在本机联测。 |

常用点击到反馈 P95 ≤100 ms、60 Hz 下滚动 P95 接近 16.7 ms、重复操作后的私有内存不随次数持续增长作为验收指标。本轮证据尚不能确认全软件达到这些指标。
