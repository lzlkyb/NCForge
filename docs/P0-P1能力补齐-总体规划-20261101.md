## 1. P0-1　补丁应用 / 回滚（摘要，详见专文）

核心事实（实测）：zip 带统一 `replacement/` 前缀，**剥前缀即 1:1 落 HOME 根**，
与出包侧 `patch_view::target_dir()` 同一套规则，所以应用侧不另写映射。

台账落 `{config_dir}/patch_applied.json`，每条记录存 `zipSha256` + 每个文件的
`before{sha256,backup}` / `after{sha256}`。回滚靠两个哈希判断"中途有没有人动过手"。

批次：

| 批 | 内容 | 估 |
|----|------|-----|
| A | zip 校验 + 逆映射**预演**（只读，不改盘） | 1.5 d |
| B | 应用（备份 + 原子写 + 台账）+ 冲突检测 | 2.5 d |
| C | 回滚 + 补丁页签的"已装补丁"列表与对话框 | 1.5 d |

不做：自动执行 zip 里的 `.sql`、打补丁到远端、`_src.jar` 双产物。

## 2. P0-2　日志归因（摘要，详见专文）

核心事实（实测）：

- 1909 是 `nclogs/server/` 下 42 个 `*-log.log` + 2 个子目录，**没有 `run.log`/`err.log`**
  （那是 NC57/65）。`ierp/bin/logger-config.properties` 是 logger→文件/轮转的权威表，
  **不许硬编码文件名**。
- 行格式 `$$k=v … $$msg=`，四条硬约束：GBK、CRLF、堆栈行不带前缀、`debuglevel` 不可信。
- **`callid` 就是 traceId**，跨 logger 可串一次请求。
- **`warningsql-log.log` 自带 `costtime` / `rownum`**，慢 SQL 不用算，排序即可。

批次：

| 批 | 内容 | 估 |
|----|------|-----|
| A | `nc_log.rs`：读 config → 文件清单；GBK/CRLF/续行解析器 + 真日志切片单测 | 2.5 d |
| B | 规则表（12 条）+ 归因 + callid 串联 | 1.5 d |
| C | "NC 日志"页签 + 跳转（源码 / `.upm` / SQL 窗口） | 2 d |

## 3. P0-3　数据字典导出

### 3.1 为什么值得做

NC 交付里"给甲方一份数据字典"几乎是每个项目都有的动作，现在靠
`65数据字典.chm`（本机 `/d/ncc/65数据字典.chm`）+ 手抄 Excel。
而**开发者真正要的不是全库字典，是"我改的这几张表长什么样"**。

### 3.2 连接问题已经解决了（复核代码后修正）

初稿我写的是"可以从 `prop.xml` 免手填连接"——**复核发现这已经是既有能力，不用新做**：

| 证据 | 位置 |
|------|------|
| 连接串默认从 NC home 的 `ierp/bin/prop.xml` 读 | `config.rs:56` |
| 连接来源有 `manual` / `prop` 两种，`prop` 即 NC 的 `prop.xml` 数据源 | `config.rs:125` |
| 首次启动自动导入 `prop.xml`，只做一次（用户删掉的不再加回） | `config.rs:72` |
| 解 `prop.xml` 加密口令用 NC 自带的 `PropXMLReader`，首次连接时在 JVM 里解一次存 DPAPI | `db_bridge.rs:58`、`db_engine.rs:61` |

所以数据字典**直接复用现有连接列表**即可，A 批不需要做连接导入。
`prop.xml` 里 `<isBase>true</isBase>` 说明 NC 自己区分设计库/基础库，
但我们的连接模型目前只记 `origin`，**没有记这个维度**——要不要加，见 §9 待确认。

### 3.3 取数（Oracle only）

引擎只有两个（`EngineKind::Java` 走 JVM+JDBC、`EngineKind::Rust` 走 `oracledb`），
**都是 Oracle**，不需要多方言分支，SQL 直接写死 Oracle 字典视图：

| 内容 | 来源 |
|------|------|
| 表清单 + 表注释 | `all_tables` ⋈ `all_tab_comments` |
| 列 + 类型 + 长度 + 注释 | `all_tab_columns` ⋈ `all_col_comments` |
| 主键 | `all_constraints(ConstraintType='P')` ⋈ `all_cons_columns` |
| 索引 | `all_indexes` ⋈ `all_ind_columns`（可选，第二版） |

🔴 **规模约束**：NC 库 2000+ 张表。全量导会拉几百次往返、生成几十 MB 文档，没人看。
所以默认**不导全库**，三种入口：
1. 勾选表（带模糊过滤，复用现有对象浏览器的过滤）
2. 按前缀批选（`bd_` / `sm_` / `org_` / `arap_` …，NC 表名有约定）
3. 「补丁涉及的表」——从当前补丁草稿里扫出的 SQL 引用表名直接带过来（**这是最贴工作流的入口**）

### 3.4 输出

- **首版出 CSV（UTF-8 带 BOM，Excel 双击不乱码）** + Markdown 两份。
  不引 xlsx 写库：CSV 已能满足交付，多一个依赖不值得（体积预算红线 §8）。
- 一表一节；CSV 是扁平结构（表名,表注释,列名,类型,可空,主键,列注释），便于甲方自己透视。
- 加分项（复用 `sql_refs` / `SchemaIndex`）：标出"当前工程源码里从没出现过的表"，
  顺手能发现死表与漏改。

### 3.5 批次

| 批 | 内容 | 估 |
|----|------|-----|
| A | 补 `db_schema` 的注释查询（现在只有「表名+列名+类型」，**没有注释**） | 0.5 d |
| B | 三个入口（勾选/前缀/补丁涉及）+ 取数 | 1.5 d |
| C | CSV + Markdown 产出与定位 | 1 d |

## 4. P1-4　热部署

### 4.1 先纠正一个容易误判的点

本机 `prop.xml` 第 3 行有 `<enableHotDeploy>false</enableHotDeploy>`，
看起来像"NC 的热部署开关"。**它不是**：该文件的根元素是
`ClassType="nc.uap.plugin.studio.ui.preference.prop.PropInfo"`，
即 **UAP Studio 的项目偏好**（IDE 侧"保存时同步到服务器"那个开关），不是运行时开关。
把它改 true 不会让运行中的 JVM 换类。

所以真实可用的只有两条路：

| 路径 | 机制 | 能改什么 | 代价 |
|------|------|---------|------|
| **JDI redefineClasses** | 走已打通的调试通道（`debug.rs` / java-debug 0.32.0） | **只能改方法体**；增删字段/方法、改签名都不行 | 秒级 |
| **复制 + 重启** | 落盘到 `modules/<m>/classes`，重启中间件 | 任意 | 约 40 s |

我们的定位是**第一条自动、第二条兜底**，且**不假装成功**：
JDI 推不动时明确报"结构性变更，需要重启"，并给一键重启。

### 4.2 必须先 spike（0.5 d，go / no-go）

唯一的不确定点：**`redefineClasses` 对 NC 的类加载器成不成立**。
NC 用的不是标准 AppClassLoader，而是 `BootstrapClassLoader` 那一套多段加载，
而 `redefineClasses` 只对"**已被某个 loader 加载过的类**"生效，且要求前后结构兼容。

spike 做法：改一个方法体里的字符串常量 → 触发保存 → 断言
① 能定位到加载该类的 loader；② redefine 返回成功；③ 页面/接口行为真变了。
**失败就只做"复制 + 重启"**，把 JDI 那条降级为"能成再加"。

### 4.3 批次

| 批 | 内容 | 估 |
|----|------|-----|
| 0 | spike（go / no-go） | 0.5 d |
| A | 保存 → 编译当前文件 → 落盘到 HOME（复用补丁应用的落位逻辑） | 1.5 d |
| B | JDI redefine（若 spike 通过）+ 失败降级提示 + 一键重启 | 1.5 d |

🔴 与补丁应用共用落位代码，不要写第二套 —— 两处对不上的后果是"补丁生效了但热部署没生效"。

## 5. P1-5　元数据体检（只查，不建模）

### 5.1 边界（与三期）

三期做**生成侧**（建模 → BMF → VO → 建库脚本）。本项做**校验侧**：
拿"已经发布的结果"和"工程里的代码"对撞。两者只共享"读元数据"，不共享工期。

### 5.2 分两层，文件侧先上（不依赖库）

**文件侧（可以立刻做，零风险）**

| 检查 | 依据 |
|------|------|
| `.upm` 组件重复注册 | **本机日志实测** `DuplicateException: Detail Message: deviceregister`，路径直指 `modules/mmbcm-scm/META-INF/accessright.upm` |
| `METADATA/*.bmf` 与 `META-INF/*.upm` 声明的组件名不一致 | 两处都读，比组件名集合 |
| VO 里 `getAttributeValue(XxxVO.FIELD)` 的常量是否为 `null` | 社区高频坑（"getsStatus 一直是 null，要改 super."）；纯静态分析，扫 `.java` 即可 |

**库侧（连库才做）**

| 检查 | 依据 |
|------|------|
| 实体声明了但表不存在 | 直接对应 `ORA-00942`；`all_tables` 里有实测样本 |
| 组件表 vs 工程模块对不上 | `md_component` **在本机日志的 SQL 里出现过**，确认存在 |
| 字段名实体/表两处不一致 | 社区高频（"元数据名称和字段名称不一致导致报错"） |
| 必实现接口是否挂上（`IBillInterface` / `pfbizitf` / `general_interface`） | 开发步骤链的硬要求 |

🔴 **待确认**：实体/属性表的确切表名（`md_class` / `md_property`？）本机没有连库环境，
**没验证过就不写进方案当事实**。A 批第一步就是连库 `select * from all_tables where table_name like 'MD\_%'`
把清单落下来，再定检查项。

### 5.3 输出

问题列表，每条三列：**问题 / 依据（文件:行 或 表.字段）/ 为什么这条要命**。
不输出"评分"，不做"体检通过"的假绿灯——查不出来的就说"未覆盖"。

### 5.4 批次

| 批 | 内容 | 估 |

## 6. P1-6　接口调试

### 6.1 为什么现在做成本最低

`reqwest 0.13` **已经在 `Cargo.toml` 里**（`resource_pack.rs` 的资源包下载在用），不新增依赖。
而"跟 WMS/MES/OA 对接联调"在招聘 JD 里是常规项，现在只能开 Postman 再手抄 NC 的登录态。

### 6.2 形态（刻意做小）

```
[POST ▾]  http://10.200.22.144/nccloud/api/xxx        [发送]
环境: [测试 ▾]   头: Cookie / Content-Type …
Body: { … }
──────────────────────────────────────────
200  127 ms
{ "code": "0", … }
```

- 多环境变量（`{{host}}` 这种占位替换），因为 NC 现场永远是开发/测试/生产三套
- 历史记录（最近 20 条，落本地）
- 响应原文 + 耗时 + 状态码 + 大小

**不做**：OpenAPI 文档同步（接口资产在平台上，抓不全）、鉴权流程编排、压测、断言脚本。
目标是"不用切窗口"，不是"替代 Postman"。

### 6.3 批次

| 批 | 内容 | 估 |
|----|------|-----|
| A | 请求发送（方法/URL/头/体）+ 响应展示 | 1.5 d |
| B | 环境变量 + 历史 | 1 d |
