# Java 完整类名搜索修复与验收

日期：2026-11-14。

## 问题与本机证据

用户输入以下完整类名时搜不到，缩成短类名后又出现多个包下的同名类：

```text
nc.ui.pp.m28.editor.card.afteredit.CardBodyAfterEditEventHandler
```

已确认对应源码在[当前工程的 purp 模块](C:/work/aier/newar/purp/src/client/nc/ui/pp/m28/editor/card/afteredit/CardBodyAfterEditEventHandler.java)中存在。该文件的 package 是 `nc.ui.pp.m28.editor.card.afteredit`，本机既有类型缓存也已经包含它；当前工程共有八个同名 Java 文件。

原因是查询规则：

- 工作区类型索引和依赖 JAR 的模糊类型查询只拿短类名进行匹配，完整包名无法命中。
- 文件搜索把点当普通字符，没有把完整类名转换为包目录路径。
- 索引未就绪时的类型兜底只保留文件名命中，路径命中会被过滤掉。
- 语言服务兜底在包名过滤之前截断候选，其他包中的同名类可能占满结果。

## 修复后的行为

| 查询入口 | 行为 |
| --- | --- |
| 顶部「文件」 | 完整类名按 Java 包路径后缀精准匹配，保留模块目录和真实打开路径；可附加 `.java`。普通点分文件名继续优先按文件名匹配。 |
| 顶部「类型」的本地索引 | 带包名的查询按完整名称精确或前缀匹配；短类名、驼峰缩写继续使用原排序。包名不匹配时不会退回同名类。 |
| 依赖 JAR 的类型查询 | 共用完整名称匹配规则，结果继续指向对应 JAR，并沿用已有反编译打开方式。 |
| 索引未就绪 | 当前工程源码按文件清单中的包路径精准匹配，不必等类型索引完成。 |
| 语言服务兜底 | 用短类名请求候选，再按完整包名筛选，筛选后才限制显示数量。 |

完整名称中的包路径也会显示在结果中。类型结果的高亮只应用于短类名，避免把完整包名对应的偏移画到标题之外。

工程全文搜索仍按输入文本查找内容。Java 源码里的 package 和类声明通常在不同行；定位一个完整类名应使用「文件」或「类型」。

## JAR 搜索的当前范围

| 内容 | 当前支持 |
| --- | --- |
| 已索引依赖 JAR 中的类型 | 可以按类名查询、按完整类名定位，并打开查看；类型目录保留原有的可见性与去重规则。 |
| 编译 class 的符号与常量池文本 | 工程搜索包含包名、类名、方法名、字段、常量与字符串文本的结果。 |
| 源码包中的 Java 注释 | 存在可用源码包时，可在工程搜索的源码注释结果中查看。 |
| JAR 内 XML、properties 等资源文件 | 当前没有接入包内文件名或全文搜索。 |

本轮修复的是类名精准查询，没有增加 JAR 资源文件搜索。
