# SQL 动作可发现性实施与验收

日期：2026-11-17。「生成主子表联查」「展开 `*`」「生成 INSERT 模板」「转为 IN 条件」「检查重复」「汇总」这六个动作此前只有两条路：右键菜单（用户不会在 SQL 编辑器里点右键找功能）和 `Ctrl+.`（没人知道）。本轮把它们搬进**敲字时的补全列表**和 `Ctrl+.` 菜单，实现与判定一行没重写。

## 使用方式

| 位置 | 补全列表里多出什么 | 选中后 |
| --- | --- | --- |
| 新语句开头打表名（`po_order`） | 表名候选中混入「补全为整条主子表联查」「生成 INSERT 模板」 | 前者弹菜单选子表，后者直接插模板 |
| `SELECT * FROM po_order` 光标在表名上 | 「追加子表 LEFT JOIN」 | 弹菜单选子表，在表名后追加 |
| 光标压在 `*` 或 `m.*` 上 | 「展开 \* 为字段列表」**置顶**，并且已预选 | `Enter` 直接展开（`Ctrl+Z` 可撤销） |
| 语句任意位置打 `exp` | 「exp 展开 \* 为字段列表」置顶 | 直接展开，并把 `exp` 三个字符一起吃掉 |
| 语句任意位置打 `insert`（裸表名起手） | 「insert 生成 INSERT 模板」置顶 | 直接插入模板 |
| 选中一列值后按 `Ctrl+.` | 「转为 IN 条件」 | 转成 `IN (...)`，值按字段物理类型加引号 |
| 选中 SELECT 投影里的字段后按 `Ctrl+.` | 「按所选字段检查重复（全表）」「按所选明细字段汇总（全表）」 | 追加一条独立全表查询，原 WHERE 不带入 |

「纠错类」（把条件移入 ON、明确 INNER JOIN）**故意不进补全列表**：它们已经有 marker 与行尾透镜作锚点，在用户没犯错的地方推销只会稀释信号。「固定表 / 忘记表 / 快捷键速查」是设置不是改写，留在右键。

## 四条 Monaco 硬约束

这几条决定了方案形状，不是风格选择：

1. **`CompletionItem.label` 只吃纯文本**（`{ label, detail, description }`）。做不了彩色徽章，也做不了分组标题。动作项只能靠 `CompletionItemKind.Event`（闪电图标）+ 标题区分。
2. **`filterText` 只有一个**。既没法同时「跟着上下文表名走」又「被 ASCII 关键词搜到」，只能二选一：命中关键词时 `filterText = exp`，否则 `filterText = 已输入的前缀`。
3. **`filterText` 与 `label` 不等长会涂错字**。Monaco 拿 `filterText` 去套 `label` 算高亮区间，中文标题只有四五个字时，匹配区间会盖在开头几个字上。所以关键词命中时 **label 必须以关键词打头**（`exp 展开 * 为字段列表`），视觉上正好是「把这个词替换成这个动作」。
4. **`CodeAction.edit` 必须同步返回**。转 IN / 查重 / 汇总都要异步读库之后才 `executeEdits`，因此只能返回**命令型** action（`{ title, command }`），由 `ncforge.sql.runAction` 转调同一条 editor action。

## 排序与预选

- 动作项 `preselect` **恒 false**：`suggestSelection: "first"` 下把动作放首位等于把 `Enter` 绑给「展开 31 个字段」。
- 只有**光标真压在 `*` 上**才置顶（`sortText` 前缀 `\u0000`）。这是唯一一个「按 `Ctrl+空格` 第一眼就该是它」的位置；其余位置置顶只会打乱字段补全。误触是一次 `Ctrl+Z` 就能撤销的编辑，这个取舍是明示的。
- 语句里另有 `*` 不等于「现在就想展开它」：只有光标压在 `*` 上、或用户主动打了 `exp`，这条动作才出现。否则每一条表名补全都会多一行无关动作。
- 「生成 INSERT 模板」只在**裸表名起手**进列表。`SELECT * FROM ___` 那里列表已经塞满表名与 JOIN 片段，再挂一条就是噪音——那种位置右键菜单里一直有。

## 关键词只给两个词

`exp` / `expand` 与 `insert`。**联查类刻意不给 `join`**：它本身就是 SQL 关键字，给了会抢掉 `JOIN` 的补全位，按 `Enter` 还会打开一个菜单而不是插入关键字。同理 `in` 不算 `insert` 的前缀命中（两字符以下一律不认），否则 `IN` 操作符会被挤下首位。
