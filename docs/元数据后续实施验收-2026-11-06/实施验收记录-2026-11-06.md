## 4. 最终性能测量

生产 `MetaTab`、`WorkbenchFrame` 和应用 CSS 构建后，使用无头 Edge、禁用 GPU、内存 IPC 测量。完整数据及方法见 [生产联调与性能](生产联调与性能-2026-11-06.json)。

| 场景 | 最终测量 |
| --- | --- |
| 500 实体、100 关系、主实体 1000 字段、1500 资源 | 实际挂载 15 个节点、16 个字段行、13 个资源行 |
| 大模型字段键盘反馈，60 次 | 中位 25.8 ms，P95 37.7 ms |
| 50 实体、100 关系，拖动 45 帧 | 中位帧间隔 15.7 ms，P95 帧间隔 30.5 ms |
| 同次拖动的 renderer 主线程任务区间，288 个任务 | 中位 9.698 ms，P95 14.967 ms |
| 两个已热身文档切换，30 次 | 中位 43.1 ms，P95 58.7 ms；逐次核对目标正文及 30 次 SHA 刷新路径 |
| 打开/关闭 8 次后强制 GC | 关闭后保留 JS 堆增量 180264 bytes，约 0.17 MiB |

确认拖动实际改变节点位置：`translate(28 28)` → `translate(118 73)`。CDP [主线程轨迹](拖动主线程轨迹-2026-11-06.json.gz)按 performance marks 的 renderer pid/tid 采样，标记位于同一线程，并要求至少 80% 的采样帧包含实际任务。

主线程任务区间是 `RunTask` 时长并集，包含脚本、布局、绘制与驱动开销，排除浏览器 idle；不是原生或 GPU 帧耗时。字段反馈包含事件与下一帧调度。热切等待独特目标正文出现，内存 IPC 数据未包含原生文件 I/O 与解析。

JS 堆回收测量不等于原生 WebView 常驻内存。方案中的原生增量 ≤40 MB、原生 I/O 性能及真实 Windows DPI 仍需实机验收。

## 6. 构建与验收资源

重任务串行，启动前检查其他编译任务与可用内存。未知任务和 Rust 起跑要求至少 3 GiB；已有相同管线采样的轻量前端门禁依据实测消耗保留至少 1 GiB 余量。全量隔离前端构建显式限制扫描范围，采用 3 GiB 起跑门槛与 1536 MiB 的 Node 堆上限；此前同源全量构建成功采样消耗约 1.40 GiB。验收包装器每秒记录整机可用内存，若低于 1 GiB 则停止本轮自己的子进程树。

最终浏览器管线起跑可用约 6.00 GiB，最低采样约 4.39 GiB，结束约 4.86 GiB；总耗时 20.422 秒，退出 0。见 [浏览器资源门禁](门禁-browser-isolated-2026-11-06.json)。这些是每秒采样值，不是连续峰值或冷编译上限。

隔离目录首次试跑曾因 HTML 真实路径越界和共享 Rust target junction 的扫描而失败并产生资源压力。已改为规范化缓存路径，浏览器验收仅显式扫描前端源。包体积 HEAD 初次试跑也曾触发低于 1 GiB 的内存保护，被停止；见 [初次包体积试跑](门禁-bundle-head-初次试跑-2026-11-06.json)。

包体积对照只复制前端构建输入，并在两份副本中一致关闭 Tailwind 自动扫描，显式指定 `src` 与 `index.html`，避免越界扫描共享依赖和缓存。JS/TS 输入保持原字节。浏览器失败证据保留在 [隔离目录试跑记录](门禁-browser-隔离目录试跑-2026-11-06.json)，失败记录均不作为验收通过依据；成功截图替代了旧失败截图。
