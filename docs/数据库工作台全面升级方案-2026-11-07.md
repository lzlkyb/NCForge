# 数据库工作台全面升级方案

建议采用“SQL 与结果居中、范围就地说明、比对独立展开”的工作台结构。保留 NCForge 的深青识别色、Windows 操作习惯和 NC 中文字段能力；重新组织连接、执行、结果、比对、输出之间的关系。

本轮交付是方案与静态设计稿，未修改应用代码。主工作流按用户确认的 **写 SQL → 查数据 → 比对 → 导出** 排序。页面美化和交互调整共同验收，功能完整性是前提。

## 当前页面为什么显得不精致

问题集中在层级与行为语义。截图已有合适的“对象—编辑器—结果”骨架，但同一层放进了太多不同性质的信息；一些关键状态被收起来，次要信息却持续占位。

| 优先级 | 已观察的具体问题 | 用户付出的成本 | 调整方向 |
| --- | --- | --- | --- |
| P1 | 宽屏 CSS 隐藏执行范围，主按钮仍只写“执行” | 光标语句、选中 SQL、整个脚本容易混淆 | 主按钮动态显示执行对象，旁边保留行范围与快捷键 |
| P1 | 独立/共享会话可见，自动/手动提交通常藏在详情里；连接只读的作用范围主要靠 tooltip | 需要反复确认当前事务模式，可能误以为只读只影响当前标签 | 会话状态组常驻；只读明确标为连接级 |
| P1 | “500+”“还有更多”“已取 500 行”分散；本地排序筛选的范围提示出现较晚 | 容易把部分数据当成查询全量 | 固定一处说明已加载数量与完整性，动作上说明范围 |
| P1 | 固定对照与比对在泛化菜单中；主界面没有持续显示基线身份 | 必须记住 A 是哪一份数据 | 比对升为直接入口，显示 A 的来源、时间、范围 |
| P1 | 比对以逐字段文本列表呈现，不能连续扫描同一记录的 A/B 值 | 多行、多字段核对困难 | 独立比对文档，按唯一键对齐、按字段成对展示 |
| P1 | 结果缺少执行时 schema 和编辑版本的完整快照 | 改 SQL 或 schema 后，旧结果与当前编辑上下文可能混淆 | 新增不可变执行上下文，明确“SQL 已修改，结果尚未更新” |
| P1 | 结果标签缺少完整选中/面板关联和键盘切换，表头菜单依赖鼠标 | 无法完整地用键盘完成数据工作流 | 复用主文档标签的键盘模型，补表头菜单入口 |
| P2 | 左侧连接区很宽，执行带发生换行；结果栏混合标签、统计和大量工具 | 视线往返，宽屏仍拥挤 | 稳定分区、可控折叠、明确断点，不依赖自由换行 |
| P2 | 表头、技术标识、中文说明、数据值的视觉重量接近 | 核心业务字段与记录不够突出 | 校准字重、文字颜色、列宽、横向边界和选中层次 |
| P2 | 旧游标不能续取时原因常在 tooltip；普通续取失败主要进入“输出” | 按钮恢复后，不清楚发生了什么 | 在原结果底部保留失败原因与可执行的下一步 |

这些是截图和当前源码支持的判断。没有把“已有停止、没有全量导出、没有错误恢复、没有键盘支持”等不准确结论当作问题。细节证据与独立评估见 [评估记录](D:/AItool/winapp/nc-workbench/docs/数据库工作台全面升级评估-2026-11-07.md)。

## 结构取舍与推荐

| 方向 | 改动 | 收益与代价 | 判断 |
| --- | --- | --- | --- |
| A：延续当前结构，只改视觉 | 统一字体、边距、颜色，继续折叠按钮 | 代价较小；执行范围、结果身份与比对流程仍没有解决 | 可作过渡，不能满足本次全面升级 |
| **B：任务优先的 SQL 工作台** | 对象侧栏收窄；执行带重组；结果状态归位；比对进入独立文档；输出范围前移 | 直接改善已确认主流程；需要补部分状态逻辑与比对呈现 | **推荐，设计稿按此展开** |
| C：所有能力常驻的多面板 IDE | 对象、编辑、结果、记录详情、比对和任务同时停靠 | 极宽屏可用；普通笔记本被分割，复杂度与布局维护成本显著增加 | 暂不作为默认结构 |

推荐 B 的关键取舍：常规查询页保留两块核心画布；需要读长值时才开检查器，需要比对时进入宽幅文档，需要输出时才集中填写输出选项。用户能连续工作，主画布不承担所有工具的常驻成本。

## 布局与空间效果

宽屏结构从左到右为“全局导航 / 连接与对象 / 工作文档”。工作文档从上到下如下。

| 层 | 建议结构 | 设计稿尺寸 |
| --- | --- | ---: |
| 文档标签 | SQL / 表页 / 比对文档；标签写任务名称，完整来源可查看 | 38 px |
| 执行带 | 左侧执行与范围，中部连接/schema/会话，右侧历史/片段/更多 | 48 px |
| SQL 编辑器 | 保留补全、参数、格式化、错误定位；可拖动和最大化 | 示例 276 px，可调整 |
| 分隔柄 | 可拖动、有键盘入口；还原上次比例 | 4 px 可见线，扩大命中区域 |
| 结果身份 | 数据/输出/计划标签，A 基线摘要，执行来源与时间 | 40 px |
| 结果操作 | 当前结果筛选、列布局、比对；选区复制、导出、详情菜单 | 36 px |
| 结果网格 | 固定表头、双层名称、连续数据行 | 表头 44 px，示例行高 30 px |
| 结果状态 | 已加载数量、完整性、续取、选区摘要 | 30 px |

默认对象侧栏建议 236 px，可拖动约 200–340 px；收起后由数据库导航与面板开关恢复。连接账号、完整 URL、连接默认提交设置等进入连接详情；**执行目标和环境不能因收纳而失去可见性**。

截图与设计稿的几何对照仅用于解释方向：

| 项目 | 用户截图的近似像素范围 | 设计稿 | 预期效果 |
| --- | --- | --- | --- |
| 对象侧栏 | 约 326 px | 236 px | 增加横向数据空间 |
| SQL 与结果画布宽度 | 约 1508 px | 1608 px | 同一示意画布增加约 100 px，约 6.6% |
| 编辑器上方执行/上下文带 | 约 100 px，内容发生换行 | 48 px | 示例释放约 52 px 纵向空间 |
| 数据行区域 | 约 350 px | 420 px | 为连续阅读与扩选留出更大范围 |
| 可见行 | 截图约 10–11 行 | 示例 14 行 | 展示密度改善方向，不作实际性能/空间验收结论 |

**截图的 Windows 缩放和逻辑视口未知；以上不是同设备实测，更不能把行数提升归因于布局一个因素。** 正式验收须使用同一窗口、同一缩放、同一字号、同一数据与面板状态；目标为“编辑器与数据行画布总可用面积至少增加 10%”，不能通过调小字体达标。

响应式规则以工作文档的 CSS 容器宽度判断：

- 宽度充足时执行带单行固定分组。
- 约 900–1180 px 时拆成明确的上下文行和操作行；历史、片段等进入辅助菜单。具体阈值由真实中文内容与缩放验收后确定。
- 更窄时提供收起对象区与专注结果；仍放不下则继续分组排布。环境、执行范围、停止操作和未提交状态不得仅留 tooltip。
- 记录/长值检查器宽约 320–380 px；主网格将不足约 720 px 时使用临时覆盖面板。关闭后返回原单元格和滚动位置。
- 返回 SQL 文档时恢复该文档的对象区宽度、分栏比例、光标和结果位置；执行完成不自动抢比例或折叠编辑器。

## 写 SQL 与执行

主按钮按真实执行意图变化：无选区为“执行当前语句”，有选区为“执行选中 SQL”。旁边显示行范围与语句数量；数量无法可靠判断时只显示范围，不猜测。Ctrl+Enter 与主按钮使用同一个执行意图。

“执行整个脚本”仍在执行分体菜单，保留 Alt+X；执行计划、回放文件继续按现有语义进入。范围显示不得另写一套 SQL 分割器，应复用编辑器实际交给执行器的语句列表。按钮状态与按下时的范围要一致，切换标签后不能复用过期范围。

连接/schema 与会话属性分清三件事：

| 属性 | 常驻文案示例 | 点击后 |
| --- | --- | --- |
| 执行目标 | `NC_TEST · 测试 · NCDEMO` | 选择连接或 schema，保留现有运行中限制 |
| 当前会话 | `独立会话 · 手动提交` | 当前会话详情与事务操作 |
| 连接策略 | `连接只读：开启/关闭/待验证` | 明确“此连接的全部会话”，沿用现有切换校验 |

没有待提交写入时，提交/回滚不再作为两个大禁用按钮占位；事务菜单仍可发现，禁用原因可读。有待提交写入、会话丢失或提交结果未知时，出现紧贴编辑器的事务条，写明所属会话、语句/影响行数及“提交 / 回滚 / 核对事务”等实际可用操作。危险/异常状态不会被折进“更多”。

执行过程中原位显示“停止”；发出取消后显示“等待数据库停止”，收到返回才结束。已有结果可继续阅读，但须标为上次结果。保留现有生产写入确认、脚本进度和错误定位，不为普通只读查询增加额外确认。

新增结果上下文需在执行开始时冻结连接身份、环境、schema、SQL 文本、范围/起始行、编辑版本和时间。展示阶段使用该快照，不从当前连接设置反向拼出过去的身份。改动相关语句后显示“SQL 已修改，结果尚未更新”；改动另一个不相关语句时避免误报。执行版本相同也不代表数据库内容永远新鲜，文案不能写成“数据最新”。

## 查数据与结果阅读

结果页持续回答三个问题：这是谁的结果，读到了多少，当前在操作哪一部分。

- 数量统一写“已加载 500 行 · 尚未取完”；只有游标确实结束才写“完整结果 · 500 行”。未知总量不显示伪总数，不为了一个数字默认发 COUNT。
- 过滤入口直接叫“筛选已加载数据”；无匹配时说明范围并可清除。表头排序显示“当前已加载数据排序”；数据库重排/重查是显式的独立动作，沿用已有重查入口与校验。
- 多结果标签使用可识别名称、语句序号与运行时间。能可靠识别单表时显示表名；复杂查询使用用户命名或语句序号，不根据猜测给错误表名。隐式结果集保留父语句与子结果关系。
- 逻辑读、物理读等诊断项归入结果详情；常驻耗时与执行时间。完整性与错误不会随诊断信息一起隐藏。
- 旧游标失效时保留已加载行，直接说明“游标已失效，无法继续读取”；提供定位原 SQL 与准备重新查询。不可安全重放的过程或写入语句不得一键隐式重放。
- 续取失败留在当前结果旁，区分可重试失败和需要重新执行的失效；不让用户必须去“输出”猜原因。
- 列宽、冻结、隐藏、排序和选区沿用已有能力。保存/恢复现有布局；不默认隐藏全部技术字段，不因为姓名更“好看”而擅自把原始外键替换成关联名称。
- 双层表头保留技术字段名与 NC 中文说明，主层约 13 px / 600，说明约 12 px / 400。业务数据比说明更有对比度；长值仍可看完整原值和复制，不把显示省略写入输出。
- `NULL`、空字符串、空白字符、数值 0 和字面量 `~` 保持可区分。`~` 不自动当作 NULL；NC 迁移转换只在对应流程中显式应用。
- Hover、选区、活动单元格、未保存修改使用不同层级：淡底表示范围，清晰边线表示活动格，修改使用额外标记。颜色之外保留文本/图标语义。

## 比对升级为完整工作流

保留现有跨标签/连接的单份内存对照，不引入数据库写入或自动修复。首批不做多基线管理器，也不默认落盘业务快照。

流程为：**在 A 固定对照 → 看到 A 摘要 → 切到 B → 比对 → 确认唯一键 → 阅读差异 → 导出差异**。

1. “比对”直接出现在结果工具条，分体菜单包含“固定为对照 / 更新对照 / 查看对照来源”。未固定时主动作引导固定，已有 A 时主动作进入与 A 的比对。
2. 主界面常驻 `对照 A · 来源 · 时间 · 已加载行数 · 部分/完整` 的简短摘要，完整 SQL 可展开。更新后各标签显示同一份真实基线状态。
3. 默认维持现有口径：比较两份**全部已加载数据，包含隐藏列**，不因为界面筛选而偷偷缩小范围。固定时和比对页均说明。若以后支持“固定当前视图”，必须另加显式范围选择与回归测试。
4. 比对使用独立文档页，返回查询恢复上下文。A/B 的来源、schema、时间、行数、完整性和唯一键在首屏可见。
5. 保留现有复合键、NULL 键、重复键、重复字段与字段不一致校验。不默认按行号对齐。首批手动选键；未来只有取得可靠主键元数据并验证唯一性后，才可推荐键。
6. 差异表固定键/业务编码，变化字段按 A/B 成对出现；颜色只落在变化单元格。新增、删除、修改带文字标识；缺失记录写“无此记录”，与数据库 NULL 区分。
7. 提供修改/新增/删除过滤、按键查找、只看变化字段与长值检查器。大量差异使用虚拟列表，完整性不再依赖“屏幕仅显示前 100 条”的文本列表。
8. 对照为跨库或不同时刻的数据，A/B 标签采用“对照值 / 当前值”；不暗示这些差异已经写回数据库。
9. 两边任一为部分结果时，持续提示“仅比较已加载数据，不能代表全表差异”，导出也保留这个说明。样本中的“新增/删除”不能被当成数据库真实增删的证据。
10. 导出全部差异保留现有能力，按钮显示差异数量；筛选后的导出若要提供，必须与“全部差异”分开命名，不能随筛选暗改原有导出范围。

独立比对文档、完整差异网格、持续基线订阅与冻结来源都是新增交互/状态工作；现有比较算法和校验可复用。

## 复制与导出

当前高级输出已经具备四类范围、格式、预览、列选择、原生保存、任务进度和停止。本次提升首屏判断效率，并统一外观。

| 入口 | 默认行为 | 必须看得见的范围 |
| --- | --- | --- |
| 网格 Ctrl+C | 复制当前选区；编辑框内仍复制文本 | 选区高亮与行列数 |
| 分体复制主按钮 | 有选区复制选区，无选区复制当前筛选视图 | `复制选区 6 × 3` 或 `复制当前结果`，结果完整性就近可见 |
| 复制下拉 | 选择常用格式，或进入高级复制 | 菜单顶部显示同一范围，换格式不扩范围 |
| 导出 | 打开现有共享窗口 | 选区 / 当前筛选 / 已加载全部 / 重新查询导出全部 |

输出窗口采用“左侧范围与格式，右侧预览，底部固定摘要与动作”。上方先显示输出范围，选中少量数据时不用从长表单末尾才能发现自己导出什么。相关选项随格式出现；高级编码、NULL、引用、SQL 映射与 NC 迁移规则保持可达。

重新查询属于不同来源：显式说明使用独立只读会话，不沿用网格的本地筛选、排序或未保存修改，也看不到主会话未提交数据。预览为当前已加载样本；不得为预览隐式跑全量查询。保留现有可重查限制、200 万行上限及部分结果处理。

打开输出窗口后冻结来源、范围、列与数据视图；后续切换标签或 schema 不改变已开始任务。完成摘要显示实际文件、行列数、大小与完整性；已停止、部分保存、保存失败与完整成功明确区分。已有后台运行、停止等待、再次导出和原子保存语义保持。

CSV/TSV/JSON/JSONL/Markdown/HTML/SQL/XLSX、IN/WHERE/UPDATE、NC INSERT 等已支持的能力以实际源码为准全部保留，不为简化首屏删掉格式。精度、前导零、公式文本和长字段继续使用已有规则；视觉层不承担修复源读取链路已经丢失的数据。

## 必须覆盖的状态

| 场景 | 应出现的反馈与下一步 |
| --- | --- |
| 首次进入 / 无连接 | 短说明 + 新建连接 / 从 NC 配置导入，主要画布不铺装饰卡片 |
| 连接中 / 失败 | 当前连接行和执行区保持一致；失败保留参数与明确重试入口 |
| SQL 空白 / 无当前语句 | 执行禁用并可读原因，历史/片段仍可用 |
| 查询执行中 | 显示实际阶段与耗时；保留旧结果但明确标为上次结果 |
| 停止请求中 | 等待数据库确认，不能瞬间显示“已停止” |
| 返回 0 行 | “查询完成，0 行”，保留字段、来源、耗时；区别于筛选后 0 行 |
| 返回部分行 | 已加载数量 + 未取完 + 续取；未知总量不用百分比 |
| 普通续取失败 | 在结果旁保留失败信息；只有游标仍可用才给继续读取 |
| 游标失效 / 内存上限 / 隐式结果集截断 | 三种原因分别说明；保留已加载数据；下一步遵守现有安全重查能力 |
| SQL 或执行 schema 改变 | 旧结果来源不改写，提示结果尚未更新或来自其他 schema |
| SQL 错误 | 原错误码 + 人能理解的解释 + 定位 SQL / 查看结构 / 会话与锁等相关动作 |
| 待提交 / 结果未知 | 当前会话专属事务条，保持确认、核对与恢复入口 |
| 未固定基线 / 键无效 | 就地指导固定 A 或选择复合键，不展示空白的差异表 |
| A/B 相同 | “本次比较范围内未发现差异”，仍说明两边完整性 |
| 输出进行中 / 停止 / 完成 / 部分 / 失败 | 沿用现有任务真实状态；不把部分文件当完整成功，不丢设置与重试上下文 |
| 关闭或切换工作文档 | 现有草稿、未保存编辑、待提交事务检查继续生效；返回恢复焦点 |
