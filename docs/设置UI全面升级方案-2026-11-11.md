# 设置 UI 全面升级方案

日期：2026-11-11。用户选择：整体升级，优先理顺分类和操作流程。

建议将设置中心整理成“找到设置 → 理解影响 → 修改 → 确认结果”的完整体验。优先解决分类、操作规则和反馈，再完成视觉与窗口适配。

本文是升级方案。依据当前工作区源码、设置相关测试以及 2026-11-04 的明暗主题验收截图形成；历史截图用于参考既有布局，不作为当前运行界面的验收证据。本文中的验收指标是升级目标，尚未执行新界面的运行验证。

## 1. 当前问题与优先级

| 优先级 | 当前实现中的问题 | 用户受到的影响 | 升级方向 |
| --- | --- | --- | --- |
| P0 | NC 目录的“浏览”选完即调用保存，手输路径则需再点击保存 | 同一个设置有两套提交规则，无法先核对选择 | 浏览、手输、扫描候选统一先进入草稿，再检测并确认使用 |
| P0 | 通用数值字段失焦自动保存，代码智能内存字段明确保存 | 不知道点击空白是在离开输入还是提交修改 | 输入类统一显式保存，Enter 提交、Esc 还原；失焦仅校验 |
| P0 | SQL 设置保存函数只设置失败提示，没有把失败传给通用字段 | 持久化失败时可能同时出现错误与“已保存” | 保存结果必须区分持久保存、仅会话生效、失败 |
| P0 | NC 环境里的设置行没有配置搜索项所需的稳定 id | 搜索目录、扫描等关键词可能只找到分类，不能定位具体操作 | 给设置与状态操作补齐定位标识、说明、当前值 |
| P1 | “NC 环境”和“开发环境”相邻，后者实际主要是代码智能 | 用户需要猜测 JDK、内存、安装目录分别在哪 | 分类按任务命名，明确区分 NC 安装与代码智能 |
| P1 | 任务页同时包含构建选项、缓存统计、热替换、内置任务和新建表单 | 页面过长，创建任务被大量其他设置挡住 | 拆出“编译与热替换”，任务页聚焦流程管理 |
| P1 | 当前任务用复选框点击顺序决定执行顺序，已有任务只有删除入口 | 步骤顺序不直观，修改流程需要删除重建 | 显式编号步骤，提供上下移动、移除和编辑 |
| P1 | 作用范围和生效时间分散在页面说明、详细提示和弹窗里 | 难以区分本机偏好、工作区任务、运行服务配置 | 在字段旁显示真实范围与生效条件 |
| P1 | 搜索结果点击后清空查询，搜索框又随共享侧栏一起隐藏 | 连续查找需要重新输入，窄窗口入口间接 | 保留返回结果入口，正文顶部提供直接搜索与分类入口 |
| P1 | NC 扫描无结果主要用短暂通知提示；部分禁用按钮缺少就地原因 | 容易认为操作没有响应或按钮坏了 | 原位显示空结果、失败原因、前置条件与下一步 |
| P2 | 外观预览占据首屏较多空间，SQL 方言有九个并列选项 | 高频修改需要滚动，选项多时难以扫描 | 高频控件提前，预览缩小；多选项使用下拉选择 |

主要依据：`SettingsTab.tsx`、`SettingsLayout.tsx`、`SettingsField.tsx`、`NcEnvSettings.tsx`、`TaskSettings.tsx`、`SqlFormatSettings.tsx` 和 `lib/sqlFormatPrefs.ts`。

当前已有中文、英文、拼音搜索、折叠组定位、草稿保留、单组件下载及更新进度。这些能力作为升级基础继续使用。2026-11-03 的记录比当前源码旧，例如当前已支持单组件重新下载，实施必须以当前能力为准。

## 2. 分类结构

保持工作台共享侧栏，分为三个组、十一个页面。新增的一个页面来自任务页拆分。

| 分组 | 新页面名称 | 内容与调整 |
| --- | --- | --- |
| 使用偏好 | 外观与启动 | 明暗、材质、密度、开机启动 |
| 使用偏好 | 编辑器 | 字体、缩进、阅读辅助、自动保存、保存时格式化、模板 |
| 使用偏好 | SQL 格式化 | 排版、方言、换行和即时示例；由原“开发”组移入 |
| 使用偏好 | 快捷键 | 方案、绑定、自定义、冲突和恢复 |
| NC 开发 | NC 安装与检测 | 当前目录、选择目录、候选扫描、环境检测 |
| NC 开发 | 代码智能 | 原“开发环境”；补全与跳转状态、自动启动、内存、工程重建 |
| NC 开发 | 编译与热替换 | 原任务页的自动编译、模块增量、外部修改、性能、缓存、热替换 |
| NC 开发 | 任务流程 | 内置与自定义流程、新建、编辑、步骤顺序 |
| 维护 | 软件与组件 | 软件更新与运行组件，页内采用两个清晰分区 |
| 维护 | 配置迁移 | 导出范围、导入预览、路径检查、导入结果 |
| 维护 | 关于与支持 | 当前版本、更新历史、仓库、反馈、许可 |

旧名称和原有深链接继续通过别名进入对应页面。任务页拆分时，旧编译与热替换字段定位应迁移到新页面，不能只兼容分类名称。

沿用 NCForge 工作台的明暗主题、系统字体、青灰色体系和现有控件语言。设置表单的背景保持稳定可读，重点用边界、对齐、文字层级和选中态表达。

- 顶部固定轻量页头：当前位置、页面说明、直接搜索和分类入口。分类侧栏隐藏时，入口仍然可见。
- 表单采用连续分区。简单设置按“标签与短说明 / 控件”对齐；目录、任务、导入使用纵向编辑区。
- 简单表单建议控制在约 800–960px；路径、快捷键与流程列表可使用更宽空间，避免整页一刀切。
- 文案常规字号以 13–14px 为目标，帮助文字约 12px；舒适密度控件高度约 36–40px。沿用设计 token 统一调节。
- 2–4 个简短互斥选项使用分段选择；九种 SQL 方言使用下拉；布尔值使用开关；有单位的数值显示输入框、单位与合法范围。
- 关键风险、禁用原因、生效时间常显。原理、技术背景和完整错误放到“详细说明”。
- 正文实际宽度不足时，将控件放到标签下方。长路径保留盘符与关键目录，提供完整路径查看和复制，避免仅依赖 RTL 截断。
- 当前页面和焦点状态明确区分；状态用文字加图标表达，颜色作为辅助。
- 外观和编辑器预览缩小到控件旁或下方。窄窗口移到下面，不占据整个首屏。

## 4. 全局交互规则

### 4.1 修改与保存

| 操作类型 | 统一行为 | 示例 |
| --- | --- | --- |
| 简单开关、单选、下拉 | 操作后提交，原位显示保存结果；写入未完成时防止同字段重复提交 | 主题、密度、SQL 方言、自动启动 |
| 文本、数字输入 | 先形成草稿；点击保存或 Enter 提交；失焦仅校验；Esc 还原 | 字体、字号、内存上限 |
| NC 安装目录 | 手输、浏览、候选选择都先形成草稿；检测通过后确认使用 | 切换 NC 安装 |
| 任务与导入等多字段操作 | 作为完整表单确认提交，失败保留内容 | 新建流程、编辑流程、配置导入 |

明确保存的表单仅在存在修改时显示操作区。普通设置不加全页“保存全部”，避免已即时生效的开关与待提交输入混在一起。

同一配置对象的异步保存要有顺序和正确的回写规则，避免快速连续修改时晚返回的旧值覆盖新值。优先沿用现有配置写入与订阅通路，不另外建立通用配置框架。

### 4.2 状态与错误

修改状态统一为：未修改、待保存、保存中、已保存、仅本次会话生效、保存失败。

“已保存”只代表成功持久化。持久化失败但当前会话已应用时，显示“本次会话已生效，未保存到本机”，并提供重试；不能以红色页级提示搭配绿色字段成功提示。

运行状态与修改状态分别展示。例如：内存配置已保存，但正在运行的代码智能仍使用旧上限；不能用“已保存”暗示运行进程已经切换。

错误就地说明三件事：发生了什么、当前值是否仍然有效、下一步能做什么。短暂通知用于补充操作结果，不承担唯一的失败信息。

### 4.3 范围与生效时间

按实际存储和执行语义标注，不能根据分类推断范围：

- 本机偏好：外观、编辑器、SQL 格式化；按现有迁移规则不包含在导出文件中。
- 工作区配置：自定义任务；显示工作区名称与可查看的完整路径。
- 应用配置：NC 目录、代码智能及构建相关字段；逐项核对现有配置范围。
- 生效条件：立即应用、下次打开工程、下次启动代码智能、下次启动 NC 服务等，以真实消费配置的时机为准。

已有延后生效项在字段旁常显条件。服务正在运行时，同时展示“配置目录”和“当前服务目录”。当前后端已保留运行服务的启动目录，前端说明应与该行为一致，不继续使用可能误导的旧端口警告。

### 4.4 查找、草稿与恢复

- 搜索返回设置名称、分类路径、真实当前值；具体设置优先于分类，名称精确匹配优先于说明文字匹配。
- 定位后展开目标分组，移交焦点；提供“返回搜索结果”，恢复查询和结果位置。
- 搜索与分类切换保留有效草稿；直接定位不能自动保存。
- 设置项使用稳定 id，旧标签变化不破坏深链接。搜索当前值应使用真实值，不从“保存 / 重试”等按钮文字推断。
- 任务草稿绑定创建时的工作区。切换工程后不得静默保存到新工程；采用按工作区保留草稿并明确提示的方式。
- 对存在默认值的个人偏好提供单项或分组恢复。恢复多个自定义项前列出影响范围；路径配置与运行操作不提供无条件“全部重置”。

## 5. 各页具体升级

### 外观与启动

第一屏直接显示主题、材质与密度，紧邻缩小的预览。启动放在独立分区。选项使用结果性说明，例如“舒适：文字和操作空间更大”。提供外观分组恢复默认，写入失败就地重试。

### 编辑器

常用排版默认展开，辅助选项和模板按需展开。字体提供常见等宽字体选择与自定义输入。代码预览随有效草稿变化，提示“预览，尚未保存”；保存后应用到编辑器。自动保存开启后展示延迟设置，关闭时就地说明依赖条件。

“保存时格式化”明确可能重排文件；“保存时自动编译”保持归属编译页，但在编辑器保存分区提供直达入口。相关设置不重复存储。

### SQL 格式化

增加固定示例的格式化前后预览，使用现有格式化库而非手绘结果。方言改为下拉；“跟随连接”时可显示当前连接实际方言，没有连接时明确说明状态。排版风格配简短效果描述。数值校验保持现有范围，修复持久化失败反馈并提供原位重试。

### 快捷键

方案选择下面显示命令、组合键、是否自定义、操作。录入状态在目标行明显展示。冲突信息留在该行并可定位到冲突命令；保留键在采集阶段直接拒绝。固定键与依赖代码智能的命令就地标注。恢复全部前显示受影响的自定义绑定数量。

### NC 安装与检测

主流程：选择目录 → 检测 → 核对结果 → 保存并使用。

1. 未配置时，直接展示可输入路径、浏览和扫描入口。
2. 浏览或选择候选只更新草稿。复用现有目录探测接口进行校验。
3. 检测结果分为目录识别、Java、模块、启动文件和端口；保留后端真实识别标准。
4. 路径错误紧邻输入框显示，指出应选择包含哪些目录的那一层。
5. 运行中切换时说明新配置的影响，提供“保存配置，稍后重启”和取消；重启通过现有服务入口明确执行。
6. 扫描结果用列表表达当前使用、可检测、检测失败；无结果时保留“手动指定目录”入口。
7. 环境检测与数据库管理的跳转分开：数据库连接是相关入口，不伪装成 NC 安装识别的一项通过条件。

### 代码智能

页面顶部展示已关闭、启动中、索引中、就绪或失败及下一步。失败时提供实际支持的修复入口，例如下载缺失组件、重试或查看详细原因。启用、自动启动和内存放在常用分区。

内存使用明确保存，常显“下次启动代码智能生效”。重新生成工程放入维护分区，动作名称和说明指出会停止并重新准备代码智能。完成后区分“工程已生成”与“索引已就绪”。

### 编译与热替换

拆成“自动编译”“性能”“热替换”“缓存维护”四个分区。

- 自动编译集中说明：保存单文件 → 空闲时模块增量；外部修改单独控制。
- 性能显示并行构建数量、常驻编译进程与真实统计；推荐理由清楚，数值范围按后端约束。
- 热替换同时显示配置开关与当前服务能力：本次启动是否带代理、代理是否就绪、待推送数量。
- 热替换总开关的“下次启动服务生效”常显；立即推送禁用时说明具体原因。
- 缓存占用、最近构建、重建索引和清理临时文件归入维护分区。重建按钮放在类索引项旁，避免混在最近构建一行。

### 任务流程

页面先显示当前工作区与“新建任务”，随后列出自定义任务，再展示可折叠的内置流程。

新建和编辑使用相同表单：名称、编号步骤、添加步骤、上下移动、移除、完整顺序预览。步骤名称沿用真实含义，例如“投送元数据到 NC”和“打开补丁打包”，不将其描述为泛化部署或自动完成打包。

已有流程增加编辑入口。保存任务与运行任务分开；运行继续连接现有任务菜单及执行通路。失败停止后续步骤的规则保留并常显。没有工程时显示“打开工程”入口和说明，避免整张表单无解释地禁用。

### 软件与组件

软件更新在上方展示运行版本、目标版本、当前阶段与一个对应的主动作。检查更新、下载、下载完成待安装、安装准备和错误阶段的反馈连续，下载详情弹框使用既有状态源。

运行组件按“用途 / 状态 / 版本与大小 / 操作”排列，缺失时说明影响哪个功能。沿用现有单组件下载、重新下载和剩余组件重试能力；“重新下载全部”移到次要维护操作。组件状态未知、读取失败和未安装必须区分，不能都显示缺失。

### 配置迁移

入口直接说明文件包含与不包含哪些配置，避免让“导出配置”被理解为整个工作台的完整备份。

导入使用选择文件、核对变更、确认导入、查看结果四个阶段。预览展示本机值与导入值、路径可编辑与检测、连接数量、缺少密码的后续处理。路径标题准确表达“请调整为本机路径”，不在未检测或未改写时声称已自动改好。导入失败保留预览及路径修改。

首轮沿用现有导入范围与规则。增加可选导入项或扩大备份范围需另行调整配置协议，不作为基础 UI 升级的隐含需求。

### 关于与支持

首屏集中运行版本、更新历史、复制版本信息和问题反馈。版本读取失败保留重试；随包记录与实际运行版本明确区分。完整许可和较长更新记录按需打开。

## 6. 实施顺序与交付物

| 阶段 | 实施内容 | 可验收交付物 |
| --- | --- | --- |
| 第一阶段：规则与结构 | 分类重组、任务页拆分、输入提交统一、保存结果修复、NC 搜索补齐、关键生效条件常显 | 能找准设置、不会误提交、不会误报保存的设置中心 |
| 第二阶段：关键流程 | NC 目录检测确认、代码智能状态、任务编辑与排序、快捷键冲突、迁移核对 | 可完整走通的配置、修复、创建与迁移流程 |
| 第三阶段：视觉与易用性 | 控件规范、预览、常用分区、更新与组件整理、窄窗口及缩放适配 | 明暗主题一致、长内容可读、键盘可操作的完整设置体验 |

第一阶段优先用外观与启动、NC 安装与检测、任务流程三种页面验证简单设置、路径流程和多字段编辑，再推广共同规则到所有页面。阶段验收后继续推进下一阶段。

建议修改位置：

- `components/tabs/SettingsTab.tsx`：分类、别名、拆分后的页面组织。
- `components/settings/SettingsLayout.tsx`：页头、直接分类入口、搜索往返和定位。
- `components/ui/SettingsRow.tsx`、`SettingsChoice.tsx` 与 `components/settings/SettingsField.tsx`：字段布局、状态、控件类型和提交规则。
- `lib/settingsSearch.ts`、`hooks/useSettingsIndex.ts`：索引完整性与结果排序。
- 各设置页：接入同一交互约定，保持真实数据源和现有业务能力。
- `lib/ncTasks.ts`：增加已有任务编辑能力，保持工作区隔离和执行语义。
- `settings-center.css` 及设置专项样式：对齐、密度、窄内容布局和状态表现。

实现优先通过现有组件与配置接口完成。仅在现有接口不足以支持明确交互时补充小范围能力，并配套回归测试。

## 7. 验收场景

### 交互与数据正确性

1. 搜索“NC 目录”“内存”“自动编译”“热替换”能定位到具体项；返回结果保留查询，旧入口仍可用。
2. 浏览、手输和扫描选择目录在确认前不修改实际配置；检测错误可就地修改和重试。
3. 输入空值、越界值、中文输入法组合状态时不提交；Enter 保存、Esc 还原、失焦校验行为一致。
4. 模拟本机存储失败和 IPC 失败：没有虚假的“已保存”，草稿可重试；会话生效状态准确。
5. 连续快速修改两项配置，响应乱序或某项失败时，最终界面与实际配置一致。
6. 已保存但延后生效的内存与热替换配置，清楚显示当前进程状态和生效条件。
7. 新建、编辑、排序、取消、删除任务都按界面顺序保存；切换工作区不串任务或草稿。
8. 快捷键冲突和保留键被拒绝，目标行持续显示原因，取消录入不修改旧绑定。
9. 更新与组件覆盖未知、加载、可用、下载、校验、待安装、失败与重试；主动作与状态匹配。
10. 导入先预览再写入，失败保留路径修改；导出范围和密码处理与实际文件一致。

### 布局与可访问性

- 检查 1280×800 和 1024×768 窗口，并检查正文约 560px 的受限宽度。
- 在 100%、125%、150% Windows 缩放下检查长中文标签、长路径、按钮与弹框。
- 明暗主题及标准、舒适密度均可读；全程没有必要的横向滚动。
- Tab 能到达关键操作；单选支持方向键；Esc 的行为与当前编辑或抽屉状态一致；焦点不留在隐藏区域。
- 禁用原因和错误不只靠悬浮或颜色表达；减少动态效果模式仍能看清定位反馈。
- 常用设置直接出现在首屏，任务新建入口不需要滚过编译和缓存设置。

### 测试与验证方式

为保存失败、明确提交、搜索定位、快速修改、工作区草稿隔离和任务编辑新增或调整语义回归测试。用隔离 IPC 的浏览器验收确认布局与关键操作，再在正式桌面窗口检查缩放、目录选择和焦点行为。真实配置操作使用专用验收目录及配置，不把模拟结果当成真实业务通过。

遵守项目资源规则：重任务串行，启动前检查可用内存，复用现有门禁及验收脚本。以测试、操作记录和截图交付结果。

## 8. 成功标准

升级完成后，用户应该能直接回答：设置在哪里、它影响什么、何时生效、是否真的保存、失败后下一步怎么做。

三条代表性验收路线为：找到并修改代码智能内存；检测并切换 NC 安装目录；创建并调整“编译全部模块 → 投送元数据到 NC → 重启 NC 服务”任务。每条路线都必须在正常、取消、错误和重试状态下完整成立。
