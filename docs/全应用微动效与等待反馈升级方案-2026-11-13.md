# NCForge 全应用微动效与等待反馈升级方案

日期：2026-11-13  
状态：公共体系与业务接入已实施，两项收尾均已完成：全仓检查、最终桌面构建与包体复验；真实桌面业务及 10 分钟连续运行验收。标准动效切页 P95 55.6ms，24 轮连续操作无页面异常，隐藏动画归零。  
依据：当前工作区源码、既有动效预览与测试，以及下列公开设计指南。下文保留原始方案目标；最终实现、实测结果与全仓门禁限制见 [实施验收](D:/AItool/winapp/nc-workbench/docs/全应用微动效与等待反馈实施验收-2026-11-13.md)。

## 1. 推荐方向

把全软件的交互统一成清楚、连贯的 **操作反馈 → 等待说明 → 真实结果 → 下一步**。

整体采用适合开发工作台的克制动效：按钮触感明确，内容切换短促，浮层有轻微空间感，长任务有可追踪的进度。重点照顾日常反复使用的编辑、查询、生成、编译和部署操作。

现有 CSS、原生 View Transition、WAAPI 与组件能力足以作为基础。本轮优先统一使用规则和业务接入，预计无需新增动画依赖；实施时再核对实际包体增量。

| 推进选择 | 收益 | 工作范围与取舍 |
| --- | --- | --- |
| A：先统一公共控件 | 较快改善按钮、弹层和切页的一致性 | 长任务与各业务页的等待差异留到后续处理 |
| **B：全应用统一反馈，分四步落地（推荐）** | 同时改善操作手感、等待可理解性和完成后的衔接 | 覆盖面较大，需要按模块接入并验证取消、失败等状态 |

用户要求全面升级，建议按 B 推进，每一步都交付可使用、可验收的结果。

## 2. 研究了哪些做法

调研方式是阅读公开指南并与本仓实现对照。以下为可借鉴原则，不代表已在外部产品中逐项进行实机体验。

| 参考 | 公开指南的要点 | 在 NCForge 中的应用 |
| --- | --- | --- |
| [Fluent 2：Motion](https://fluent2.microsoft.design/motion) | 动效帮助理解状态和空间关系；保持快速、一致；关注用户正在操作的区域 | 统一按钮、菜单、弹层与内容区的节奏，保留 Windows 桌面工具的轻快感 |
| [Carbon：Motion](https://carbondesignsystem.com/guidelines/motion/overview/) | 高频生产力操作使用简短、克制的动效；更强的表达留给少数重要时刻 | 查询、编辑、切页采用短动效；任务完成用局部确认。借鉴语义分类，沿用本项目既有时长 |
| [VS Code：Notifications](https://code.visualstudio.com/api/ux-guidelines/notifications) | 优先在相关视图显示进度；需要时提供日志、取消；减少重复全局通知 | 查询留在查询区、生成留在产物区、编译留在任务区；用户离开页面后再考虑全局完成提示 |
| [Windows：Progress controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/progress-controls) | 已知总量使用真实确定进度，未知总量使用不定进度；可继续操作时优先非模态反馈 | 下载显示真实字节进度，生成显示真实文件计数；列表加载统一在区域层表达，避免每行转圈 |
| [NN/g：Response time limits](https://www.nngroup.com/articles/response-times-3-important-limits/) | 约 0.1、1、10 秒是理解响应感知的经典参考；长等待需要持续可理解的反馈 | 点击立即回应，较长等待说明阶段，长任务提供详情与后续操作 |

下文“约 180ms 后显示忙碌视觉”是本项目建议初值，需要通过实际任务分布和预览验证；不是上述文章规定的统一阈值。

## 3. 现有基础与具体缺口

| 当前已有能力 | 本轮处理 |
| --- | --- |
| 统一时长：反馈 100ms、常规 160ms、入场 180ms、退出 140ms；CSS 另有按下 70ms、切页 170ms | 继续使用，按动作语义收敛模块中的硬编码值 |
| 页面切换支持原生 View Transition、快速切换中断、旧引擎回退、减少动效和隐藏窗口降级 | 继续沿用，补齐各页面首次加载和失败时的衔接 |
| 内容区切换，顶栏与侧栏保持响应；已访问页面保留 DOM、草稿和滚动 | 保持这一结构，编辑器和终端的实例保留机制纳入验收 |
| 公共 Button 已有加载态、宽度保持和 aria-busy | 增加统一的等待披露规则，避免短任务 spinner 闪现 |
| 弹层可反向打开，Collapse 已有延迟挂载和关闭后的交互隔离；Toast、SavedHint 已有反馈能力 | 统一调用和完成/失败衔接，复用已有实现 |
| 全局减少动效、隐藏窗口暂停 CSS 动效；数字动画也已有可见性守卫 | 核对 CSS、WAAPI、AutoAnimate 的覆盖一致性，补齐缺口 |
| 服务流程已有真实阶段、耗时和取消能力 | 作为其他长任务的参考，复用各模块已有状态来源 |
| 工作区已有结构化骨架，当前 Skeleton 是透明度呼吸效果 | 扩展到仍使用纯文本等待的局部区域，保持占位尺寸稳定 |

优先解决的差异：

1. 公共 Button 与数据库、服务、工作区专用按钮并存，反馈节奏和异步状态表达各不相同。
2. 短任务何时展示等待、长任务如何说明进度、结束后如何显示结果，缺少跨模块的一致规则。
3. 元数据工具的部分首次加载仍是纯文字，内容进入时的结构连续性可以改善。
4. 多个骨架块和外层区域均可能声明状态角色，存在重复读屏播报风险；需按区域核对，尚未实测确认。
5. AutoAnimate 的公共封装目前关注减少动效，尚未统一接入窗口和页面活动策略；需要审计实际使用点。
6. 少数未读光圈等持续动画可以改为有限提示，随后用静态标记保留状态。

源码索引见文末。以上是本轮范围，不涉及重做已经完成的元数据编辑和 BMF 生成工作台。

## 4. 统一动效规则

### 4.1 时长与幅度

| 动作 | 建议规则 | 用户感受 |
| --- | --- | --- |
| 按下按钮 | 沿用 70ms、最多 1px 按下位移；键盘操作同样有明确状态 | 一按就有回应 |
| 悬停、图标和边框变化 | 沿用 100ms；焦点标记保持稳定可见 | 可操作区域清楚，焦点容易追踪 |
| 开关、选中态、折叠箭头 | 沿用常规 160ms；实际状态提交由业务结果决定 | 状态变化连贯 |
| 页面与标签切换 | 沿用 170ms 内容淡入，导航选中立即更新 | 连续快速切换仍跟手 |
| 菜单、弹窗 | 沿用进入 180ms、退出 140ms；轻微位移与现有 0.985→1 缩放 | 看得出打开与关闭的关系 |
| 抽屉与小型展开区 | 按常规/进入/退出节奏；抽屉建议仅 8–12px 方向提示 | 内容出现位置明确，长距离移动少 |
| 完成提示 | 就地对勾和短文本淡入；留读时间与动画时长分开管理 | 能确认刚才的操作结果 |
| 正在处理 | 延迟披露局部 spinner 或区域进度；骨架沿用轻微透明度变化 | 等待状态稳定，不持续争夺注意力 |

高频场景以透明度和轻微位移为主。表格、代码编辑器、终端和真实输入内容保持位置稳定。展开所必需的布局变化限定在局部小容器，大列表继续使用现有虚拟化和固定行高策略。

新请求和真实结果都立即处理。动画结束回调只负责视觉清理，不能成为发请求、保存成功、关闭确认或允许下一次操作的前提。

### 4.2 等待分级

| 耗时/时机 | 呈现方式 | 行为约束 |
| --- | --- | --- |
| 点击当下 | 按下/选中反馈；立即建立业务忙碌状态与防重复提交保护 | 可取消的任务从启动起提供取消入口 |
| 约 180ms 内完成 | 直接显示结果，通常不出现 spinner | 不人为保留“加载中”凑时长 |
| 约 180ms 后仍未完成 | 按钮内 spinner 或当前区域加载状态 | 保持原宽度和区域尺寸，减少布局跳动 |
| 超过约 1 秒 | 显示实际操作或阶段，例如“正在读取表结构”；可显示耗时 | 后端无细分阶段时保留真实的总体操作名称 |
| 超过约 10 秒 | 加强详情、日志和当前处理对象的可见性，说明还能做什么 | 不自动判为失败；有异常依据时才提示连接问题、重试等 |
| 完成、失败、取消或部分完成 | 立即切换到对应结果，保留必要的摘要和操作入口 | 不让前一个动画遮住真实结果 |

已知总量：真实已处理数/总量，下载用真实字节进度。未知总量：不定进度＋真实阶段、计数或耗时。阶段序号用于说明流程，不等同于耗时百分比。只有具备可靠数据来源时才给预计剩余时间。

### 4.3 首次读取与刷新采用不同表达

- **首次读取**：立即保留区域结构，超过等待阈值后显示与最终布局接近的骨架；同一区域只声明一个可访问状态。
- **刷新已有内容**：保留原内容和滚动位置，在区域工具栏标注“正在更新”；旧结果明确标识，避免被当成新请求结果。
- **切换文件或业务对象**：标题、内容和加载状态保持同一对象归属，避免把旧对象的内容显示在新标题下面。
- **空结果或读取失败**：移除骨架，直接给出对应说明和可用操作。

## 5. 全应用场景清单

| 场景 | 具体升级效果 | 等待与结果处理 |
| --- | --- | --- |
| 主导航、页面、标签页 | 即时选中＋内容区短淡入；快速连切只展示最后选择 | 首次读取局部占位；保留已访问页草稿、滚动和编辑器实例 |
| 工具栏、文字按钮、图标按钮 | 统一悬停、按下、禁用、键盘焦点节奏；危险操作保留明确文案 | 忙碌立即防重，spinner 延迟出现；完成反馈优先留在原位置 |
| 表单、设置、开关 | 焦点边框短过渡，展开选项有连续性；错误就近显示 | 需要远端保存时区分“正在保存”和“已保存”；失败保留输入与重试入口 |
| 菜单、弹窗、抽屉 | 轻微方向感，进入和退出节奏一致，支持中途反向 | 关闭时立即停止内部交互；焦点按现有可访问行为归还 |
| 搜索、筛选、命令入口 | 输入与选择立即响应，结果区域稳定 | 保留输入；更新时说明旧结果状态；旧请求晚到不得覆盖新查询 |
| 文件树、表格、结果列表 | 展开箭头旋转，操作影响的行短暂高亮，选中与滚动位置稳定 | 在集合或分组处统一显示读取状态；大批数据按现有虚拟化呈现 |
| 代码编辑、文件打开、保存 | 标签状态与编辑区联动，保存后就地确认 | 文件加载与保存错误清楚归属；代码正文保持稳定 |
| 元数据图形与属性表 | 选中实体时图形与属性行短暂联动强调 | 保存与校验各有状态；自动聚焦只在用户明确触发定位时移动视图 |
| 当前 BMF 整套生成 | 配置、检查、预览、写入各阶段清楚衔接；产物行显示真实状态 | 显示实际处理文件与计数；完成区区分成功、跳过、失败和部分完成 |
| 数据库连接、SQL 查询、数据回写 | 连接测试原位反馈，查询工具栏进度稳定，受影响单元格/行有限高亮 | 显示真实耗时、可用取消及结果归属；回写失败保留待处理内容 |
| 编译、部署、服务启停 | 复用已有阶段流程，当前阶段明确，已完成阶段保留确认 | 日志按真实事件更新；取消依后端确认，完成后给出服务状态或失败步骤 |
| 版本控制、导入导出 | 操作所在区域显示状态；新增或变化文件短暂强调 | 有总量显示实际进度；涉及部分成功时保留逐项结果 |
| 更新、主题与外观 | 沿用现有主题过渡与快速切换保护，更新阶段前后连贯 | 下载用实际进度；检查、下载、验证等只显示后端真实可提供的状态 |
| Toast、复制与保存提示、未读提示 | 就地反馈优先；需全局提示时避免重复；未读提示有限强调后静止 | 失败保留原因与操作入口；关键结果在任务区域可重新查看 |

这张表是接入范围。具体操作是否可取消、是否具备阶段事件，以当前业务能力为准；缺失能力在接入时单独列出，不由动画模拟。

## 6. 长任务全过程

### 6.1 一套显示规则，保留各模块真实语义

按实际能力呈现：待开始、运行中、取消请求中、已完成、已取消、失败、部分完成。不是每个任务都必须拥有全部状态。

- **运行中**：当前对象、阶段、实际计数或耗时；任务允许时可继续使用其他页面。
- **取消请求中**：显示“正在取消”，等待后端确认；不能把点击取消直接画成“已取消”。
- **已完成**：给出结果摘要和最相关的后续入口，例如查看文件、打开结果、查看日志。
- **部分完成**：说明已完成和未完成部分；取消不等于已写入结果自动回滚。
- **失败**：原区域保留原因、失败对象和适用的重试入口。重试前按现有业务规则检查，避免重复写入等操作。

以下仅为文案示例，阶段和数量由真实任务提供：

> 正在生成代码 · 当前 XxxVO.java · 已处理 8 / 12 个文件 · 2.4 秒　[取消]  
> 已生成 10 个 · 保留 1 个 · 失败 1 个　[查看失败项] [打开目录]

### 6.2 结果必须与发起操作绑定

每次操作沿用现有请求标识或补充必要的操作身份，绑定文件、连接或当前任务上下文。快速重试、切对象、取消与完成同时发生时，以实际任务结果为准；旧提示不能覆盖新操作。

高频进度事件合并到有限刷新频率，终态立即刷新。耗时文本优先沿用现有“可见且运行时每秒一次”的策略。页面隐藏时停止视觉工作，必要的后台业务任务继续执行；返回页面同步最新真实状态。

## 7. 轻量实现方式

### 7.1 延续已有结构

1. **动效语义层**：继续以 motion.ts 和 CSS token 为共同依据，核对公共与专用控件的映射。
2. **活动策略层**：让 CSS、WAAPI、现有 AutoAnimate 封装一致响应减少动效、窗口隐藏和页面非活动状态；打断后落到正确状态。
3. **等待呈现层**：只抽取重复出现的等待披露、按钮占位和阶段摘要能力；消费各模块现有任务状态。
4. **页面接入层**：逐模块替换反馈差异，保留原来的业务请求、防重、取消和错误处理。

这次无需先建立新的全局任务调度器。若某个长任务没有可用进度事件，先提供真实的不定进度和操作名称，再评估是否确有必要补充后端事件。

### 7.2 性能规则

- 动效不得增加业务请求延迟，也不能靠推迟结果显示制造平滑感。
- 优先透明度和 transform；大型内容保持稳定，少做布局变化和全屏截图过渡。
- 阴影、模糊和材质按现有主题呈现，避免持续动画；动画层按需建立并及时释放，不全局常驻 will-change。
- 虚拟表格、日志和大树不逐行交错入场，不把整个集合包进自动布局动画。
- 行数、毫秒、文件数等业务数字直接显示真实值，沿用必要的格式化，不增加数字滚动等待。
- 不新增常驻帧循环或定时轮询；隐藏页面的视觉工作应退出或暂停。
- 包体按当前项目门禁与预算核对，沿用已有 5% 预算余量规则，不为动效随意上调门槛。

### 7.3 减少动效与可访问性

- 默认跟随系统“减少动态效果”；建议在外观设置增加简洁的“跟随系统 / 减少动效”选项，复用现有设置持久化方式。
- 减少动效时直接呈现最终状态或极短淡变，保留颜色、文本、图标和真实进度信息。
- 加载区域统一 aria-busy 与状态播报；骨架和装饰 spinner 不重复播报，每秒计时不逐秒读出。
- 焦点可见，键盘可以完成对应操作；动画关闭和弹层反向不造成焦点丢失。
- 重要错误保留可阅读说明，不能仅靠颜色、闪烁或短暂 Toast 表达。

## 8. 四步实施与交付

| 阶段 | 交付内容 | 验收点 |
| --- | --- | --- |
| **1. 统一规范与可交互预览** | 延用现有真实组件动效预览，补充短等待、长等待、错误、取消、减少动效场景；设计稿按项目约定放在 design 目录 | 在一个预览中确认按钮、切页、弹层和进度的实际节奏；生产改动前确认效果 |
| **2. 高频控件与页面切换** | 统一公共和专用按钮、菜单、抽屉、标签与首次加载占位，补齐活动策略 | 快速点击和切页跟手；原有草稿、滚动、选择与焦点保留；无布局跳动 |
| **3. 长任务全过程接入** | 按 BMF 生成、数据库、编译部署、版本控制/导出、更新等模块接入等待和结果规则 | 成功、失败、可用取消、部分完成都有真实表达；同一操作不重复全局提示 |

## 9. 拟定验收标准

下列为方案验收目标。已验证项目和未覆盖范围见实施验收记录，不能将预览测试结果等同于安装版全应用性能结论。

| 维度 | 验收标准 |
| --- | --- |
| 即时响应 | 代表性高频操作，从输入事件到首个可见反馈的 P95 ≤100ms；动画不延后请求发送或结果呈现 |
| 主线程 | 动效路径不新增超过 50ms 的长任务；代表场景录制性能轨迹检查布局与绘制成本 |
| 短任务 | 用约 50、150、250ms 的受控任务核对披露边界：短任务无 spinner 闪现，较慢任务正常展示；按钮位置与宽度稳定 |
| 长任务 | 约 1 秒和 10 秒以上场景有可理解状态；未知总量不伪造百分比，支持取消的任务从开始提供入口 |
| 快速切换 | 连续快速切页、切标签、切主题、弹层反向打开，最终状态与最后操作一致，无残留遮罩 |
| 业务上下文 | 草稿、滚动、编辑器与终端实例按现有策略保留；旧请求不覆盖新对象和新操作 |
| 结果正确性 | 成功、失败、取消请求中、确认取消、部分完成、重试及其竞态均按模块能力覆盖 |
| 大数据 | 使用现有大型表格/树/日志/元数据样例，验证虚拟化仍有效，批量更新不触发成千上万条入场动画 |
| 可访问性 | 键盘完整操作、状态按区域播报；减少动效设置动态切换后生效，提示仍可理解 |
| 窗口与主题 | 覆盖现有主题/材质、窄窗口、低窗口高度及常用缩放；按钮、进度和取消入口可见可用 |
| 空闲与隐藏 | 无新增持续视觉循环；反复进入退出后，动画、监听器和计时器回到合理基线；不影响必要后台任务 |
| 包体与维护 | 记录依赖和产物增量，通过当前包体、组件体量及相关统一门禁；实测数据随验收文档交付 |
