# JAR 与扩展类搜索实施与验收

沿用顶部搜索浮层，把依赖包中的文本、包内文件名与散放 class 纳入搜索。库结果保留独立的只读打开管道，不进入工作区替换和编辑匹配范围。

## 搜索覆盖

| 对象 | 入口与行为 |
| --- | --- |
| NC 运行依赖 JAR | 文件模式按包内文件名查；类型模式查完整类名或短名；现有符号段继续查 class 常量池 |
| NC 源码包 `_src.jar` | 文件模式查 `.java` 文件名；搜索模式查 Java 完整文本，包括实现和注释 |
| JAR 内 XML、properties、JSON、SQL 等文本 | 文件名查找与全文搜索，保留大小写、整词、正则、文件掩码和行内高亮 |
| 工作区 JAR | 递归发现工程带的 JAR，跳过版本库、依赖缓存与构建目录 |
| 模块 hyext | public、client、META-INF 三个作用域下的 JAR，以及 classes、_classes、resources 等散文件目录 |
| NC 根级 hyext | 单独补充 JAR 与标准 classes/resources 目录 |
| 散放 class | 查完整类名、短名、包路径或驼峰首字母，点击反编译只读查看 |

例如 `nccloud.pubimpl.platform.translate.TranslatorRowService` 可查到本机
`D:/ncc/1909home/modules/platform/META-INF/hyext/classes/nccloud/pubimpl/platform/translate/TranslatorRowService.class`。

包内 Java、XML、properties 等结果显示准确的绝对 JAR 路径、包内路径和行号。打开地址携带完整来源，避免不同目录的同名 JAR 被误选；类型搜索的 JAR 打开也使用此管道。XML、Java、properties 等采用各自语言显示。

散 class 的源码注释和原始实现不能直接全文查找；它们不属于文本文件，点击后按单类反编译。现有 JAR 常量池结果仍用于方法、字段及字符串搜索。

## 实现与边界

- 每个来源缓存包内目录和文本块，不把全库正文常驻内存；查询时逐来源读缓存，不重复解压全库。文件名/类名目录在 128 MiB 内复用内存，超出部分回落到磁盘缓存；纯 class 来源不参与文本读取。
- 初次建立在后台进行；界面显示准备状态并提供重试。无定时轮询；新查询、重试及打开工程触发必要工作。
- 文件长度和修改时间作为指纹；查询侧每 30 秒至多发起一次后台重新发现和核验，替换或新增 JAR 会在后续查询触发的刷新中纳入。
- 缓存目录和正文作为同一快照读取，旧快照不与新正文配对。切工程及 A→B→A 的排队任务按代次隔离。
- 搜索选项采用执行时快照，支持跨工程及工作区结果截断时的库补充搜索；输入框继续输入不触发重搜。
- 查询单飞且可取消；旧请求不能覆盖新结果，取消按请求身份匹配。
- 单文件解压/读取上限 4 MiB，单来源正文 32 MiB，总正文预算 512 MiB，单来源目录 100,000 项；每次最多返回 100 处、20 秒扫描预算。超限、无法读取、过期及取消均明确提示，不能把部分结果解释成全库零命中。
- 读取仍沿用路径 canonicalize 与当前 NC/工程根校验；不允许包内路径穿越，不解压写回真实工程。
- 库标签只读，禁止保存、编译和普通磁盘恢复。支持行列定位、导航及关闭后重新打开。
