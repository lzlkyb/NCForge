# 剩余五类查询辅助实施与验收

日期：2026-11-13。完成用户要求的五类辅助，沿用 SQL 编辑器、补全列表、右键操作和快捷修正菜单。根据当前库真实表、字段和外键/NC 类引用生成查询，不固定采购订单或单号，不增加参数填写面板。

## 使用方式

| 辅助 | 操作入口 | 生成或提示内容 |
| --- | --- | --- |
| 主表没有关联行 | 新语句输入表名/中文名，Ctrl+空格 | “没有关联行”模板，用 NOT EXISTS 检查 |
| 关联记录找不到主表 | 同上 | “找不到主表”模板；排除任一关联键为 NULL 的行 |
| 字段组合重复 | 选中 SELECT 中同一表的完整字段，右键“按所选字段检查重复（全表）” | GROUP BY 所选字段，HAVING COUNT(*) > 1 |
| 明细计数与数值汇总 | 主表模板中选择“明细行数”；或选中明细数值字段，右键“按所选明细字段汇总（全表）” | 明细先按关联键聚合，再 LEFT JOIN 主表；无明细时返回 0 |
| LEFT JOIN 条件含义 | 在 WHERE 写关联表直接过滤条件 | 字段显示含义提示；Ctrl+. 可选择移入 ON 或明确 INNER JOIN |
| 时间快捷条件 | 在 WHERE/ON 输入真实日期字段或中文名，再选条件；已有字段后可输入“本月”等 | 今天、本月、上月、近七天的动态时间范围 |

检查和汇总生成的是独立全表查询，追加在原语句后，原 WHERE 不带入。菜单、生成注释和通知明确说明范围；需要筛选时直接在新 SQL 添加条件。多条已确认父表关系使用现有补全列表供用户选择，每个候选独立生成。

## 1. 主子/关联数据检查

以真实关系 `INVOICE_ROWS.HEAD_ID -> INVOICE_HEAD.ID` 为例，主表没有关联行：

```sql
SELECT a.*
FROM INVOICE_HEAD a
WHERE NOT EXISTS (
    SELECT 1
    FROM INVOICE_ROWS b
    WHERE b.HEAD_ID = a.ID
);
```

关联记录找不到主表：

```sql
SELECT b.*
FROM INVOICE_ROWS b
WHERE b.HEAD_ID IS NOT NULL
  AND NOT EXISTS (
    SELECT 1
    FROM INVOICE_HEAD a
    WHERE b.HEAD_ID = a.ID
);
```

复合关联键使用所有已确认配对，两侧字段必须是支持等值比较的实际标量类型。关联模板可以用于主子单据及其他关联表，业务身份以实际元数据为准；没有可靠关系或真实字段时不猜测。

## 2. 字段组合重复检查

选择 `SELECT a.ORG_ID, a.BILL_NUMBER FROM INVOICE_HEAD a` 中完整的 `a.ORG_ID, a.BILL_NUMBER`，生成：

```sql
SELECT a.ORG_ID, a.BILL_NUMBER, COUNT(*) AS DUPLICATE_COUNT
FROM INVOICE_HEAD a
GROUP BY a.ORG_ID, a.BILL_NUMBER
HAVING COUNT(*) > 1;
```

支持一个或多个字段。现有查询带 JOIN 时，所选字段仍须来自同一明确物理表；不接受局部字段、函数、通配符、输出别名、歧义字段、CTE、嵌套或集合/聚合查询。按实际 Oracle 字段类型核验可分组性，大对象、二进制、对象和未知类型不生成。

## 3. 明细计数和数值汇总

选择明细的 `b.QTY, b.AMOUNT`，按完整父主键生成：

```sql
SELECT p.*,
       NVL(d.DETAIL_COUNT, 0) AS DETAIL_COUNT,
       NVL(d.SUM_QTY, 0) AS SUM_QTY,
       NVL(d.SUM_AMOUNT, 0) AS SUM_AMOUNT
FROM INVOICE_HEAD p
LEFT JOIN (
    SELECT c.HEAD_ID,
           COUNT(*) AS DETAIL_COUNT,
           SUM(c.QTY) AS SUM_QTY,
           SUM(c.AMOUNT) AS SUM_AMOUNT
    FROM INVOICE_ROWS c
    GROUP BY c.HEAD_ID
) d
    ON d.HEAD_ID = p.ID;
```

先聚合明细，保证外层每条主记录一行；不会因展开明细导致主表金额重复累计。父表关联列必须覆盖完整真实主键，子表分组键必须可分组，SUM 字段必须是实际数值类型；条件不满足时不生成。复合键全部参与。生成结果名避开父表/分组列重名，并限制 Oracle 别名长度。

多个父表不会擅自选择。父表候选接受前再次检查连接、schema、字段缓存、模型版本、语言和光标，防止已展示的旧候选插入过期 SQL。支持 LF/Windows CRLF 编辑模型；尾部行注释和独立 `/` 结束符保持正确分隔。右键追加和选择后的查询插入均有撤销边界。

## 4. LEFT JOIN 条件含义

例如：

```sql
SELECT a.*, b.*
FROM INVOICE_HEAD a
LEFT JOIN INVOICE_ROWS b ON a.ID = b.HEAD_ID
WHERE a.ORG_ID = 'O1' AND b.QTY > 1;
```

`b.QTY > 1` 会排除没有匹配 b 记录的行。编辑器只显示说明，用户通过快捷修正明确选择：

- “将此条件移入 ON（调整筛选范围）”：保留主表条件，将明细过滤放入匹配范围，既有 ON 和移入条件均加括号保持优先级。
- “仅保留匹配记录：明确使用 INNER JOIN”：表达只要匹配行的意图。

提示不自动改写 SQL。对 OR、NOT、函数、子查询或不能证明空关联是否被排除的表达式保持保守；`IS NULL`、比较后 `IS NULL`/`ISNULL` 等能保留未匹配行的写法不会误报。复杂关联可仅说明含义；自动编辑仅提供给安全的普通两表最外层查询。其他 WHERE 和关联仍可能影响最终结果。

## 5. 常用时间条件

时间范围采用“大于等于开始，小于结束”。边界在执行时由数据库计算，不使用补全当天的客户端时间。

| 条件 | 范围 |
| --- | --- |
| 今天 | 今天 00:00 至明天 00:00 |
| 本月 | 本月 1 日至下月 1 日 |
| 上月 | 上月 1 日至本月 1 日 |
| 近七天 | 六天前 00:00 至明天 00:00，包含今天 |

支持已确认日期类型的 Oracle、PostgreSQL、SQL Server、MySQL/MariaDB、DB2。条件说明标明数据库会话/事务/服务器的日期与时区语义；带时区日期按支持的类型分别生成。NC 常见 `CHAR(19)` 日期、未知类型、SQLite/generic SQL、SQL Server rowversion/TIMESTAMP 与 DATETIMEOFFSET 不推测时间编码或时区。

已有别名的字段重复出现在上下界时保持限定。直接 NOT 下不提供双条件范围，明确的 NOT(...) 内允许使用。

## 范围和实现

关系检查、组合重复与汇总目前使用已连接 Oracle 当前 schema 的元数据；其他数据库的时间快捷按实际 SQL 方言和字段类型提供。查询模板、时间条件及含义提示由现有“查询与条件模板”设置控制，选区检查/汇总是独立右键操作。

所有辅助只编辑 SQL，执行由用户主动触发。纯函数负责 SQL 生成、时间边界和含义分析，编辑器层负责元数据、选择和撤销。新增含义分析采用 250ms 有限延时，编辑时先清空旧提示，销毁时取消延时、注销提供器和命令。
