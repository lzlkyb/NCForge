# NCForge 等待体验全面重构 — 方案（2026-11-19）

目标：把全应用耗时操作的等待 UI 统一重构。**能预测的，让用户看见还要多久；不能预测的，让用户看见正在发生什么、值得等、随时能走。** 等待本身也可以有内容、有质感，但不许挡路、不许撒谎。

配套设计稿：`desktop/wait-preview.html`（真控件 + 真样式表的交互预览，见 §10）。

---

## 1. 现状盘点

### 1.1 基础设施（已有的底子，不推倒）

| 资产 | 位置 | 现状 |
|---|---|---|
| 统一任务状态机 | `src/lib/operations.ts` | running/cancelling/success/failed/cancelled；progress{done,total}；phase 文本；cancel/retry/reveal；300ms 延迟可见防闪烁；同键去重 |
| 单任务等待组件 | `src/components/ui/TaskFeedback.tsx` | 转圈 + 已用秒 + 确定/不确定进度条 + 取消 + ≥10s 长安慰文案。**没有 ETA、没有阶段列表、没有完成摘要** |
| 任务中心浮层 | `src/components/ui/OperationStatus.tsx` | 全部任务列表；原生 `<progress>` + 文本；≥10s 提示「可继续处理其他内容」 |
| 延迟转圈 | `BusyIndicator.tsx` / `useDelayedBusy` / `useTaskElapsed` | 短操作不闪；秒表在窗口隐藏/视图不活跃时暂停 |
| 查询动画场 | `src/components/db/QueryField.tsx` | 全应用唯一真动画：canvas 粒子场，保旧数据、pointer 互动、reduce/隐藏暂停。**只有「等待数据库返回」一句文案，无进度语义** |
| 动效纪律 | `index.css` token（--dur-*/--ease-*）、`motion-feedback.css`、`scripts/check-motion.mjs` | reduce 全局降级、隐藏/不活跃暂停循环动画、Playwright 回归锁 token 一致 |
| 骨架屏 | `.skeleton` shimmer + `meta-tool-skeleton` | 元数据工具有结构骨架；**表树/结果区/对象树没有** |

### 1.2 操作矩阵（现状 → 进度数据可用性）

| 操作 | 现在用户看到 | 进度数据 | 可预测性 |
|---|---|---|---|
| 数据库连接 | 状态 chip 转圈，两态 | 无阶段（TCP/认证/切 schema/拉元数据实际分步） | **半可预测**：阶段可拆，总时长可历史学习 |
| SQL 单条执行 | QueryField + 秒表 + 停止 | 无（数据库说了算） | **不可预测**，但同连接历史耗时可给「通常 Xs」 |
| SQL 脚本批量 | 「执行脚本 N/M 条」+ 逐条结果 | done/total 有；每条耗时未知 | **混合**：条数确定，时长靠历史 |
| 加载更多 | 转圈 | 无 | 不可预测（短） |
| 表树/元数据加载 | tablesLoading 转圈 | 无 | 半可预测（对象数可历史学习） |
| schema 同步 | 状态文本 | 有同步状态机 | 半可预测 |
| 按值反查 | 两阶段文案（catalog→逐表） | 表清单 + 已查数 | **可预测**（表数已知） |
| 导出 INSERT/数据 | transferJobs 进度 | done/total | **可预测** |
| 编译/构建 | 阶段名 + done/total + 当前模块 + 日志流 | **四件套全有**（全应用唯一） | **可预测**（模块数已知，历史时长丰富） |
| jdt.ls 启动/影子工程重生成 | 两态文案 | 无阶段 | 半可预测（阶段可拆） |
| SVN 扫描 | 计数 | 有计数 | 可预测 |
| SVN 提交/更新/撤销 | 阶段文案 | 阶段有、量无 | 半可预测 |
| 全局搜索/替换 | 两态 | 无 | 不可预测（通常短） |
| 应用更新下载 | 字节进度 | 字节有 | **可预测**（ETA 可算） |
| 组件下载 | 字节 + 速率 | 字节 + 速率 | **可预测** |
| NC 启动/任务链 | 轮询阶段文案 | 阶段有 | 半可预测 |

**结论：数据底子比 UI 好得多。** 编译/导出/更新/反查/脚本都有计数，但除了编译，都没把「还要多久」说出来；连接/jdt.ls/SVN 的阶段在后端存在，前端只收到一个笼统 phase 字符串；全应用没有任何 ETA、没有历史耗时学习、完成反馈普遍是一行字或 toast。

## 2. 业界对标（带出处）

### 2.1 阈值与形式选择（研究共识）

| 等待时长 | 应该给什么 | 出处 |
|---|---|---|
| <0.1s | 直接给结果，不需要反馈 | Nielsen 三限（NN/g） |
| 0.1–1s | 无需特殊反馈，但操作要有即时按下态 | Nielsen 三限；Sherwin（NN/g）：任何动作立即给视觉回应 |
| <0.3–0.4s | 不显示加载指示（闪烁反而是噪音）；Doherty 阈值：<400ms 交互保住心流与生产率 | IBM Doherty & Thadani 1982（Laws of UX 收录）；我们已有 300ms 延迟可见，对齐 |
| 1–10s | 循环动画 + 文案说明在等什么；有计数就给快速变化的绝对量（「已更新 3/50」），不必百分比 | Sherwin（NN/g）：looped 只用于 2–10s；Nielsen：2–10s 用 busy + 小数显 |
| >10s | **百分比/步骤进度 + 预计剩余 + 明确的取消入口**；用户会去干别的，完成时要显著通知 | Nielsen 三限；Kaplan（NN/g 复杂应用长等待五准则） |
| 总量未知 | 给**绝对工作量**（正在处理第几个、名字是什么），不给假百分比；最后手段才是纯转圈 | Nielsen 三限原文；Apple HIG：不可量化用 indeterminate |

关键实验结论（不是博客玄学）：
- **有进度反馈的等待耐受度约 3 倍**：Nebraska-Lincoln 实验，看到循环进度条的组满意度更高、平均愿意等 3 倍时间（Sherwin/NN/g 转述）。
- **进度条末段加速感觉更快**：CMU Chris Harrison（CHI'07），同样总时长，加速到终点的进度条比匀速感觉快（userpilot 转述，Duolingo 案例）。
- **中速动画最优**：Stanford Ding & Kyung 2025，1400+ 人三组实验，2–5s/圈的中速动画在感知速度、喜爱度、等待留存上全面胜过快速、慢速与静态（20s 等待组 45% 留到落地 vs 快速组更低；30s 组中速 2/3 完成 vs 快速约一半）。**我们的 --dur-loop=1.15s 偏快，应调到 ~2s。**
- **互动动画 > 进度条 > 被动动画**：Cornell 研究，互动加载动画 perceived 更快、更被喜欢（userpilot 转述）。QueryField 的 pointer 互动方向是对的。
- **劳动幻觉（Labor Illusion）**：Harvard Buell & Norton，展示「正在 exert effort」的运营透明化，让用户甚至偏好稍长的等待（TurboTax 案例）。**阶段叙事不是装饰，是价值证明。**
- **骨架屏前提**：占位结构必须与真实内容 1:1，否则落地跳动制造第二次等待（多源一致：saasui.design、CSS-Tricks、业界实践）。感知缩短 20–30% 的说法来自厂商博客，**只作方向参考，不作验收指标**。

### 2.2 标杆产品怎么做

| 产品 | 做法 | 对我们的启示 |
|---|---|---|
| **IntelliJ IDEA / DataGrip**（直接竞品） | 状态栏进度 + 点开 Processes/Background Tasks 管理器；索引拆成两个命名阶段「Scanning files to index / Updating indexes」；任务可转后台；全部完成后清空状态栏 = 「智能功能已就绪」信号 | 我们的状态栏 chip + 任务中心骨架已对齐；**缺命名阶段、缺「就绪」完成信号** |
| **Linear** | local-first 同步引擎 + 乐观更新：先渲染本地缓存数据、后台静默同步，「没有 spinner」；把网络从体验里藏掉 | 方向正确但属架构级投入；**本方案只做轻量版：缓存优先渲染（表树/元数据已有缓存可先显旧数据再刷新）**，不做同步引擎 |
| **Vercel** | 部署 = 实时构建日志流 + 每阶段状态 + 即时回滚 | 编译已有日志流，**补阶段可视化与 ETA**；长任务等待区放「正在发生什么」的实时叙事 |
| **Slack** | 骨架屏 + 团队自定义语录 + 产品 tip，等待变品牌时刻与功能发现 | **WaitTips 内容层**：NC 开发技巧/快捷键/功能发现，按剩余时长轮换 |
| **Expedia** | 加载动画镜像正在做的任务（搜机票 = 飞机穿云） | QueryField 已是「数据场」隐喻，**按操作类型换叙事文案与形态**（查询/编译/导出各有其形） |
| **Productboard** | 局部加载用小骨架，整应用启动才用大动画——**模式随等待长度升级** | 我们的分级反馈同构：chip → panel → field，不许到处放大动画 |
| **Webflow** | 技术用户编辑器加载：居中 logo + 进度条，零娱乐 | **我们的用户是 NC 开发者，克制是底色**；趣味层是点缀不是主菜 |
| **WeTransfer** | 进度始终是视觉锚点，旁边放编辑内容，不挤占 | 等待内容层永远不许盖过进度本身（NN/g 儿童研究同结论） |
| **Apple HIG** | 尽快显示占位；等待时让用户干别的；长等待给有趣内容（tips/新功能）且**时长要匹配内容量**；知道时长用 determinate；**indeterminate 能转 determinate 就转**；进度匀速化、不许 90% 五秒最后 10% 五分钟；**取消有代价要告知** | 全部吸收为 §3 原则 |

## 3. 设计原则（八条，验收按这八条）

1. **分级反馈**：<300ms 无指示（已有）；0.3–1s 轻 chip；1–10s 循环 + 计数/阶段；>10s 百分比或步骤 + ETA + 取消 + 可后台。模式随等待长度升级，不越级。
2. **可预测必给 ETA**：有计数或历史样本的操作，显示「预计还需 ~Xs / ~X 分钟」。ETA 来自历史学习（§4.2），**保守向上取整、样本不足给区间或「通常 Xs」**。不可预测的给阶段 + 绝对量，绝不编百分比。
3. **进度诚实**：单调不回退；显示层可平滑（ease 逼近目标），不许伪造总量、不许卡在 99%；真停滞时明说「正在等待 X（已 Ns）」并给取消；indeterminate 拿到总量后**原地转 determinate**（形状不变，Apple HIG）。
4. **永远有出口**：能取消的都有取消；不能取消的明说「此操作不支持中途停止」（已有）；取消有代价（丢已下载部分/回滚）先告知（Apple HIG）。长任务一键转后台，完成显著通知。
5. **等待有内容**：阶段叙事（正在做什么、为什么）+ 任务相关 tips；内容量匹配预计时长；**内容永远不盖过进度**；reduce 模式静态单条。
6. **完成有摘要**：长任务完成给 开始/结束/耗时 + 发生了什么（条数/模块数/跳过/失败）+ 跳转链接（NN/g 五准则之二）；短任务保持现状一行字，不升级成弹窗。
7. **桌面原生**：状态栏 + 任务中心 + 就地反馈为骨架（IDEA 同构）；**不做全屏阻塞加载页、不做模态进度窗**；等待期间应用处处可继续工作。
8. **动效纪律**：沿用 --dur-*/--ease-* token 与 reduce/隐藏暂停规则（check-motion 回归）；循环动画调至 ~2s/圈（Stanford 中速结论）；骨架与真实结构 1:1；新动画进 check-motion 清单。

## 4. 等待态设计系统（新增基础设施）

### 4.1 Operation 扩展（operations.ts，向后兼容）

```ts
interface Operation {
  // 现有字段不动
  phases?: { name: string; state: "pending" | "active" | "done" | "skipped" }[];
  eta?: { seconds: number; basis: "history" | "rate" | "static"; confidence: "low" | "ok" };
  summary?: { startedAt: number; endedAt: number; items?: { label: string; value: string }[]; reveal?: string };
}
```
后端能推阶段的推阶段（编译已有、连接/jdt.ls/SVN 补），推不了的前端按已知步骤派生。

### 4.2 ETA 引擎（新 lib/eta.ts）

- 每次任务完成记录 `(key, 规模维度, 耗时)`：SQL 按 connId+语句类型、编译按模块数、导出按行数、下载按字节。本地持久化（localStorage，**不进导出**，与自动行为开关同口径）。
- 估算：同 key 近 N 次指数加权均值；有规模维度时按规模归一（每模块/每行/每字节单价）。
- 输出规则：样本 <3 → 「通常 Xs」（静态默认表兜底）；方差大 → 区间「约 X–Ys」；正常 → 「预计还需 ~Xs」，**向上取整到人类刻度**（5s/10s/30s/1min/5min）。剩余 = 估算总时长 − 已用，随进度单调收敛；下载类直接用 剩余字节/平滑速率。
- 显示措辞永远带「预计/约」，不许「精确倒计时」——NN/g：粗估足够，精确必失信。

### 4.3 WaitFeedback 组件族（TaskFeedback v2，同一数据源三种形态）

| 形态 | 用在哪 | 内容 |
|---|---|---|
| **chip**（就地） | 结果头、状态栏、按钮内 | 转圈/确定环 + 阶段短语 + 秒表；>10s 追加 ETA |
| **panel**（任务中心行） | OperationStatus | 阶段 stepper（≤5 步）+ 进度条 + ETA + 计数 + 取消/后台/返回来源 |
| **field**（区域动画） | 结果区/编辑区空白 | QueryField 扩展：按操作类型换叙事（查询/编译/导出），进度语义驱动粒子聚集程度 |

三形态共享 Operation 数据，**不许各写各的进度逻辑**。完成摘要卡 CompletionSummary 统一渲染 summary。

### 4.4 内容层 WaitTips

- 本地静态内容库（NC 开发技巧、快捷键、功能发现、schema 小知识），**不联网**。
- 预计等待 >15s 才出现；按剩余时长决定条数；reduce → 静态一条；永远在进度下方/侧方，不覆盖。
- 完成即收，不留痕。

### 4.5 动效参数调整

- `--dur-loop` 1.15s → **2s**（Stanford 中速区间下沿，配合 check-motion 更新基线）。
- shimmer 1.3s 保留（落在 1.2–1.5s 实践区间）。
- 进度条末段加速：显示层 ease-out 逼近（Harrison CHI'07），但**真实进度数据不改**。

## 5. 逐操作目标态

| 操作 | 目标等待态 | ETA 来源 | 阶段 |
|---|---|---|---|
| 数据库连接 | chip→panel：连接中→认证→切 schema→就绪；失败给具体阶段 | 历史（同连接） | 后端补 4 阶段 |
| SQL 单条 | QueryField + chip「正在查询 · 通常 3s」；>10s 出 ETA 与「可继续工作」 | 历史（connId+类型） | 无（单阶段），停滞 >15s 明说等待数据库 |
| SQL 脚本 | panel：N/M 条 + 当前语句摘要 + 预计剩余；逐条结果保留 | 历史每条均值×剩余 | 每条一阶段（>20 条折叠为计数） |
| 表树/元数据 | **结构骨架 1:1** + 缓存旧数据先显（Linear 轻量版）+ 刷新 chip | 历史 | 拉取→渲染 |
| 按值反查 | panel：catalog→逐表 N/M + ETA | 表数×历史单价 | 两阶段已有，补计数 |
| 导出 | panel：行 N/M + 速率 + ETA + 取消（告知已写部分保留） | 行数×历史单价 | 读取→写入 |
| 编译/构建 | panel：阶段 stepper（扫描→编译→收尾）+ 模块 N/M + 当前模块 + ETA + 日志入口；完成摘要（成功/失败/跳过模块数 + 耗时） | 模块数×历史单价（make 化后数据更全） | 已有，可视化 |
| jdt.ls 启动 | chip：启动 JVM→加载工程→索引就绪；就绪信号进状态栏（IDEA 同构） | 历史 | 后端补 3 阶段 |
| SVN 提交/更新 | panel：阶段 + 文件计数（有则显）+ 取消 | 历史 | 已有文案结构化 |
| 更新/组件下载 | panel：字节进度 + 平滑速率 + ETA + 取消（告知丢已下载） | 剩余字节/速率 | 下载→校验→安装 |
| 全局搜索 | chip（通常 <1s，不升级） | 无 | 无 |
| NC 启动链 | panel：任务链 stepper + 当前任务日志入口 | 历史 | 已有轮询阶段结构化 |

## 6. 分期

**P0 · 基础（所有操作受益）**
- Operation 扩展 phases/eta/summary（向后兼容）+ eta.ts 历史学习 + TaskFeedback v2（chip/panel 两形态）+ OperationStatus 行升级 + CompletionSummary。
- 验收：编译/导出/更新三个已有计数操作立即显示 ETA 与阶段；check-motion 绿；eta 单测（含反例：样本不足/方差大/单调收敛）。

**P1 · 高频短等待**
- SQL 单条/脚本接 ETA 与阶段叙事；连接四阶段；表树/元数据骨架 1:1 + 缓存先显；QueryField 叙事按操作类型。
- 验收：wait-preview 全场景可演；真机连接/查询/脚本各跑一遍；骨架落地零跳动（rAF 重量）。

**P2 · 长任务全覆盖**
- jdt.ls/SVN/反查/NC 启动链接阶段与 ETA；下载速率平滑与取消代价提示；长任务后台化 + 完成显著通知。
- 验收：§5 矩阵逐行核；取消覆盖率 100%（可取消操作）。

**P3 · 愉悦层**
- WaitTips 内容库 + 完成微仪式（克制：摘要卡入场 + 状态栏就绪信号，不做撒花）；QueryField 形态增强；--dur-loop 调 2s 全量回归。
- 验收：reduce/隐藏/不活跃三态暂停回归；tips 不盖进度；内容量匹配时长。

## 7. 不做（及触发条件）

| 不做 | 理由 | 重估触发 |
|---|---|---|
| 全屏阻塞加载页 / 模态进度窗 | 桌面原生红线；IDEA/我们骨架都是非阻塞 | 无 |
| 游戏化等待（小游戏/ mascot 撒花） | 用户是 NC 开发者，Webflow 式克制是底色；NN/g：干扰物不得盖过进度 | 无 |
| 伪造百分比 / 假 99% | 诚实原则；Apple HIG 明确点名 deceptive | 无 |
| Linear 式 local-first 同步引擎 | 架构级投入，ROI 另议；本方案只做缓存先显轻量版 | 元数据刷新成为头号抱怨时 |
| 每操作独立雪花 UI | 三形态共享数据源，维护成本 | 无 |
| 默认声音通知 | 办公环境打扰 | 用户显式要求 |
| A/B 实验平台 | 无真用户规模（测试库数据不是用户证据）；用 check-motion + 验收脚本 + 用户反馈替代 | 有真实投放规模后 |
| 精确倒计时 | NN/g：粗估足够，精确必失信 | 无 |

## 8. 度量与验收

- 首次反馈 ≤300ms（已有机制，回归保住）。
- ETA 覆盖率：§5 标「可预测/半可预测」的操作全部有 ETA 或「通常 Xs」。
- 取消覆盖率：可取消操作 100% 有入口；不可取消的 100% 有说明。
- 进度诚实回归：单调性单测 + 停滞文案触发测试。
- 动效回归：check-motion 扩 wait-preview 场景；reduce/隐藏/不活跃暂停。
- 感知验证：开发者真机走查 + 用户反馈通道；**不拿测试库数据外推用户收益**。
