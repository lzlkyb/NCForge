# 交互稿方向约定

## Direction contract

THESIS: 以文件、SQL 与日志内容为中心。高频操作直接可达；面板采用连续平面布局，避免多层卡片和重复工具条。

OWN-WORLD: 深青 #24766E / #78BFB4，中性灰工具区与白色或石墨色内容区。系统界面字体，代码使用等宽字体。控件 6px、菜单 10px、弹窗 12px，停靠区域直角相接。

STORY: 用户先选择工程内容，编辑或执行，观察就近结果，然后在代码、数据库和日志间切换。搜索命中和日志位置能打开源码；各 SQL 标签独立保留结果与事务状态。

FIRST VIEWPORT: 全窗口工作台，标题栏 36px、默认主导航 148px、资源树 240px、文档标签 36px、底部状态栏 25px。代码工具条右侧为编译；数据库的连接与执行操作位于编辑器上方。

FORM: 用户已明确选择方案，无随机方向探索。交互稿使用现有工作台空间结构，采用桌面布局的自适应宽度。主要检查 1440×900、1280×800、1024×768，不将全窗口缩小成卡片。

MOTION: 内容切换 170ms 淡入，弹窗 180ms 轻位移。导航与标题栏保持稳定；系统或应用的减少动态效果选项会关闭转场。编辑与 SQL 草稿跨模块保留。

FINISH: 以实际浏览器交互检查、深浅主题截图、独立审阅和设计文档作为交付证据。成果是待用户确认的交互设计稿，不宣称已将该设计实施到应用中。
