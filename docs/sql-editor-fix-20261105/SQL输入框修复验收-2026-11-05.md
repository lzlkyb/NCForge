# SQL 输入框修复验收

## 根因与修复

用户反馈安装版有黑框、行号贴边，dev 正常。使用生产 dist 和 Tauri 的 CSP nonce 注入方式复现了同样的黑框，记录见 `production-before.png` 和 `production-before.json`。

生产策略原本声明允许内联样式，但 Tauri 为 HTML 的样式标签追加 nonce 后，浏览器忽略同一 `style-src` 中的 `unsafe-inline`，阻止 Monaco 动态样式和部分内联布局属性。显式配置 `style-src-elem` 和 `style-src-attr` 恢复原先允许动态样式的意图；脚本仍仅允许本地来源与构建注入的 hash，未允许内联脚本或 eval，未禁用 CSP 或 Tauri 的 nonce 注入。

另修复结果区固定高度挤压输入区的问题：首次绘制前和窗口缩放时重新限制高度，保留至少 140px 编辑空间，计入 5px 分隔条，恢复窗口后恢复高度偏好；极小高度允许控制台内部滚动。损坏的保存值使用默认值。键盘与拖动调节都保存偏好并清理指针监听。

编辑器在绘制前创建并绑定模型，绑定后按实际容器重新布局，补充上下各 8px 留白与可访问名称。

## 验收范围

浏览器使用本地模拟 IPC，没有连接或修改业务数据库。生产测试直接使用 `dist` 的 JS/CSS，复制 Tauri 的 nonce/hash 注入方式与配置策略，未引用 dev 的 TypeScript 模块；详细测量见 `measurements.json` 与 `production.json`。

本次没有生成或安装新 exe，当前已安装的旧版本还不包含此修复。需构建新安装包并更新客户端后完成原生安装版验收。无 Rust 源码改动、无版本号变更、无提交。

重任务串行执行。前端构建启动可用内存约 3.75GiB，运行采样约 3.28GiB；这是增量构建采样，不能当作冷构建最低内存依据。
