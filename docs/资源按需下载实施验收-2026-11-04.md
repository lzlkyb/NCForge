# 资源按需下载实施验收

> 本文保留组件下载专项的阶段记录。后续监听握手、旧安装资源识别及浏览器夹具修复，以及完整门禁结果见[工作区改动审查与提交验收](工作区改动审查与提交验收-2026-11-04.md)，提交验收以该记录为准。

本次交付按此前确认的建议，完成四种运行组件的按需下载与缺失引导。组件包括 Java 代码智能（jdtls）、Java 编译器（ecj）、SVN（svnkit）和 CFR 反编译器。

## 用户流程

- 启动只读取本地状态，不自动下载全部组件。
- 设置 → 维护 → 组件与更新中，每个组件可以独立下载或重新下载；保留批量下载缺失项与明确的全量重装入口。
- SVN 扫描、代码智能设置及状态栏、编译输出与问题面板、CFR 签名桩提示提供对应组件的下载按钮。自动编译缺组件时保留下载引导，不强行打开或切换面板。
- 标题栏常驻下载入口，下载时显示等待图标；关闭面板后下载继续，再打开保留本轮记录，关闭走公共弹窗退场动画。
- 已知总大小时显示百分比、下载量、总大小及网速；未知总大小时显示不确定进度和实际下载量，不虚构百分比。
- 下载结束后继续显示实际校验和安装等待状态；只有后端终态才允许下一次下载。
- 失败重试保留已完成项，严格限定到原请求剩余组件；强制重装失败后仍保留原重装语义。单项重试成功不会将其他未完成项误报为完成。
- 组件文件被移走、仅有空目录或缺少运行必需文件时显示缺失；CFR 支持带版本号的 jar 与归档内子目录。

## 后端契约

`resources_ensure(force?: boolean, ids?: string[])` 支持严格白名单。空列表及未知 ID 明确拒绝，指定 ID 时检查、认领、下载和强制重装只处理所选组件。单飞锁占用时同步返回错误。

阶段事件为 checking → available → downloading → progress → verifying → installing → installed → ready；无须下载时发送 uptodate 后仍等待 ready。校验失败不会安装。镜像回退保留本轮成功的组件，不重复重装。

## 内存规则调整

按用户本轮指示，取消固定 4GB 门槛：未测过的重任务以 3GB 可用内存起跑，低于 4GB 时 Rust 编译 1 路，测试 2 线程；重任务继续串行。已有相同缓存、并发条件的成功采样时，用实测最大消耗加至少 1GB 余量决定能否运行。

| 任务 | 采样起点可用内存 | 最低可用内存 | 最后采样 |
| --- | --- | --- | --- |
| Rust 全量测试，1 路编译 | 3.28GB | 2.20GB | 3.86GB |
| 前端全量测试，2 个 worker | 2.82GB | 2.02GB | 3.11GB |
| 浏览器确认，1 个无头页面 | 2.72GB | 2.24GB | 2.26GB |
| Vite 构建 | 3.03GB | 2.45GB | 2.45GB |

每约两秒采样一次，按 1024 进制换算。这里测的是系统可用内存，包含其他应用的影响；采样起点可能已分配部分任务内存，最后采样也不等于关闭任务后完全回收。这次没有出现崩溃或页面错误，仅说明当前缓存与并发条件下运行正常，不推断冷编译或多任务同时运行的需求。
