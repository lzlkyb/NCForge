# 切页与骨架屏修复

六类工作区已经使用各自布局的骨架屏，并直接停靠到实际正文、资源栏、工具栏和底部面板。导航立即更新页面；编辑器、查询草稿、文件树节点和滚动位置继续保留。

## 原因与修复

1. 原导航通过 `startViewTransition` 捕获整页，再用 `flushSync` 更新。保活编辑器和大文件树增加截图与同步布局开销。现在直接提交导航，仅在实际阅读区做 100ms 的轻微透明度淡入；资源树不参与动效，减少动效时跳过。
2. 文件树曾在其他工具接管侧栏、或元数据与日志收起侧栏时重新测量。几千项文件及图标的排版会牵动工作区；继承宽度变量也会扩大样式重新计算。现在原生树保持自己的宽度、隔离布局，隐藏内容暂停排版。
3. 返回大文件树时仍需处理全部节点，因此将大目录的固定高度兄弟行按 50 项分批，用浏览器跳过屏幕外内容的排版与绘制。完整 DOM 和键盘目标仍在；递归分支、成员行、加载提示与内联编辑继续保留自然高度。
4. 原工具页共用 `m-4 h-40` 骨架，落在工作台运行宿主中，额外占用正文下方空间。现在 `WorkspaceSkeleton` 使用真实停靠槽，180ms 后才出现加载视觉，只有一处状态播报。
5. 代码骨架对齐 47px 上下文、36px 标签、28px 路径与真实底部面板；数据库对应标签、SQL、结果区；SVN 对应工具栏、改动列表与正文；元数据对应资源和文档；日志对应 52% 列表及详情、窄窗口上下布局；设置对应搜索、标题、分组和背景。元数据工具内部按比较、历史、生成、Excel、发布等视图区分骨架。

经典与玻璃继续共用整体 14px 圆角外壳和既有密度。

## 性能采样

使用生产构建、正式 CSP、Headless Edge、1440×900 窗口、3000 项文件树和内存业务数据；各页面预先访问，随后六页循环三轮。性能采样单独运行，没有并发构建、单测或 trace。

下表为点击到工作台页面标识更新的中位耗时，单位 ms：

| 页面 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 代码 | 656.4 | 50.0 |
| 数据库 | 165.3 | 50.0 |
| 版本控制 | 30.8 | 14.8 |
| 元数据 | 29.1 | 15.2 |
| 日志 | 224.3 | 16.2 |
| 设置 | 245.5 | 16.1 |

代码页三轮为 141.7 / 49.0 / 50.0ms，首轮仍有额外开销；最终采样不表示所有切换都在一帧内完成。整页截图调用由 23 次降为 0。修改后元数据、日志、设置和 SVN 的切页窗口均没有 50ms 以上长任务。

前后 `commitMs` 定义一致。帧间隔采集曾修正首帧丢弃问题，因此不直接对比旧结果的 P95 帧间隔。这里只量前端导航；真实工程首次读取、数据库响应与后端服务耗时不在模拟结果中。

## 验收

- 六页骨架正文的 x、y、宽、高与加载完成后的正文边界完全一致；运行宿主额外占位为 0，外壳圆角为 14px。
- 树滚动位置 6000px、宽度 240px、总高度 81013px 在代码 → 元数据 → 日志 → 数据库 → 代码后保持一致，原节点身份保留。
- 键盘 End 能定位和显示第 3000 项；大目录单测覆盖末行选择、F2 重命名和取消后完整顺序。
- SQL 未保存内容返回后保留；快速连切最后一次点击生效；减少动效时没有阅读区动画。
- 1024px 窗口下元数据骨架隐藏资源栏，日志骨架上下分栏，与实际布局一致。
- 67 项相关单测、14 项动效浏览器检查和 133 项材质工作台检查通过。材质检查包含浅／深色、经典／玻璃、560／1024px、选区、键盘面板调整与正式 CSP。
- 前端类型检查及生产构建、组件体量、设计 token、UI 约定和新增实现的 ESLint 检查通过。
