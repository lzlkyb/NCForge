**这是最后一次「与通用数据库客户端逐项对比」**，已于 2026-11-10 完成并拍板。所有已知差距一次列全，之后不再反复对比。

拍板后的三类状态：

| 状态 | 效力 |
| --- | --- |
| **不做（产品边界）** | 不是暂缓排期。后续能力评价、差距清单、路线图评审中不再计入待补项，不再作为扣分项；新提案命中即驳回。重开需「前提实质变化 + 新的产品决策」，**不因竞品有而重启** |

| **确定性欠账（X1 / X3 / X4）** | 不属于功能对比，锁定必做，顺序固定，不因功能拍板而取消 |

- 11-08 评价报告归档为历史快照，只用于回溯，不再作为差距来源；后续数据库评审只做两件事：**边界内能力的成熟度验收**与 **NC 场景新需求**。

## 2. 已补齐，不再计入差距

11-08 报告列为「A 必须补」的 5 项与「B 打磨」里除 `runToken` 外的 3 项，均已在 v0.3.0 / v0.4.0 落地并核准源码：行级 INSERT/DELETE、XLSX/JSON 导入、表结构对比（DDL diff，只生成脚本）、跨连接搬运、CLOB 全量取数（`execFull`）、`v$transaction` 事务真源、全覆盖 `call_timeout`。11-10 UI/UX 审查的 5 个 S1 也已修。数据库 tab 的滚动、所有标签下拉、拖拽排序与最近关闭恢复已实现。

**这些项此后不再出现在任何差距清单里。**

### 组 1｜报告已否决，待确认（01–03）

**拍板结论（2026-11-10）：01–03 全部「不做」，并入产品边界。**

### 组 2｜PL/SQL 与诊断深化（04–11）

**拍板结论（2026-11-10）：04–11 整组「保留待评估」——不定性、不排期、不主动对比。** 技术建议仍保留在下表；其中 07 是唯一成本与收益匹配的一项，但未获保留为需求。

| 编号 | 能力 | 行业谁有 | 我们的现状 | 建议 | 理由 |
| --- | --- | --- | --- | --- | --- |
| 04 | PL/SQL 调试（断点 / 单步 / 变量观察） | PS / DG / DF | 无；项目里的 DAP 断点是 NC Java 代码，不是 PL/SQL | 不做（先调研） | 若 NC 现场不写存储过程即为假需求；需要一次现场频次证据才值得重开 |
| 05 | DBMS_PROFILER / 层级 profiler | PS / DF / TD | 无 | 不做 | 需要目标库装 profiler 包与写权限，实施账号通常没有 |
| 06 | AWR / ASH / SQL Monitor 报告 | TD / DF / DG（部分） | 无；只有执行计划 + `v$mystat` 统计 | 不做 | 需 DBA 授权与许可，属 DBA 职责不是二开职责 |
| 07 | 函数 / 过程签名帮助、参数提示 | PS / DG / DF | 补全有表、列、关键字、中文名，无参数提示 | 建议保留（低成本） | SQL 编辑高频、实现只需读 `all_arguments`；是这一组里唯一成本与收益匹配的 |
| 08 | JOIN 条件推导、别名智能补全 | DG / DB | 无 | 不做 | 依赖外键，NC 库外键稀疏，推导结果大概率是错的 |
| 09 | SQL 重构（提取 CTE、内联、重命名） | DG | 无；只有格式化与精确执行 | 不做 | 通用 IDE 能力，NC 场景写的是短查询与脚本 |
| 10 | SQL 方言级 lint / 静态检查 | DG / DF | 无 | 不做 | 与 08 同源，且会与现有单表可编辑判据重复造轮子 |
| 11 | SQL 脚本工程 + Git 本地历史 / 脚本版本对比 | DG / DB | 已有 SQL 片段库、执行历史全文检索、工作台文件编辑器与版本控制页 | 不做 | 数据库页内不缺「找回来」的通道；通用编辑器已能编辑 `.sql` 并看 diff |

## 4. 确定性欠账（X1–X4，其中 X2 已移出）

| 编号 | 欠账 | 状态 | 现状 | 证据 |
