# 桌面应用壳子抽离方案（cc-bridge → 可复用脚手架）

> 目标：把 cc-bridge 的**整体技术架构**、**软件更新架构**、**UI 风格架构**三层抽离成一个独立壳子仓库，以后做桌面应用 = 复制一份 → 改名 → 写业务页。
> 源工程：`D:\AItool\winapp\cc-bridge`（Tauri 2 + React 18 + TS + Rust，v3.0.0，2026-10-26 调研）

---

## 一、调研结论：cc-bridge 架构全景

### 1.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | Tauri 2 | `decorations:false` 无边框窗口 + 自绘标题栏 + 托盘常驻 + 单实例 |
| 前端 | React 18 + TS + Vite 6 | TanStack Query v5 管服务端状态，懒加载分页 |
| 样式 | TailwindCSS 4 | `@theme inline` + CSS 变量设计 token，浅/深双主题 |
| 后端 | Rust（tokio） | 模块按域拆分，IPC 命令层 `pub use` 聚合 |
| 质量门禁 | 脚本化 | 组件体量门禁 + eslint + tsc + vitest + cargo fmt/clippy/test，进 pre-push 钩子与 CI |

### 1.2 三层可抽取资产盘点

**① 整体技术架构（壳层，与业务无关）**
- 前端壳：`App.tsx`（Header + SideNav + Tabs + ToastProvider + ErrorBoundary + 懒加载 + 隐藏停轮询）
- 布局件：`components/layout/`（自绘标题栏 TitleBarControls、侧导航、更新徽章）
- 基础件：`components/ui/` 30+ 组件（button/dialog/menu/toast/table/tabs/combobox/switch/Modal/Skeleton/Spinner…）
- 横切 hooks：`useAppHiddenFlag`（窗口隐藏停 CSS 动画，实测省 0.6 核）、`useWindowSizePersistence`（尺寸持久化）、`usePrefersReducedMotion`
- Rust 壳：`main.rs` 的托盘 / 单实例 / 关窗销毁重建（省 80MB webview 内存）/ Win11 DWM 圆角 / 桌面通知门控
- Rust 分层范式：`commands/` 按域拆分 + `pub use` 重导出（调用方零改动）、`branding.rs` 显示名单一来源、`security/` 路径白名单 + 常量时间 token 比较 + 限流
- 前端 IPC 包装：`lib/tauri.ts`（invoke / invokeOrToast / listen）

**② 软件更新架构（完整闭环，这是最值钱的资产）**

发布链（一条命令打通）：
```
npm run release -- --patch
  → 只改 Cargo.toml 版本真源
  → sync-version 同步 tauri.conf.json + package.json
  → CHANGELOG.md 插版本段（git log 自动分类草稿）
  → README 版本历史插行
  → gen-changelog 重新生成 changelog.generated.ts
  → cargo test + clippy 门禁
  → commit → push main → tag vX.Y.Z → push tag
  → GitHub Actions：build-macos → build-windows（needs 串联）
  → generate-updater-json.mjs 生成 updater.json（跨平台条目合并）
  → Release attach 安装包 + updater.json
```

运行时三层：
- Rust 端 `commands/update.rs`（559 行）：`check_update` / `start_update` 后台任务、单飞闸（防连点）、指数退避重试 + 不可重试错误立即换源、错误分类码（manifest/network/timeout/signature/install/config/stale）、`update:*` 事件推送（进度/速率/已下载字节/总量未知不确定态）
- 前端状态机 `contexts/UpdateContext.tsx`（543 行）：idle→checking→available→downloading→ready→error/uptodate 全状态机、安装完成 8 秒**可见可撤销**自动重启、"稍后提醒"按版本号抑制、自动检查失败不弹 toast（降噪）
- UI 件 `components/update/`：更新弹框（版本胶囊 v旧→v新 + 更新内容）、状态 pill、下载进度、重启覆盖层（1.1s 仪式过渡）、更新内容对话框（历史版本）、升级欢迎条、折叠侧栏更新点

工程化配套：
- `scripts/generate-updater-json.mjs`：产物扫描 + 签名强制校验（缺 .sig 直接 fail，不发带病版本）+ 跨 job 合并（UPDATER_MERGE_INTO，防 mac/win 互覆）+ 镜像/Gitee URL 变体（UPDATER_DOWNLOAD_BASE / UPDATER_URL_TEMPLATE）
- `scripts/update-release-notes.mjs`：CHANGELOG → 用户可见 notes（剔除技术细节小节）+ 近 10 版历史元数据（HTML 注释形式内联，旧客户端不受伤）
- `scripts/fake-update-server.mjs`：本地假更新服务器，更新流可离线测试
- CI `build.yml` 的 tag 发版 job：签名密钥注入、updater.json 合并、notes 提取、附件清单

**③ UI 风格架构（设计系统）**
- `index.css`（2433 行）：设计 token 全量——语义色（primary 靛蓝 #4F46E5 / success / warning / destructive + WCAG AA 实测校准的 -ink 淡底文字色）、动效 token（三档时长 100/160/320ms + 统一 expo-out easing + spring）、阴影 token（浅/深自适应）、圆角档位
- 双主题：`lib/theme.ts`（localStorage 安全读写——禁用存储时不白屏、themechange 事件）+ `lib/appearance.ts`（classic/glass 双材质，`data-ui-style` 根属性切换，React 挂载前恢复防闪烁）
- 30+ 基础组件（含 Menu/Modal/Dialog/Toast/Table/Tabs/Combobox/Switch 等成套交互件）
- 动效规范：`lib/motion.ts` + `scripts/check-motion.mjs`（真实浏览器回归：CSS token 与 JS 常量必须一致、按钮 loading 不改几何）
- 无障碍：`prefers-reduced-motion` 降级、ErrorBoundary、空/错/加载三态件

### 1.3 不需要抽取的（cc-bridge 业务专属）

MCP 协议服务（`mcp/` + axum/tower）、SSH 终端（xterm + portable-pty + ssh_*）、CC 对话 GUI（`cc_session` + `ccgui` 组件群）、防火墙诊断、备份、审计域、pinyin-pro/marked 等业务依赖。这些是新应用各自写的部分。

## 三、变量化与改名方案

cc-bridge 里产品标识散落在 7 处，壳子用「占位符 + rename 脚本」收敛：

| 位置 | 内容 | 壳子处理 |
|---|---|---|
| `src-tauri/Cargo.toml` | `name = "cc-bridge-desktop"` | 占位 `my-app-desktop` |
| `src-tauri/tauri.conf.json` | productName / identifier / title / updater endpoints / pubkey | 占位 + 注释标记 `<!-- RENAME -->` |
| `desktop/package.json` | name / version | 占位 |
| `src-tauri/src/branding.rs` | APP_DISPLAY_NAME | 占位 + 改名说明 |
| `src/lib/about.ts` | APP_INFO.name | 占位 + 改名说明 |
| `scripts/generate-updater-json.mjs` | FALLBACK_OWNER / FALLBACK_REPO | 占位 |
| `.github/workflows/build.yml` | secrets 名沿用 `TAURI_SIGNING_PRIVATE_KEY` | 注释说明 |

**新增 `scripts/rename-app.mjs`**（一条命令改 6 处）：
```
node scripts/rename-app.mjs --name "我的应用" --id "com.example.myapp" --repo "user/my-app"
```
依次改写：Cargo.toml name、tauri.conf.json（productName/identifier/title/endpoints）、package.json name、branding.rs、about.ts、generate-updater-json.mjs 的 owner/repo。**pubkey 不改**（新应用必须自己生成密钥对，README 写步骤：`npx tauri signer generate`）。

> 2026-10-27 修正：壳子 tauri.conf.json 的 pubkey 实为一个**一次性测试密钥对**的公钥（非 cc-bridge 密钥、非占位串）——因为 `tests/update_flow.rs` 集成测试要从配置里读一个**可解析的** minisign 公钥才能跑通；同时保留 `dangerousInsecureTransportProtocol: true` 联调开关（本地 http 源，Layer 1/3 需要）。两项都必须在发布新应用前替换/删除（README 快速开始第 4 步有说明）。

## 四、复制即用流程（新应用启动 5 步）

```bash
# 1. 复制壳子（不带 git 历史）
cp -r desktop-app-shell my-new-app && cd my-new-app

# 2. 改名（6 处一次改完）
node desktop/scripts/rename-app.mjs --name "MyApp" --id "com.me.myapp" --repo "me/myapp"

# 3. 生成自己的更新签名密钥对，pubkey 填进 tauri.conf.json
npx tauri signer generate -w ~/.tauri/myapp.key
# （私钥存本地/CI secrets，公钥贴 tauri.conf.json plugins.updater.pubkey）

# 4. 装依赖跑起来
cd desktop && npm install && npm run dev

# 5. 写业务：在 src/components/tabs/ 加新 Tab（照 HomeTab 示例），
#    后端在 src-tauri/src/commands/ 加 _cmds 模块 + mod.rs 声明 + pub use
```

## 五、更新架构在壳子中的完整形态

```
开发期                      发布期                      用户期
──────                     ──────                      ──────
改代码                       npm run release -- --minor   启动自检 / 24h 定时检查
CHANGELOG 追加 [Unreleased]   → 版本真源同步               ↓ 有新版
                               → 门禁(cargo test/clippy)   UpdateContext: checking
                             → commit/push/tag            ↓ available → 更新弹框
                             → CI: build-macos            用户点安装 → downloading(进度/速率)
                             → CI: build-windows           ↓ ready → 8 秒可撤销自动重启
                               → updater.json 合并          relaunch
                               → Release attach
                                 (安装包 + updater.json + notes)
```

壳子保留这条链的**全部 9 个脚本/job**，包括这些血泪换来的细节：
- 版本号只有一个真源（Cargo.toml），另两处脚本同步，禁止手改
- updater.json 跨平台合并（防 mac/win 互覆导致对方用户静默失去更新）
- 缺 .sig 签名直接构建期 fail，不发带病版本
- 错误分类码 + 友好文案映射（不靠 `includes("fetch")` 猜原因）
- 自动检查失败不弹 toast（公司网络封锁 GitHub 时降噪）
- 安装完成给可见可撤销的 8 秒重启窗口，不是无限期"请重启"

## 七、风险与注意点

1. **Cargo.lock / node_modules / target 不进壳子**——复制后由新应用 `npm install` + `cargo build` 重新生成，否则锁定的还是 cc-bridge 的依赖解析。
2. **签名密钥**：壳子的 pubkey 是**一次性测试密钥**（让集成测试开箱可跑）。新应用必须 `tauri signer generate` 自己的密钥对，私钥进 CI secrets（`TAURI_SIGNING_PRIVATE_KEY`）。**不要**沿用 cc-bridge 的密钥，也不要拿测试密钥发布真包。另记得删除 `dangerousInsecureTransportProtocol` 联调开关。
3. **更新端点**：rename 时 endpoints 改为新 repo 的 GitHub Releases 地址；国内分发再叠 gh-proxy 镜像（壳子保留双 endpoint 数组范式）。
4. **组件体量门禁的 BASELINE**：check-component-size.mjs 里的棘轮基线要清零（壳子里所有文件直接合规）。
5. **图标**：壳子带一套占位图标，README 写替换清单（icons/ 全目录 + nsis 位图）。
6. **cc-bridge 的 CLAUDE.md 规则**按相关性裁剪移植（版本真源/构建前询问/设计稿先行/门禁），去掉 MCP、SSH、CC 业务条款。
