# 全软件性能与内存审查（2026-11-08）

本报告审查当前工作区，包含尚未提交的搜索及数据库改动，不能等同于已发布版本。只做代码审查，未修改实现，未重新运行性能压测。A 表示代码直接确认存在开销或缺口；B 表示机制已确认、实际影响待测。没有把“可能卡顿”写成已经测到卡顿，也没有把缓存或子进程的存在直接认定为泄漏。

轻量化目标应落实为：交互线程不承担长任务，内存与并发有预算，慢任务有进度、取消和资源回收。磁盘、网络及服务端工作不可能保证任意场景瞬时完成；需要防止它们拖住界面。分级：高＝可产生大规模前台工作或明显内存峰值，优先 P1；中＝特定规模/路径下重复开销，P2；低＝小规模累计开销，P3。暂未取得足以判定必须立即停用的 P0 证据。

## 已检查但不应重复认定为缺陷

- 数据库结果：已有行列虚拟化、结果内存预算、筛选 Worker、短期复用和5秒释放；不能再列成“每次全量 DOM”“Worker 永不释放”。剩余风险是比对等旁路。
- 搜索包：已有串行建包队列、LRU、多根磁盘份数控制；应修复单包与峰值例外，而非报告为“完全无缓存上限”。源代码注释中的过往速度数字未在本轮复测。
- 文件：常规命令已通过 spawn_blocking 执行磁盘工作；不能仅凭 fs::read 就断言阻塞 UI。编辑器读文件有10MB限制，本地历史有文件数/总字节预算。
- 日志：useServerLog 已按可见性关闭、空读取指数退避；本地历史清理定时器有卸载回收。没有证据认定这些定时器泄漏。
- CFR 子进程超时已有 kill+wait，桥接也有 kill/wait；剩余是并发、输出预算和极端失败路径验证。
- 元数据画布已裁剪节点；搜索结果尚无相同层次的 DOM 虚拟化。两者不能混为一谈。
- 安装/开发占用：先前门禁提示的 target/debug 十几 GB 是开发产物磁盘占用，不是发布应用运行内存，不应混进运行时内存结论。

## 验收与排期

建议 P1：01–08；P2：09–16；P3：17–18。同一根因合并实施，例如启动调度、后台预算和多进程总内存预算一起设计，避免各模块分别扩容。

每项验证至少记录：场景、数据规模、冷/热缓存、机器配置、版本/工作区差异、P50/P95、峰值及回落后内存。基准必须覆盖首次运行、长时间空闲、跨工作区切换、连续取消重试、慢网/断网、慢盘、大文件、多窗口/多标签和多任务叠加。

建议目标（待按最低支持机器校准）：常见点击到可见反馈 P95 ≤100ms；前端任务尽量不超过50ms，超出必须拆分/移出主线程；单项耗时超过1秒提供进度与取消；后台任务不抢占首屏；每个缓存有字节预算和压力降级；重复20轮打开/关闭/取消后内存不随轮次持续线性增长。不能用“关闭后立刻回到原始 RSS”代替泄漏判断，应结合 GC、分配器保留和 retained heap。

此清单是当前代码确认及待测风险的审查结果，不是“已经发现所有可能问题”的证明。未在本轮取得全进程堆快照、CPU采样、磁盘ETW和真实网络分段记录，因此实际严重程度需用上述验收补齐；尤其不能把外部 SQL、编译和全工程索引的必要耗时一概归为卡顿。
