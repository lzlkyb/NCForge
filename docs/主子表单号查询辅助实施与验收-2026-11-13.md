## 使用方式

在已连接的 Oracle 数据库 SQL 编辑器中，新语句输入任意单据主表的表名，或已加载的中文表名。补全列表显示“主表名称 · 按单号关联 关联表名称”，选择需要的子表后生成 SQL。以下为采购订单示例，表名和关联字段均来自当前库元数据：

```sql
SELECT a.*, b.*
FROM po_order a
LEFT JOIN po_order_b b
    ON a.pk_order = b.pk_order
WHERE a.vbillcode = '';
```

光标停在最后一行的两个单引号之间。用户手工输入单号，例如 `ASSCG2026110800000005`，再通过原有执行按钮或 `Ctrl+Enter` 查询。选择模板只插入 SQL，不自动执行，也不增加单号输入框或参数弹窗。关键词大小写沿用编辑器设置。

在已有语句的 WHERE 条件位置，也可选择“单据号过滤 · 填写单号”，插入当前表别名限定的 `vbillcode = ''`，并将光标放进引号。

## 关联范围与降级

- 所有单据使用同一套规则，不再包含采购订单或其他单据的固定表名、主键配置。关系来源为数据库显式外键或 NC 类引用；不根据 `_b` 后缀或同名字段猜关联。
- 关联模板要求当前 schema 存在两张表，输入的主表存在 `vbillcode`，关系两端的所有字段均已读到。支持不同名称的两端字段及复合键；NC 引用可在没有数据库外键时提供关系。
- 输入的表固定为 `a`，所选关联表为 `b`；正向和反向引用都按元数据的字段对应关系生成 `LEFT JOIN`。入向引用优先展示；标签称“关联”，避免把普通档案引用误称为业务子表。
- 多个子表分别列出候选，每条 SQL 只连一个关联表，避免多子表互相乘行。同一关系的重复证据去重，同一张表的不同关联条件保留，并在候选说明中显示条件。
- 关系缺失、关联表或字段不可读取时，只要主表单号字段可确认，就提供“按单号查主表”，采购订单也遵循这条规则。主表单号字段不可确认时，不提供单号模板。
- 其他普通表如有 `vbillcode`，可提供主表单号模板。完整语句模板当前接入已连接 Oracle 的普通表补全路径；需引用或保留字表名仍使用原有补全。
- 读取字段复用既有缓存、两路读取门控、等待预算和连接/schema 过期检查。每次最多处理 8 条关系；元数据与字段读取共用原有时间预算，延迟数据可通过再次触发补全读取。切换 schema 后不插入旧上下文的模板。
- 保留普通 SELECT 等默认候选；中文精确表名优先于中文前缀匹配。FROM 位置仍补全表名，已有语句和分号不被覆盖。
