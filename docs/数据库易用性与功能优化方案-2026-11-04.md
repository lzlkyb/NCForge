# 数据库易用性与功能优化方案

日期：2026-11-04。用户已授权实施全部 A / B / C 批次，三阶段代码已接入；本地逻辑、JDBC 契约和模拟 IPC 浏览器验收记录见 [数据库优化实施验收](数据库优化实施验收-2026-11-04.md)。未连接真实业务库。

## 方向

优先缩短「找表 → 筛选 → 查看 → 复制 → 核对改动」的操作路径，再增加 NC 现场排查能力。沿用当前工作台与柔光玻璃外壳，SQL 和数据表继续使用清晰的阅读底色。

## 已有基础

当前已提供多连接、环境标识、NC prop.xml 导入、表与字段中文名、对象收藏、表名及字段补全、SQL 格式化、执行历史及失败搜索、SQL 片段、执行计划及前后对比、结果虚拟滚动、排序、当前结果筛选、CSV/TSV/INSERT 导出、按值反查、表数据编辑与 SQL 预览、事务提交与回滚、会话与锁、脚本回放。

本方案在这些能力上补全操作路径，不重复建设历史、收藏、执行计划和普通导出。

## 第一阶段：每天都用得上的交互

### 1. 表与对象快速定位

新增「查找数据库对象」入口，复用连接树的数据、缓存和 NC 中文名。支持表名、中文名与拼音首字母，展示所在连接和最近访问项。键盘选择后可打开数据、结构或插入表名，快捷键纳入现有可配置快捷键系统。

保留连接树筛选；快速定位用于跨越庞大对象树，默认限定当前连接，不为搜索自动连接所有库。

验收：无需展开连接树即可打开已知表；同名表明确显示连接；缓存尚未完整加载时说明搜索范围。

### 2. 可视化条件与常用筛选

表页在现有 WHERE / ORDER BY 基础上增加条件编辑：字段中文名、运算符、值、AND/OR、排序。支持等于、包含、区间、为空；日期和数字使用对应输入方式。条件可生成参数化查询并展示 SQL；复杂手写 WHERE 保留高级模式，无法解析时不强行转换。

按连接与表保存常用筛选。检测到对应字段时提供 NC 快捷条件，例如未删除 `dr = 0`、组织、编码、更新时间；不假定每张表都有这些字段。

验收：已知编码或组织条件无需手写 SQL；刷新可恢复保存的条件；条件值不会直接拼接成 SQL。

### 3. 结果表格的局部操作

在当前单元格选择与整批复制基础上增加矩形选区、Shift 扩展、整行/整列选择和选区复制。提供列隐藏、列顺序、固定关键列、自动适应列宽，并按连接/对象保存布局。保留现有 CSV、TSV、INSERT、IN 列表输出，增加「选区」「当前显示」「整条查询」的明确范围。

第一版只做选择、复制与布局，批量粘贴写入另行评估。

验收：选择 3 行 2 列后 Ctrl+C 仅复制该区域；虚拟滚动、排序、筛选后仍指向正确的原始记录；复制及导出范围一眼可辨。

### 4. 统一连接与执行上下文

SQL 页和表页共用简短的上下文条，显示连接名、环境、用户及数据库/Schema。生产环境使用已有标识；细节按需展开。执行范围明确显示「选中 SQL」「当前语句」「整个脚本」，避免依赖悬停提示。

SQL 标签的独立事务和表页的共享事务分别说明，结果保留来源连接、SQL 与读取时间。连接切换后的旧结果处理沿用现有逻辑。

验收：不打开连接下拉框也能确认目标库；在两个同名表标签间切换可分辨环境；当前标签的提交入口不误指另一条会话。

## 第二阶段：更方便核对与排错

### 5. 数据修改复核

在现有单元格编辑、预览 SQL 与写回基础上增加修改面板，逐行显示主键、字段、原值和新值，允许逐项撤销，明确待写回行数。写回前检查记录是否已被其他人修改，发现冲突时展示差异，由用户选择重新读取或处理冲突，默认不覆盖。

实现需结合实际主键、字段类型与数据库能力。批量失败反馈区分已提交、未提交、尚未执行，不改变现有事务的边界。

验收：能查看并撤销单项改动；模拟并发修改不会静默覆盖；部分失败后明确哪些操作可回滚。

### 6. 查询结果快照与对比

增加「固定为对照」和「与对照比较」，保留 SQL、来源库、读取时间和已取数据。按用户指定且唯一的键比较新增、删除与字段变化；重复键先提示，不能按行号假定两次结果对应。

第一版比较两份查询快照，后续再扩展跨库表结构/DDL 对比。查询快照对比与现有执行计划对比是两项能力。

验收：明确显示比较范围；只取到部分数据时不能声称完成全表比较；不同排序不造成误报。

### 7. 错误恢复与只读查询模式

在现有错误说明、执行计划与停止操作基础上，让错误项提供对应下一步，例如定位 SQL 行、打开表结构、查看阻塞会话或重新连接。不会默认自动重放写操作。

增加显式只读查询模式时，优先使用数据库账号权限与驱动/数据库会话能力，覆盖独立 SQL 会话和实际执行通道。前端关键词拦截不能作为只读保证；连接的实际能力无法验证时应明确说明。

验收：常见错误可直接进入下一步；重新连接不会悄悄重新执行 UPDATE；只读模式的执行通道一致。

## 第三阶段：NC 专用排查

### 8. 关联数据与元数据定位

结合数据库外键及 NC 元数据引用关系，从 `pk_org`、物料主键、主子表字段等打开关联记录。优先提供明确的引用关系，不仅凭字段名猜测；没有元数据或权限时保留普通查询入口。

展示字段中文名、引用对象和业务枚举。利用现有按值反查，把查找结果连接到表页，并保留向前/返回的路径。代码与元数据的进一步联动复用现有工程索引，先做可确定的跳转。

验收：可从一条已知主表记录打开对应子表或引用记录并返回；未知关系不伪造链接；权限不足不会阻断原有数据浏览。
