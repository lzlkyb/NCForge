# 版本控制页面全面升级方案

日期：2026-11-04。状态：A、B、C 已实施并完成本地前端与 SVN 仓库验收。最终结果见《版本控制页面升级实施验收-2026-11-04.md》。

优先流程由用户确定：查看差异 → 审查 → 提交。兼顾冲突、历史追溯及 NC 补丁打包。以下保留确认时的设计与技术边界；最终验收已覆盖真实前端的 12 种布局组合、固定版本历史、准确逐行追溯及实际冲突副本。

## 方向

把版本控制页升级为连续的审查工作台：选文件、读差异、标记审查、加入本次提交、填写说明、检查结果，都围绕同一个工作副本和提交草稿完成。

沿用柔光玻璃外壳、深青强调色及现有字体、圆角和动效 token。文件清单、差异正文和提交说明使用稳定的实色阅读面。用连续分区和清晰层级组织内容；当前选中、已审、已勾选提交分别表达。

默认仍是文件清单与差异两栏，提交区按需展开。视口足够宽时提交区可停靠右侧；空间不足时使用抽屉或独立步骤，保留差异状态和草稿。适配以实际内容区宽度为准，并覆盖 1280 / 1024 / 560px 窗口及舒适密度。

结构示意：

```text
工作副本 / 仓库路径 / 本地版本     刷新  更新  打包补丁  更多
全部 · 未审 · 已审 · 冲突        本次已选 N 个 → 准备提交
┌ 文件清单 ─────┬ 差异工作区 ──────────────┬ 提交区（按需） ┐
│ 搜索 / 排序   │ 路径 / 状态 / 阅读选项   │ 提交说明       │
│ 模块分组      │ BASE ↔ 工作副本          │ 已选文件       │
│ 状态 / 已审   │ 单双栏 / 上下差异块      │ 警告与检查     │
│ 提交勾选      │ 历史 / 逐行追溯          │ 提交 N 个文件  │
└─────────────┴──────────────────────────┴───────────────┘
审查进度 · 已选数量 · 扫描时间 · 运行任务
```

## 当前基础与具体缺口

已有能力继续复用：模块分组、本地搜索与排序、构建产物隐藏、审查标记、Monaco 双栏/内联差异、差异块导航、历史分页、撤销与冲突备份、全局运行任务。

| 当前代码中的问题 | 对使用者的影响 | 处理建议 |
| --- | --- | --- |
| `SvnReview` 在提交时用 `CommitPanel` 替换差异；选文件又关闭提交视图 | 核对文件与填写说明相互打断 | 差异与提交区共存，查看文件不结束提交草稿 |
| 说明与勾选集合存在提交组件内部；关闭或切补丁会卸载组件 | 回来需要重新填写和选择 | 按工作副本保存草稿，失败或导航保留，成功后只移除本次提交项 |
| 提交清单部分选中时文案是“全不选”，动作却补成全选 | 点击结果与预期相反 | 使用原生复选语义、半选态和分别明确的全选/清空动作 |
| 提交面板刷新会自动选择新出现的文件 | 本次提交范围在后台变化 | 首次保留现有默认全选习惯；草稿建立后新文件默认未选，并明确提示 |
| 审查下一个使用原始文件顺序，不采用筛选/排序后的顺序 | 跳到隐藏文件或不按屏幕顺序移动 | 基于当前可见队列导航；到末尾提供明确完成状态 |
| 已审标记主要靠名称弱化；文件行与提交行缺少勾选语义 | 难以辨认已审、当前查看和准备提交 | 分离当前高亮、审查图标和提交复选框，补齐键盘与读屏语义 |
| `Ctrl+Enter` 提交没有 IME 防护 | 组合输入时存在误触提交风险 | 加入组合输入保护和同步防重入，真实提交期间冻结本次快照 |
| 差异块数量与导航只依靠异步计算结果，按钮边界反馈较弱 | 无差异、计算中与首末块的行为不清楚 | 区分读取、计算、无差异和已就绪，边界按钮禁用并显示实际定位 |
| Blame 将 HEAD 作者信息配到工作副本正文 | 本地增删或改行会产生错误归属，现有警告不足以修正数据 | 后端返回同一实际 revision 的正文与逐行信息，再展示；过渡期不展示不一致的行级归属 |
| 冲突只提供使用我的/服务器内容；历史只有说明列表 | 缺少实际内容核对和版本追踪闭环 | 后续补冲突版本预览、保留手工合并结果、历史版本差异与改动路径 |

## 页面与交互升级

### 1. 上下文与工具条

- 仓库 URL、工作副本路径、用户名、凭据来源与连接状态集中到可展开的上下文区域。明确显示“本地工作副本 rN”；没有查询远端时不声称已同步或领先/落后。
- 刷新、更新和“准备提交”常驻；撤销、维护与不常用动作进入更多菜单。标题栏与底部只保留必要的状态，减少重复文案。
- “审查改动 / 打包补丁”在侧栏收起后仍可切换。补丁模式名称与状态明显，避免把生成补丁误认为提交仓库。

### 2. 文件清单

- 搜索增加清除按钮，支持路径、文件名和模块；筛选加入未审/已审，保留状态数量与构建产物显示开关。
- 一行呈现状态、文件名、审查状态、提交复选框；目录和修改时间作为次级信息，完整路径通过提示与复制获得。同名文件能区分。
- 单击查看差异；复选框只改变提交范围；双击打开代码。方向键选择、Space 切换提交勾选、Enter 查看、上下审查与快捷键保持一致。
- 模块支持全选、半选、清空，以及仅选已审文件。筛选只影响显示；跨筛选的已选数量常驻，提供“查看已选”避免隐藏选择。
- 展开状态、筛选、排序和滚动位置按工作副本记忆。大量条目使用必要的虚拟化，先用真实规模测量再决定，避免引入额外复杂度。

### 3. 差异工作区

- 文件标题、完整路径入口、状态、BASE/工作副本来源和新增删除统计清晰分层。文字与颜色一起表达 M/A/D/C 等状态。
- 常用操作保留单/双栏、上一处/下一处、标记已审、加入提交、打开代码；历史和“逐行追溯”作为清晰的次级视图。
- 增加忽略空白差异、换行显示与阅读字号选项；忽略空白默认关闭。阅读偏好按工作副本保存，并明确说明当前比较来源。
- 读取新文件时显示目标文件的局部骨架/状态；若保留旧内容，明确标明其来源并禁用可能误操作的动作。慢结果不能覆盖后来选择的文件。
- 差异编辑器保持只读，切换阅读选项不重建实例；从代码返回可恢复差异滚动与当前块。删除文件展示 BASE 删除内容，新文件展示新增内容；二进制、缺失文件和编码异常使用对应说明。
- 审查完成后提供“准备提交已审文件”或继续查看，失败时保留当前项。未审允许提交，但数量与范围明确，不把审查当作强制审批。

### 4. 提交流程

- 提交说明、已选清单与差异同时可用。草稿按工作副本隔离，更新、切页、账号验证失败或服务器错误后仍保留。
- 支持按模块整理清单、查看已选、移除单项和只选已审。新出现的文件、冲突项、缺失项和构建产物有明确状态，不静默扩大提交范围。
- 提交前核对选中文件在编辑器中的未保存修改：选择保存后继续或明确提交磁盘版本；保存完成后重新验证所选范围。提交读取的是磁盘，不暗示包含尚未写盘的内容。
- 对本次文件集合和说明建立不可变快照，阻止重复请求与同期改写工作副本；重新扫描不把新文件自动加入该快照。
- 显示读取/预检、服务器提交、刷新状态三个实际阶段。服务器确认 rN 后即明确成功；刷新失败单独说明并提供刷新入口，不能误报提交失败或自动重放提交。
- 网络超时而结果不明时显示“提交结果待确认”，保留草稿并引导查服务器历史；确认前不提供会重复提交的自动重试。
- 成功后显示 revision、文件数量、提交说明及后续入口。支持继续审查剩余项；补丁流程不默认沿用已提交前的旧清单。

### 5. 历史、追溯与冲突

- 历史可切当前文件/模块/工作副本，提供作者、日期、说明搜索。只筛当前已加载分页时明确范围；全仓历史检索需后端支持。
- 选中 revision 可查看真实改动路径、前后版本差异及完整说明；支持复制版本号和路径。指定版本读取要处理该版本尚不存在、已删除或移动的路径。
- 逐行追溯必须让正文、作者和 revision 一致；点 revision 可进入对应提交，作者筛选和定位行为基于这份固定版本。
- 冲突集中展示数量与队列，先提供我的/基线/服务器实际内容预览。后端返回真实冲突版本，不能用本地 BASE revision 猜服务器版本号。
- 增加“使用手工合并后的工作副本”流程：检查文本标记、保留文件备份后解除 SVN 冲突。树冲突与二进制冲突单独处理；完整三路合并编辑器作为后续扩展，不在初期与主流程一起堆入。
- 撤销和解决冲突的结果保留备份入口；仅有备份文件时提供打开备份，正式一键恢复需要后端路径校验和恢复命令。

### 6. 动效、等待与响应式

- 复选、选中、按钮 pressed 与 focus 立即反馈；局部视图与抽屉采用既有约 150–200ms token，支持减少动态效果。代码与终端画布不加位移动画。
- 初次扫描显示结构占位与真实已扫描条目数，刷新保留旧清单并标注更新中。没有总量时不伪造百分比或剩余时间。
- 网络动作持续显示实际阶段与全局任务入口；错误说明应区分认证、锁定、过期、网络及结果未知。只有后端真正支持取消的动作才显示停止。
- 窄屏切换清单/详情时保留选择、草稿和返回位置；抽屉关闭恢复焦点，菜单不被滚动容器裁切。舒适密度提高点击区域与文字可读性，辅助信息按优先级收起。

## 实施阶段与验收点

| 阶段 | 交付内容 | 验收点 |
| --- | --- | --- |
| A：正确性与连续流程 | 半选/全选语义、IME 与同步防重入、可见队列审查、草稿隔离、固定提交快照、保存预检、Blame 错位止损 | 部分勾选按钮行为正确；切文件/页/补丁不丢草稿；刷新新增文件不入选；按当前筛选顺序审查；重复点击只发一次请求；不显示不一致的逐行归属 |
| B：主页面全面升级 | 上下文区域、文件行、差异工具条、提交抽屉/停靠、阅读偏好、局部状态、键盘与窄屏 | 1280/1024/560 × 明暗主题 × 标准/舒适密度可用；清单/差异/提交数量一致；慢读取不串内容；无裁切与焦点丢失；差异编辑器正确释放模型 |
| C：历史与冲突闭环 | 指定 revision 内容、改动路径、同版本 Blame、冲突实际内容预览、保留手工合并结果；补丁衔接 | 历史正文和作者来源一致；冲突采用实际版本号；手工结果不被覆盖；备份可定位；提交后补丁读取实际当前状态 |

建议顺序：A → B → C。A 与 B 完成后即可交付日常审查和提交体验；C 需要扩展 SVN 桥的数据契约并做真实服务器联调。

## 技术边界

- 前端主要涉及 `SvnReview`、`ChangeList`、`DiffPane`、`CommitPanel`、`SvnToolbar`、`svnSession` 与现有 hooks。复用全局任务、Menu、Modal、布局与主题系统。
- 同版本 Blame、指定 revision 正文、历史改动路径、冲突内容及“保留工作副本并解除冲突”需要 SVN 后端/Java 桥扩展，不能通过更换 UI 标签实现。
- 工作副本写操作共享同步锁，跨页仍有效；所有草稿、缓存、任务与异步结果按工作副本和会话隔离。切工程不允许旧结果修改新工程状态。
- SVN 采用文件级提交，不引入 Git 暂存区或逐块暂存概念。选择文件表示本次提交范围；既有批量扫描策略继续按需执行，筛选、勾选和阅读选项不触发全量扫描。
- 补丁目前基于未提交改动。按已提交 revision 出包属于新增后端能力，需单独确定输入、编译产物与删除清单规则，不能把提交后的空清单当作发布包。
- 验证以行为回归、前端类型/构建、token/UI/组件/命令门禁、有限轮次视觉检查及真实 SVN 场景组成。真实认证、网络中断、提交结果不明、更新冲突及编码混用需要服务器环境，模拟测试只证明前端分支与状态行为。
