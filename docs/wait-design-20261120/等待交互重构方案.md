# NCForge 轻量等待反馈方案

2026-11-20 · 设计评审稿

[交互设计稿](工作台等待设计稿.html) · [导出估时](01-结果导出.png) · [慢查询](02-慢查询.png) · [确认停止](03-停止确认.png)

**正常操作时，进度只占现有工具栏的一行。切到别处后，底栏用一个“任务”入口承接。详细进度、记录和停止操作由用户主动打开。** 编辑中的输入、选区和页面布局不随后台进度更新。

## 从成熟软件采用的做法

| 公开资料 | 做法 | 在 NCForge 的应用 |
|---|---|---|
| [VS Code 状态栏](https://code.visualstudio.com/api/ux-guidelines/status-bar)及[通知指南](https://code.visualstudio.com/api/ux-guidelines/notifications) | 后台进度适合简短的状态栏项，优先在相关视图或编辑器显示。全局通知用于需要用户关注的情况。 | 查库写在结果工具栏，搜索写在搜索栏，其他页面统一从底栏找任务。少用颜色、图标和常驻元素。 |
| [IntelliJ IDEA 界面指南](https://www.jetbrains.com/help/idea/guided-tour-around-the-user-interface.html) | 状态栏显示过程进度，主动点击可打开 Processes manager。 | 只有用户点击时才显示任务列表和详情。任务入口可返回编译、数据库或服务的来源位置。 |
| [Nielsen Norman Group 响应时间研究](https://www.nngroup.com/articles/response-times-3-important-limits/) | 短操作直接响应，稍长的操作给低干扰反馈，长操作让用户判断还要等什么并提供适当的中断方式。 | 耗时增加时更新短句的信息量，界面尺寸和焦点保持稳定。具体阈值用 NCForge 操作回放校准。 |

## 展示位置和干扰边界

| 时机 | 界面行为 |
|---|---|
| 点击开始 | 按钮立即回应。约 300ms 内完成直接出结果，避免只闪一下的等待提示。300ms 是初版防闪参数。 |
| 仍在进行 | 原工具栏留一个固定高度的短状态区域，原型高度为 26px。例如「导出 64% · 约 20–30 秒」。窄窗口先保留阶段和任务按钮，完整状态由详情提供。 |
| 等待变长 | 同一位置更新成「等待开发库 · 已用 36 秒」。继续保留旧结果，清楚标注“上次结果”。没有返回事件时可显示“尚未收到新进度”。 |
| 开始做其他工作 | 在其他页面只看到「任务 · 2 进行中」。任务继续由业务执行方管理。入口靠用户主动打开，支持回到具体文件、连接、任务记录或失败的对象。 |
| 主动查看 | 底栏上方出现紧凑浮层。第一行给阶段，下面给工作量和真实事件，需要时才列细进度条。用 Esc 或点外部关闭，鼠标可继续操作工作区。 |
| 结束或失败 | 普通成功更新原位置并进入最近记录。失败、部分提交或需要确认时，底栏留「1 待查看」，会话内可找回。只有下一步确实需要用户立即选择才在对应入口请求处理。 |

任务进度不自动弹窗、撑开面板、切换页面、抢走焦点、搬动编辑器或滚动结果区。用户点击详情后才转移焦点，关闭时还给触发按钮。操作锁只用于实际冲突，例如同一个写任务不能重复提交。确需排队的请求在对应入口写明正在等待哪项操作。

## 什么时候显示预计时间

- **总量与短期速率可靠。** 下载用已接收字节和近期速率，固定范围导出用实际写入行数和近期吞吐。展示当前阶段的剩余区间。速度波动、事件断流、总量变化时收回区间并保留实绩。写入 100% 后显示「正在完成文件」，收到落盘确认后才显示成功。
- **总量可数，单位耗时差别大。** 模块编译和 SQL 脚本显示「已完成 8/12 · uapbd」或「已执行 6/10 条」。积累可比历史并通过回测后，才考虑提供估时。
- **只能确认阶段。** 单条 SQL、连接、服务启动按真实回执给「请求已发出」「等待开发库」「认证已通过」等状态，以及已用时间。工具栏可以有一个低对比的小圆点缓慢呼吸。随系统减少动效、页面不可见或应用隐藏停止。结果区继续显示上次数据。总量未知但有累计成果时直接显示「已发现 418 个对象」。

首批估时建议用同一阶段最近 5 个有效时间窗计算上下界，至少 3 个非零窗口并覆盖 5 秒后再试显示。参数以回放调优，分别统计区间命中率、实际展示率和区间宽度。可先采用「已展示区间至少 80% 覆盖实际剩余时间」作为试点目标，保留遇到慢速、停滞与尾部收尾的样本。

## 接入全软件的统一规则

| 操作 | 放在哪里，优先露出什么 | 详情或结束 |
|---|---|---|
| 单条 SQL、脚本、加载更多 | 结果工具栏或表尾。单条显示等待时长，脚本显示已处理条数。 | 展开首个失败语句和实际执行结果。结果未知的写操作先核对事务。 |
| 导入、导出、更新与组件下载 | 原按钮所在工具栏或工作流页。总量可靠才显示比例与估时。 | 保留已提交、已回滚、已保存的结果。停止请求发出后仍等待执行方确认。 |
| 构建、热替换、服务与语言服务 | 构建输出或服务状态处。优先显示模块、阶段或最近回执。 | 首个诊断、最近日志、产物位置。区分构建成功、热替换成功和服务已就绪。 |
| 工程索引、表树、连接与元数据 | 当前树节点或连接工具栏。首次空白可用贴合几何的静态占位，刷新保留旧内容。 | 按真实事件报告发现数量、错误来源和缓存时效。 |
| 搜索、替换与 SVN | 当前搜索栏或版本控制工具栏。显示命中、已扫范围或最近处理路径。 | 取消保留已发现项并标出不完整；写入类只报告已确认改动和冲突。 |
| 设置保存、日志加载与诊断刷新 | 对应字段、日志尾部或面板标题。 | 保存失败保留输入，日志刷新保留阅读位置。 |

同一任务在来源和底栏共享现有任务状态，终态由实际业务回执决定。详情可以带任务记录、打开结果、失败诊断和适用的停止入口。等候期间愿意多看一步的用户可以展开真实日志、已返回的数据或任务记录。频繁进度更新只刷新状态区域，读屏只播报关键阶段和终态。

## 实施和验收

1. **试点三条路径。** 资源下载试真实速率估时，单条 SQL 试未知等待和旧结果留存，批量导入试部分提交和停止回执。先打通就地短状态和底栏入口，再接详情。参考[任务状态](../../desktop/src/lib/operations.ts)、[下载读数](../../desktop/src/components/resource/ResourceDownloadReadout.tsx)和[导入反馈](../../desktop/src/components/db/ImportProgress.tsx)。
2. **迁移导出、编译和其他长任务。** 接入同一任务状态，按业务能力记录阶段、取消和返回来源。逐项移除重复的转圈与完成提示。使用并发任务、乱序回执、断线、总量修订、隐藏窗口和异常写入做回归。
3. **把无干扰作为交付条件。** 输入、滚动表格或切换标签时注入进行、成功和失败事件，验证编辑器实例、焦点、光标选区、滚动位置和工具栏高度保持稳定。键盘可进入详情并关闭。减少动效仍可辨别阶段。现有输入与切页性能预算继续适用。

评审稿用四种模拟任务展示布局与交互。多个并发任务的统一入口、真实回执和估时准确度由生产接入验证。

## 实施与验收记录

已接入工作台的常驻底栏任务入口。现有任务状态中的搜索、SVN、服务、元数据等任务共用这个入口。文件读取反馈移到底栏。手动编译开始、完成与失败时保留用户所在面板，并在任务记录中提供返回构建输出的入口。

SQL 查询只更新结果工具栏。单条重跑保留旧数据和旧标签，直到新结果返回。批量导入显示已确认提交的数量，可以转到后台。停止请求发出后继续等当前批回执，结果保留已提交数量。组件下载、软件更新和已知总量的结果文件导出使用实际阶段吞吐估时。组件下载开始后留在原页面，下载详情由用户打开。

前端全量测试 601 个文件、4449 项通过。最终相关回归 91 项通过。Edge 上验证了慢查询草稿、光标、结果区几何与标签数量，确认跨页完成不弹详情。在 560px、1024px、1280px 窗口验证任务入口及浮层的深浅主题和减少动效。

生产前端构建通过。含 3000 个文件节点及 30 个标签的模拟工程中，P95 文件切换 96.6ms、页面切换 142.3ms、输入回显 44.6ms，分别在 100ms、150ms、50ms 预算内。60 次切页前后 DOM 节点与监听器数量相同。复测使用模拟后端，实际内网下载和真实数据库上的估时区间仍需现场校准。
