# 代码工作台布局深化方案

日期：2026-11-06。阶段：P0/P1 已实施，生产前端验收结果见 [实施验收](./代码工作台布局深化实施验收-2026-11-06.md)。用户批准推荐 B，并明确本次直接实施、不制作设计稿。范围为代码工作台的文件树、编辑器、搜索、问题、编译输出、服务、调试和状态栏。沿用浅深双主题与柔光玻璃外壳，正文保持稳定实底。下文保留方案评审时的依据与阶段边界。

## 1. 判断与依据

当前已具备预览标签、拖动排序、所有标签菜单、右侧分屏、类/方法面包屑、可固定结构面板、本地历史、错误内联、问题分组、导航历史、统一运行任务，以及刚完成的服务控制台。这一轮应深化这些能力之间的布局与操作关系。

当前源码可确认的结构限制：

| 位置 | 现状 | 对使用的影响 |
| --- | --- | --- |
| 工作台尺寸 | 侧栏和底部各保存一个全局尺寸；服务页将底部高度提高到至少 360px | 返回问题或编译输出后仍共用这一高度，不同任务的空间偏好难以保留。 |
| 右侧分屏 | 单独一个 splitPath，顶部只有文件名和关闭；光标回调为空 | 分屏作为辅助阅读入口可用，但尚未形成完整编辑器组；状态栏和导航仍跟随主编辑器，右侧编辑时上下文容易混淆。 |
| 文件标签 | 全部标签共用一条标签栏，右边同时放任务菜单与编译按钮 | 多文件时，文件切换与执行操作竞争横向空间；所有标签菜单是逐项列表。 |
| 底部工具 | 问题、编译、服务、调用层级、类型层级、待办、书签、调试八个入口常驻 | 新用户需要辨认全部入口；窄窗口主要通过横向滚动解决。 |
| 导航与提示 | 面包屑、结构、小地图、历史、读取提示、编码和冲突条都在正文上方 | 多个状态同时出现时需要重新安排层级，保护代码阅读高度。 |
| 文件树 | 文件/包视图、结构选项、定位、新建、搜索和工程动作集中在顶部 | 已有能力完整，但动作层级还能更清楚，窄侧栏的图标辨认成本较高。 |

源码依据：[工作台尺寸与停靠](../desktop/src/components/workspace/WorkbenchFrame.tsx)、[编辑器与分屏接线](../desktop/src/components/workspace/FilePaneSlots.tsx)、[文件标签](../desktop/src/components/workspace/TabStrip.tsx)、[底部工具](../desktop/src/components/workspace/BottomPanel.tsx)、[导航](../desktop/src/components/workspace/EditorNavRow.tsx)、[文件提示](../desktop/src/components/workspace/EditorBanners.tsx)、[文件树头部](../desktop/src/components/workspace/TreeHeader.tsx)。

视觉依据为 2026-11-04 代码工作台生产截图、2026-11-06 服务控制台生产截图，并与当前 CSS 核对。上述是源码结构限制与改进机会；分屏操作误用、复杂提示挤压等风险需在实施时做真机复现，不能仅凭旧截图宣称当前版本存在全部缺陷。

## 2. 方向选择

| 方向 | 收益 | 代价 |
| --- | --- | --- |
| A：视觉与工具栏收敛 | 调整层级、密度、控件与提示，改动较小 | 编辑器分组和工具空间分配能力仍受限。 |
| **B：工作流与布局深化，推荐** | 建立编码、排错、调试布局，完善双编辑器组和上下文，保留既有熟悉操作 | 需要调整布局状态、焦点路由与模型接线，必须覆盖保存和跨工程边界。 |
| C：完全自由停靠工作台 | 任意拖放工具、复杂多栏、多组布局自由度最高 | 实现、持久化、恢复与性能成本高，操作学习成本也更高。 |

推荐 B：先完成稳定的双组编辑、可恢复的任务布局和清晰的工具层级，再按真实需求评估自由停靠。

## 3. P0：空间与操作层级

### 3.1 三种可恢复布局

| 布局 | 左侧 | 中央 | 辅助区 |
| --- | --- | --- | --- |
| 编码 | 文件树或搜索 | 单组/双组代码 | 底部工具收起或较矮；结构按需显示。 |
| 排错 | 文件树或问题范围 | 当前文件及错误上下文 | 问题/编译输出适当展开，服务日志可临时展开阅读。 |
| 调试 | 文件树可收起 | 当前栈帧源码 | 宽屏右侧显示变量和监视，底部保留线程/调用栈与控制台。窄屏将这些内容放回工具页签。 |

布局入口复用顶栏“工作台布局”，提供一键恢复默认。分别记忆问题、编译、服务、调试的底部高度；将几何尺寸与工具数据分开保存。用户可以锁定当前布局，调试暂停或编译失败只突出对应入口，不强制改写已锁定布局。

默认首次进入编码页且没有活动任务/问题时，底部展示紧凑入口，不占用整块空面板。用户主动打开后保持选择；读取失败与编译失败不能被自动收起。

### 3.2 文件树与工具栏

- 文件树标题行常驻文件/包视图、定位和更多；新建文件、文件夹、工程切换等按动作归组。
- 展开“快速过滤”时支持文件名与包名过滤，明确过滤范围和清除入口；过滤只影响展示，不修改磁盘内容。
- 编辑器上方保持文件标签与位置导航两层。编译、开始开发等执行操作放在明确的操作区，避免标签数量变化推动按钮位置。
- 面包屑长路径折叠中间目录，保留文件、类和当前方法；结构、小地图、本地历史在窄区收进更多菜单。
- 保留现有 SVN、错误、编译和只读标记；颜色、形状和提示统一，避免同一行出现多种竞争状态的整块底色。

### 3.3 底部与状态栏

- 常驻问题、编译输出、NC 服务、调试；调用/类型层级、待办、书签放入可固定的“更多工具”。打开后在页签条出现，支持取消固定。
- 所有底部工具统一标题、范围、刷新、最大化/恢复和关闭位置；服务已实现的展开能力扩展为公共布局能力。
- 状态栏按“当前文件”“诊断与任务”“运行服务”分区。编码、行尾、光标等归入可点击的文件状态菜单，窄窗口保留未保存、错误、任务和服务状态。
- 常规保存完成用局部短暂反馈；后台自动任务更新原有状态。明确失败和需要决策的状态继续保留，减少重复任务提示。

## 4. P1：编辑器组与阅读深化

### 4.1 完整双编辑器组

将当前右侧辅助分屏升级为两个正式编辑器组：各自标签、活动文件、光标、导航历史与结构上下文；组间可移动文件、交换左右、拖动分隔线与恢复比例。第一版只支持两组。

点击右组后，保存、格式化、查找、跳转、大纲与状态栏全部作用于右组的活动文件；明确显示当前活动组。共享文本模型，同一文件双开时内容和未保存状态同步；关闭组只关闭视图，未保存内容仍走既有守卫。只读 jar、GBK 编码、慢读取和跨工程跳转保留现有保护。

空间不足时提供“切换编辑器组”的清晰入口，临时单组展示并保留另一组状态；不能把两个编辑器长期压到无法阅读。

### 4.2 多标签管理

现有预览“固定”只是将预览转为正式标签。这一轮额外增加长期钉住文件的能力，两种状态在文案与图标上区分。

- 所有标签菜单支持搜索、最近使用和未保存筛选；同名文件显示必要的工程/模块路径。
- 钉住、预览、未保存、只读与活动组状态使用统一标记，完整路径可查看与复制。
- 关闭其他、右侧、已保存保留现有未保存守卫；新增关闭组时先显示影响的文件。
- 支持按当前快捷键方案在最近文件、组间和导航历史间切换，提示文字从键位真源读取。

### 4.3 代码阅读与智能提示

- 结构面板现有固定/抽屉能力继续复用，增加与活动组联动、按名称过滤和键盘定位，保留当前方法可见。
- 错误内联默认显示主要问题的短摘要；完整说明、快速修复和来源按需展开，避免长错误占满代码行。
- 补全、参数提示、悬浮文档和定义预览统一浅深主题、字号、滚动和焦点反馈；优先复用 Monaco 能力。
- 代码智能状态给出当前模块、是否在范围内和可恢复操作；若补全入口实际没有可用结果，区分未就绪、范围外和无匹配，避免干扰正常输入。
- 混合换行、只读反编译、超大文件等说明改为摘要加详情；保存冲突和编码错误保留直接处理动作。

这一部分改善提示可理解性；补全正确率、排序和延迟另以当前代码智能验收集验证，不用布局升级代替引擎质量验收。

## 5. P1：问题、搜索与调试闭环

- 问题页保留现有严重度过滤和按文件分组，增加当前文件/模块/工程范围入口、版本新鲜度及选中项上下文预览。已保存的新版本与旧编译结果不同步时明确显示来源时间。
- 搜索保留已有工程与组件范围，增加可折叠结果、展开更多上下文、键盘连续定位与可记忆的搜索宽度；侧栏不足时可临时展开结果，关闭恢复代码布局。
- 编译输出收敛为模块摘要、问题定位和原始输出三个层次；原文持续输出采用有界缓存与可见区渲染，是否需要升级先量测现有成本。
- 调试宽屏将变量/监视从底部多列中移到右侧检查器；线程和调用栈留在底部。中间件、客户端和远程目标始终明确，继续/单步作用于当前调试目标。
- 编译报错、搜索命中、异常堆栈和暂停栈帧统一定位高亮与后退返回；重复/晚到结果不得抢当前文件和焦点。

## 6. P2：进一步能力

优先评估按工程恢复打开文件、活动组、滚动位置和布局；恢复时验证路径仍存在，未保存草稿需要明确恢复流程，不将源文件全文直接写入 localStorage。随后按实际使用需求增加上下分组、布局预设管理、快捷键引导，以及跨文件引用的停靠预览。

完整任意停靠、四组编辑和独立窗口暂列后续评估，不作为第一轮验收要求。

## 7. 视觉与反馈标准

浅深主题同时实施；玻璃保留在外壳，代码、日志、变量及结果正文使用稳定实底。活动组、选中、焦点、预览、未保存和只读分别可辨认；语义色集中在必要状态，标签不使用大面积告警底色。

常用控件命中区域建议 28–32px，紧凑密度主要减少留白，不压缩点击区域；代码字号遵循个人偏好，界面文字不靠持续缩小应对空间不足。弹层使用 portal，避免被编辑器和侧栏容器裁切。

切换工具及侧栏展开使用约 120–180ms 的短反馈；拖动分隔线实时跟手，编辑器和日志正文不做入场位移；减少动态效果时保留状态提示与焦点。耗时操作沿用已有局部等待与全局任务体系，有真实总量才显示百分比。

## 8. 实施顺序与验收

1. **P0 布局与层级** → 按用户授权直接实施双主题编码/排错/调试布局；验证空面板收敛、工具高度记忆、顶栏与状态栏、窄区行为。
2. **P1 编辑器组** → 验证焦点路由、双开共享模型、分组保存、关闭守卫、路径改名和跨工程晚到响应。
3. **P1 排查闭环** → 验证问题→源码→编译、搜索→预览→返回、断点→变量→日志→源码流程。
4. **P2 恢复与高级布局** → 用户确认需要后实施，不提前增加框架和大型依赖。

核心验收点：

- 1366×768 编码布局中，默认底部不超过约 200px，代码正文目标至少 380px；1024×540 优先收起空工具，正文目标至少 300px。实际阈值在设计稿与生产测量中确认。
- 560px 宽及高缩放等效空间无外部横向溢出，主操作和警告可达；响应式依据可用容器空间，不只看整窗宽度。
- 20 个标签、同名文件、未保存文件和两编辑器组仍能清晰定位；点击右组后所有文件操作对象正确。
- 编译失败、调试暂停和启动失败不会丢失未保存内容；布局恢复后 Monaco 模型、光标、滚动与日志阅读位置保持。
- 几何拖动不在每个 pointermove 同步写配置；隐藏工具不持续轮询，新增列表先测成本再选择虚拟化。
- 最终使用前端生产产物、安装配置 CSP、浅深×玻璃/实色及减少动态效果验收；涉及安装包原生行为再按项目规则安排真机确认。
- 组件/Hook 体量、设计 token、UI 约定、ESLint、TypeScript、受影响测试与本批隔离体积预算均过门禁；分组模型、保存和旧响应等重要逻辑编写回归测试。

P0/P1 已直接实施，包含正常编码、多标签双组、编译失败、调试暂停和小窗口场景。P2 的跨启动工程会话恢复、上下分组和任意停靠保留为后续独立阶段；体积门禁与真实 NC、安装包验收边界见实施验收记录。
