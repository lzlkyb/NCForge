# 元数据 UI 第一阶段实施验收

本记录是第一阶段存档。三阶段累计交付与最终验收见 [后续实施验收](../元数据后续实施验收-2026-11-06/实施验收记录-2026-11-06.md)。

第一阶段生产 UI 已完成：模型、字段表和属性检查器共享选中对象，常用字段在检查器内编辑，多文档切换保留视图状态。相关 25 个测试文件、68 项测试及前端门禁通过，方案指定的 7 组窗口尺寸均完成明暗主题检查。

本轮采用真实 `MetaTab`、`WorkbenchFrame` 和应用样式，浏览器验收的 Tauri 调用使用隔离的内存 IPC。保存只更新示例数据。本记录确认前端交互与构建结果，真实 BMF 读写、原生 WebView 和 Windows DPI 性能仍需实机验收。

## 实施范围

- 联动、模型、字段三种模式；按实际停靠区尺寸调整资源栏、检查器和低高度布局。
- 资源来源分组折叠、模型大纲、多文档标签；按稳定对象 ID 恢复选中、筛选、滚动、缩放和节点位置。
- 字段表固定表头、可见范围渲染；方向键选择、Enter 查看属性、F2 编辑、Ctrl+S 预览保存。
- 检查器分组显示组件、实体、字段、枚举和关系信息；关系端点与校验问题可以定位真实对象。
- 对比、历史、引用、生成中心、导入导出和发布 POC 保留入口，低频工具按需加载。
- 编辑复用 `bmfEditPreview → bmfEditSave(expectedSha)`。编辑期间锁住元数据文档和对象导航，输入变化使旧预览失效，失败保留输入。

没有扩大 Rust 解析和写入语义。业务接口映射、关系多重性、跨字段汇总草稿和批量事务仍属于后续阶段。

## 审查与修复

逐文件复核本批 diff 和新增源码，重点检查异步令牌、保存路径、选中恢复、抽屉焦点与缓存边界。旧 `MetaDetails` 的字段和检查器入口已由联动工作区接替。

已修复的具体问题：

1. 停靠 portal 延迟挂载时，尺寸监听能在真实节点出现后接上，避免窄窗口仍显示宽屏布局。
2. 引用跳转同时切换正确文档与详情；保存后的迟到刷新只更新被编辑文档，关闭后的结果不能复活标签。
3. 已有无数据库列的字段可以原样保留；只改显示名时保留未声明或未知的数据类型样式。
4. 抽屉与停靠模式使用同一棵表单内容树，调整窗口或收起抽屉保留输入。
5. 长表清除筛选后滚回选中字段。新增测试先复现 `scrollTop = 0`，修复后通过，并在浏览器中复验 2000 字段末行定位。
6. 选中来源条目的副标题使用可读前景色；工具页仅在存在编辑检查器时显示属性入口。
7. 生成中心拆分状态 Hook；旧目录的漂移结果不能覆盖新目录，规则校验失败时保留产物预览并禁止落盘。

## 轻量化与性能口径

字段表和来源列表只挂载可见区域及缓冲行；拖动按 `requestAnimationFrame` 合并。没有新增常驻轮询或大型图编辑依赖。

详情缓存最多 6 份，以原文件大小累计约 16 MiB 为预算，优先保留活动文档和最近访问文档。单个超大活动文档允许读取，但不会同时保留其它详情；这个预算不是 JavaScript 堆内存上限。切回缓存文档仍读盘核对 SHA，相同 SHA 可以复用校验结果。

隔离大模型含 50 个实体、2392 个字段，其中首实体有 2000 字段，初始字段表渲染 17 行。拖动 160 次指针事件合并为 40 帧、40 次节点坐标更新；帧间隔中位数约 16.4ms，P95 约 18.3ms。

这组夹具没有关系，测量的是 headless Edge、关闭 GPU、内存 IPC 下的浏览器帧间隔。它证明合帧行为，不能等同于真实工作帧耗时，也不能认定方案的 16.7ms 帧耗时目标已达到。尚无旧版速度对照；100 关系拖动、500 实体、真实 BMF 冷打开/热切换和常驻内存增量仍待性能验收。

### 包体积对照

在隔离目录复制同一份当前源码，升级前仅将本批已跟踪的元数据生产组件恢复为 `244dcc12` 的版本；其它会话源码保持一致。两个快照分别构建，按 gzip level 9 统计，1 KB = 1024 bytes。

| 指标 | 升级前 | 升级后 |
| --- | ---: | ---: |
| 元数据入口 JS 命名块 gzip | 29.05 KB | 27.15 KB |
| 元数据 CSS 命名块 gzip | 5.08 KB | 7.44 KB |
| 全部 JS raw | 4868.67 KB | 4905.30 KB |
| 全部 JS gzip | 1385.02 KB | 1401.31 KB |
| 最大 JS 块 raw（Monaco） | 3171 KB | 3171 KB |

入口命名块统计不包含共享依赖。低频工具拆分后，总 JS 增加 **36.64 KB raw / 16.29 KB gzip**；入口 JS 变小，CSS 增加，不能据此声称全部首屏字节减少。

预算基于本批实测增量向上取整：保留原工作区预算，在总量上增加 **37 KB raw / 17 KB gzip**，得到 4906 / 1402 KB；最大块上限维持 3171 KB。生产构建与隔离构建因路径哈希有数十字节 gzip 差异，生产门禁实测为 4905 / 1401 KB。

Vite 仍提示既有 Monaco 块超过 500 kB。该块的前后大小一致，元数据工具已拆分为独立按需加载块。

完整数值和本批预算变化见 [包体积对照](包体积对照-2026-11-06.json)。
