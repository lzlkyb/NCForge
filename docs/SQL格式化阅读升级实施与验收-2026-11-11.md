# SQL 格式化阅读升级实施与验收

## 结论与效果

保留 sql-formatter 15.9.0 方言引擎，借鉴 DataGrip 的短子句收拢、按宽度折行与独立 JOIN / WHERE 层级，以及 SQLFluff 的列表 fill 思路，实现阅读布局。没有向生产依赖加入 Prettier 或 Python 排版器。

同一份用户原始 NC / Oracle 分页查询：

| 设置 | 实际文本行数 | 最长行 |
| --- | ---: | ---: |
| 结构展开（原默认） | 100 | 101 |
| 阅读优先，120字符，2空格 | 39 | 120 |
| 阅读优先，100字符，2空格 | 46 | 100 |
| 前期人工样例 | 42 | 103 |

默认阅读方式减少61%的文本行数，保留原始字段、混合大小写、别名、括号、分页限制及逻辑顺序。原文中重复使用的 `e` 别名仍原样保留；本轮没有执行或语义改写 SQL。

完整真实输出在 `.codex-artifacts/sql-reading-final.sql`。实测脚本 `sql-reading-final-measure.mjs` 对同一源码布局连续调用6次，观察到34 / 10 / 7 / 6 / 6 / 5ms（不含依赖首次加载）；该数据是本机观察，不是通用性能承诺。原始输入与结果的 token 序列一致，第二次格式化输出不变。

成熟工具的版本、配置、原始输出与结论在 `SQL格式化阅读体验升级方案-2026-11-11.md`，调研脚本和下载依赖只在 `.codex-artifacts/sql-format-research/`。

## 使用与界面

- 设置 → SQL格式化：排版方式默认“阅读优先”；目标行宽默认120，可保存60–240字符。大小写、方言、每级空格数、AND / OR位置和语句间空行沿用用户偏好。
- 表格对齐和括号内表达式宽度在“结构展开”下调整；阅读优先使用标准缩进，并按目标行宽计算。切换方式不会覆盖已经保存的表格对齐偏好。
- 预览支持简单查询、多表关联、完整NC分页例子和粘贴自己的SQL。没有连接时NC示例使用Oracle；手动指定方言仍优先。显示格式化前后的文本行数及最长行，窄窗口上下展示并视觉折行。
- 编辑器的格式化选项菜单仍提供选中/当前语句/整个脚本，另用分隔线区分排版方式。选择排版方式只保存偏好，下次主按钮或快捷键按该方式格式化。
- 输入数值需要Enter或保存按钮确认；持久化失败明确提示，会话内仍生效，同值允许重试。
- 预览输入不执行、不进入SQL标签或应用草稿；解析失败保留原文并显示检查SQL或方言的恢复提示。迟到的异步结果不会覆盖新输入/新偏好的预览。

## 实现边界

`sqlFormat.ts` 统一读取布局偏好，先用既有公开方言接口生成结构，再交给 `sqlReadingLayout.ts`。阅读布局只合并已识别的完整兄弟字段、短子句和可完整内联的括号分组，FROM子查询少占一级额外的子句缩进；不读取引擎私有AST，不用正则批量删除SQL换行。

`sqlLayoutTokens.ts` 保护引号、Oracle q/nq字符串、MySQL转义与注释、PostgreSQL dollar字符串、SQL Server / SQLite方括号标识符、注释和括号深度。多行token涉及的物理行不能被裁切或重缩进；注释涉及的行不能合并。最终对照展开前后的token内容，不确定就返回既有展开结果。

应用设置提供的方言走阅读布局；额外的未验证方言和sql-formatter禁用区域沿用已有排版，不做新的收拢。CASE、CTE、UNION与子查询保留结构边界。目标行宽是软上限，完整字符串、标识符或不能安全拆开的表达式可能超宽。

编辑器、范围处理、脚本逐条兜底仍共用 `formatSql`。本轮没有更改现有的选区边界、model/version过时保护、坏语句保留和一次撤销编辑机制。
