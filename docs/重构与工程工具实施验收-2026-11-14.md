## 字段读写命令契约

`workspace/executeCommand`，命令 `ncforge.fieldAccesses`，参数 `[{uri,line,character}]`（行列 0 基）。返回 `{name,references:[{uri,range,access,accurate}],truncated}`。`access` 为 `read`、`write`、`readWrite` 或 `unknown`。

SearchEngine 先按具体 IField 绑定查引用，AST 再确认相同字段并识别赋值左侧、复合赋值与 ++/--。二进制或无法确认 AST 的引用为 unknown，不能按文本推断。最多 2000 处、20 秒。

## 顶部 JAR 搜索的附件源码打开

`read_library_file` 对 class 先读取当前及关联工程 `.classpath` 中与完整二进制路径一致的附件；无显式附件时复用 NC 同目录 `xxx_src.jar` 约定。根据 class 的正式 `SourceFile` 属性匹配包内 `.java`，内部类可定位外层源文件，合法含 `$` 的顶级类不会被简单截断。缺属性时只尝试精确类文件名，不猜同名外层源码。对应成员缺失或不可读才回退 CFR；根外附件拒绝读取，保留包内路径和 4 MiB 解压限制。

返回的 `sourceOrigin` 在只读提示中显示准确附件与包内路径。保存附件后刷新已打开的 JDT 类缓存和同一二进制路径的顶部搜索标签。前端验证覆盖真实源码/反编译/资源分类、同名不同 JAR 不混用，以及无语言服务时已打开搜索标签仍刷新并保留钉住/预览状态；库地址与工程工具 2 文件合计 7 条通过，相关 4 个前端模块 ESLint 通过。Rust 新增 2 条测试覆盖完整路径、内部类 SourceFile、截断数据、GBK、缺成员回退、根外拒绝和默认附件；已包含在最终库回归1218通过、0失败、18按环境跳过的结果中。

## 实际边界

- 当前批量检查和结构化搜索覆盖文件/当前语言服务模块；跨多个模块的工作区批次尚不是一个统一操作。批量修复具体是组织导入，复杂成员结构模板与通用全部问题自动修复不宣称支持。
- NC 注册、XML/反射等非 Java 语义调用无法由 Java 方法签名或重命名自动证明完整；提示用户核对。
- 暂存移开只支持有可读 SVN BASE 的既有文本文件；新增、删除、移动的 SVN 元数据不作为内容副本的一部分。未纳管文件仍能保存副本，并在恢复时安全新建已缺失的文件。
- 每工程最多 20 份/64 MiB 副本，单份最多 200 文件/16 MiB；达到预算明确停止，不静默淘汰。
- 提交前 Java 检查消费当前诊断，不代替完整编译。库版本检查是文件名候选诊断，不等于已经证明二进制冲突。
- Java/NC 日常代码区之外的完整语言插件生态不属于本批实现；新增 UI 仍沿既有 token 与材质。
