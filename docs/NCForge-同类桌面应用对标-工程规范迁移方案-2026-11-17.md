# NCForge 同类桌面应用对标：工程规范迁移方案

- 日期：2026-11-17
- 性质：**决策稿**，不是完成度台账。任何「已实现 / 未实现」以当场 grep 为准；本文只回答「谁做得好、值不值得抄、抄成什么样算抄到了」。
- 上一份《桌面端 UI/UX 顶尖化》解决的是「界面是否体面」，本份解决「**工程地基是否配得上这个界面**」。两者不重叠，本份不重复令牌 / 密度 / 弹层宽度 / 三态判据。

## 一、样本：为什么看这几个

选样标准只有两条：**技术栈同源**（Tauri + Rust 核心，或 Rust 核心 + Web 前端）、**已进生产**（有真实用户在装、在升级、在报 bug）。不选纯 Electron 样本，因为它们的进程模型和更新链路教不了我们什么。

| 样本 | 栈 | 为什么值得看 | 与我们场景的距离 |
|---|---|---|---|
| **GitButler** | Tauri 2 + SvelteKit + Rust workspace（50+ crates） | 公开信息里**架构分层写得最清楚**的 Tauri 2 应用；GUI 与 CLI 共用一套引擎；错误用 thiserror 类型化；E2E 跑编译后的二进制 | 同为「替换专业桌面工具的客户端」，工具链几乎一样 |
| **Spacedrive** | Tauri 2 + React + Rust（PRRTT） | 用 Specta **从 Rust 类型生成 TS 客户端**；核心抽成 daemon，桌面 / web / 原生外壳共用 | 文件系统密集型，和我们「工程目录 + 索引」形态接近 |
| **Noir** | Tauri + SolidJS + Monaco + AG-Grid | 「键盘驱动」不是口号：连接、切库、执行、切标签全可键盘完成；大表快渲染 | **数据库页的直接对标** |
| **QoreDB** | Tauri + React + Rust | 按环境（开发/预发布/生产）对高风险 SQL 分级告警；凭证加密；只读模式 | 同上，且它把「防误操作」做成了产品特性 |
| **Hoppscotch Desktop** | Tauri + Rust core | Rust 侧执行 HTTP，绕开浏览器同源限制 | 说明「重活放 Rust、UI 只管呈现」的边界在哪 |
| **Gitify** | Electron → Tauri | 迁移后安装包缩小约一个数量级；有公开的迁移复盘 | 证明「体积 / 启动」是可兑现的卖点，不是宣传话术 |
| **JetBrains IDEA** | JVM / Swing | `Help › Collect Logs and Diagnostic Data` 是行业事实标准：一键出 zip，含日志与线程转储，**打包前弹敏感数据确认** | 我们的用户就是从 IDEA 过来的，他们会拿这个做期待 |

另外两条规范来源：Tauri 2 官方的 Isolation Pattern 与 CSP 自动 nonce/hash 机制。

## 二、可迁移优点总表

十三行，一行一个判断。**「抄」= 直接照搬其形态；「改」= 借思路但换实现；「不抄」= 明确不做，附理由。**

| # | 优点 | 出处 | 我们现状（证据） | 结论 |
|---|---|---|---|---|
| 1 | 崩溃与异常留现场，且能一键取证 | IDEA 诊断包、GitButler undo 时间线 | 前端有 `ErrorBoundary` 三层 + `frontendLog.ts` 落盘；**Rust 侧只有 `env_logger` 到 stderr，无 `panic::set_hook`** | **抄**（P0-1） |

| 9 | 大表 / 大 diff 的渲染预算与互锁 | Noir（AG-Grid）、GitButler（rAF 预算挂载、大 diff 互锁） | 有虚拟列表与 `DENSITY_ROW_H`；无「超阈值降级渲染」的显式互锁 | **改**（P1-5） |
| 10 | 启动耗时是**可红的数字**，不是日志 | Gitify 迁移复盘、Zed 帧预算 | `boot_timing` 三段打点 + `check-boot-path` 静态门禁；数值需人工喂 `--boot-log` | **改**（P0-3） |

## 三、三条主线（方案的骨架）

不做「优点清单平铺」，因为那会变成 12 个都想要、一个都做不完。下面三条能串起全部 P0/P1，也能解释为什么某几项我们主动不做。

### 主线一 · 现场：崩了要有证据

产品的专业度越高，用户越**不会**描述故障。NC 开发者遇到问题只会说「刚点了一下就没了」——他们不会去看日志目录，也不该被要求去看。

同类产品把取证做成了产品能力：IDEA 一键出 zip，且**打包前弹敏感数据确认**（不偷偷打包）。GitButler 的 undo 时间线是另一种「现场」——让用户自己回到出事前。

我们现在的非对称很危险：
- 前端崩了 → `ErrorBoundary` 三层 + 落盘 + 重载入口，**有现场**；
- Rust 崩了 → 进程直接消失，窗口没了，用户拿不到任何东西，我们拿不到任何东西。

> 判断标准：不是「有没有日志文件」，而是**用户能不能在 30 秒内把一个能定位问题的包交给我们**。

### 主线二 · 单一真源：跨语言边界必须有一端是生成物

Tauri 的分层把前端与核心之间压缩成「JSON 序列化」这一条通道。这条通道上的一切——命令名、参数、返回结构、错误——只要两头各写一遍，就一定会漂。

同类的做法是一致的：GitButler 用 schema 宏导出 TS 类型包，Spacedrive 用 Specta 生成 `ts-client`，且生成物入库、过期即红。

我们目前只生成了**命令名**。这意味着：命令拼错能拦住（这是好事），但**字段名、可选性、枚举值、错误形态全是手写**。439 处 `Result<_, String>` 让错误在 TS 侧退化成 `string`，前端只能用正则去翻译英文原文——这条链一旦某条 Rust 文案改了措辞，翻译就静默失效。

> 判断标准：改一个 Rust struct 的字段，`tsc` 是否**当场**红。现在不会。

### 主线三 · 可测：关键路径不能只靠人手点

21 个 acceptance 脚本全部跑在浏览器里对着 vite 开发服务器。这套东西有价值（覆盖了纯前端逻辑），但它**天然测不到 Tauri 层**：窗口创建、单实例唤醒、退出拦截、更新安装、文件对话框。这些恰好是「一坏就是全坏」的部分。

GitButler 的做法是 Playwright 直接驱动编译后的二进制（blackbox + Docker）。我们不一定要一步做到 Docker，但至少要有一条「跑真二进制」的冒烟路径。

> 判断标准：`npm run tauri dev` 打不开窗口这件事，有没有一条命令能自动发现。

## 四、落地路线

排序依据：**用户可感知度 × 故障后果 × 实现成本**，不是「先进程度」。

### P0-1 · 崩溃现场与一键诊断包

**做什么**

1. Rust 侧装 `panic::set_hook`：记录 panic message、file:line、线程名、backtrace（`RUST_BACKTRACE=full` 等价），写进 `config_dir/logs/rust-panic.log`，同一 panic 指纹 5 秒内去重（对齐 `frontendLog.ts` 已有策略）。
2. 落一个「异常退出标记」：启动时写 `session.lock`，正常退出删除。下次启动若标记还在 → 判定上次异常退出，状态栏给一条**可点**的提示（读 `data-tone="bad"` 胶囊，不弹窗）。
3. 新增 `export_diagnostics` 命令，产出 `ncforge-diagnostics-<timestamp>.zip`，内容固定为六项：
   - `meta.json`：版本、构建时间、OS 版本、WebView 版本、显示器数与缩放、locale、密度档 / 外观档、启动分段耗时；
   - `logs/`：`client.log`、`middleware.log`、`frontend.log`（各自保留的轮转文件）；
   - `crashes/`：`rust-panic.log` 与前端 `record` 的错误摘要（脱敏后）；
   - `state.json`：最近打开的工作区**路径哈希**、打开的标签数量、DB 连接名称与 env（**不含 host / user / 密码**）；
   - `manifest.txt`：包内文件清单与每项来源，便于用户自己先看一眼；
   - `README.txt`：说明「这个包里有什么、没有什么、发给谁」。
4. 打包前必须弹一次确认页（学 IDEA）：**逐项列出将要包含的内容**，明确写「不含数据库密码、不含连接串、不含源码内容」，用户可勾掉任意一项再导出。

**为什么值得**：这是投入产出比最高的一项。它同时降低了我们的支持成本和用户的放弃率；而 NCForge 的替代对象是 IDEA，用户会拿 IDEA 的 `Collect Logs` 做基准。

**判据（可机器验证）**
- 单测：构造一次 panic，`rust-panic.log` 出现且含 file:line；连续两次同 message 只写一条。
- 单测：`export_diagnostics` 的包内文件集合与白名单**完全相等**（多一个文件即红），且对 `state.json` 做断言：不含任何形如 `password|pwd|jdbc:` 的键值。
- 一次性脚本：起 dev server + 真二进制，触发一次 panic，重启后状态栏出现异常退出胶囊。

**风险**：诊断包是**新的数据外泄面**。三条硬约束必须写进代码注释并在测试里钉住：① 白名单而非黑名单（不列举「排除什么」，只列举「包含什么」）；② 路径一律哈希或只保留末级目录名；③ 导出目录固定为 `Downloads` 或用户当场选择，不默认放工程目录。

### P0-2 · 跨 IPC 类型生成（棘轮式，不搞大改造）

**做什么**

1. 引入 `tauri-specta`（或 `ts-rs`，二选一，见下方取舍），把「命令签名 + 入参 + 返回 + 错误枚举」生成到 `src/lib/bindings.generated.ts`，与现有 `commandContract.generated.ts` 并存——后者继续管命令名与注册表校验，前者管类型。
2. 先把**一个模块**打通端到端：选 `frontend_log_cmds` + `system.rs`（入参简单、调用方少、无状态），验证生成链路与热重载体验。
3. 建立棘轮：`scripts/check-binding-coverage.mjs` 统计「已纳入生成的命令数 / 293」，**只许增不许减**，基线入库。新命令必须纳入，否则红。
4. 错误类型收敛：新增 `AppError`（thiserror），至少提供 `code: &'static str` + `class: ErrorClass` + `detail: String`。旧命令继续返 `String`，但**新命令禁止**再返 `String`，由门禁拦。前端 `friendlyError.ts` 优先按 `code` 查表，正则降级为兜底。

**取舍：tauri-specta vs ts-rs**

| | tauri-specta | ts-rs |
|---|---|---|
| 解决范围 | 命令签名 + 入参 + 返回 + 事件，**一次到位** | 只生成 struct 类型，命令签名仍手写 |
| 侵入性 | 运行时 handler 不用换，但要额外声明一份 `collect_commands![...]` 表用于导出 | 零侵入，只加 derive |
| 对我们最大的风险 | 命令表真源在 `commands/mod.rs` 的 `nc_forge_commands!` 宏里，`collect_commands!` 等于**第二份命令清单**——这正是现有契约门禁花力气消灭的东西 | 无新增真源 |
| 结论 | 除非能由宏同时展开两份，否则引入即制造第二真源 | **更契合现状**：命令注册表已自研且有门禁，只缺类型 |

**建议 ts-rs**：我们已有的命令契约机制是资产，不该被替换；缺的只是「结构体 → TS 类型」这一层。命令名继续由 `gen-command-contract.mjs` 三层校验，两者职责不重。

**判据**
- 改 Rust struct 一个字段名 → `tsc --noEmit` 当场红（这是本项唯一真正的验收标准）。
- `check-binding-coverage.mjs` 的基线只增不减。
- 新命令返 `Result<_, String>` 时门禁红（按 `commands/mod.rs` 的宏表逐条扫函数签名）。

**风险**：生成物会引入大量 diff，必须入库（与 `commandContract.generated.ts` 一致），否则 CI 与本地会漂。

### P0-3 · 启动耗时：从「能测」变成「会红」

**做什么**

1. 现有 `boot_timing` 的三段（tree / index / diag）+ 首帧已经足够，**不改埋点**，只补出口：`perf-baseline.mjs` 默认读最近一次启动日志，不需要人工 `--boot-log`。
2. 采用**同机滚动基线**而非绝对阈值：保留最近 10 次冷启动的分段中位数，超过基线的 120% 报警（写进 `boot-budget.json`，与 `bundle-budget.json` 同构）。
3. 做成独立命令 `npm run boot:check`，**不进 pre-commit，也不塞进 `release:verify`**。理由要写清楚：CI 机器与开发机 CPU / 磁盘差异会让绝对阈值变成噪音，跨机红线必然导致「本地绿、CI 红」或反向的麻木；而 `verify-update-chain.mjs` 校验的是**线上发布产物**（网络 + 签名），把本机耗时塞进去语义不符、还会拉长那次网络校验。

**判据**：连续两次冷启动，第二次若人为注入 500ms 延迟（sleep 在 `tree` 段），`perf-baseline` 必须变红。

**风险**：「冷启动」定义要钉死（进程启动到首帧 rAF，不含量测前的预热），否则数据不可比。

### P1-1 · 键盘完备度审计（报告，不是门禁）

**做什么**：静态扫 `src/components/**` 里带 `onClick` 的可交互元素，与 `commandRegistry` / `keymap` 已注册的动作做粗匹配，输出「Top 30 无命令入口的可点动作」报告（`npm run keyboard:audit`）。

**为什么只做报告**：全自动映射「DOM 元素 → 命令」不可能精确，做成门禁必然产生一堆豁免。业界的做法（Linear / Raycast）也是「动作清单 vs 面板注册表」的人工 diff。**报告的价值在于让缺口可见，不在于拦人**。

**判据**：报告能列出至少 20 条真实缺口，且第一批修完后数字下降。

### P1-2 · 真二进制冒烟（三条路径）

**做什么**：`tauri-driver` + WebdriverIO，覆盖三条最贵的路径：
1. 启动到首帧（窗口出现、DOM 可交互）；
2. 打开一个 NC 工程（文件树出节点）；
3. 有未保存改动时点 X → 出现三选一 → 取消后进程仍在。

**判据**：三条里任意一条被破坏，脚本非零退出。

**风险**：Windows 上需要版本匹配的 `msedgedriver`，升级 Edge 就会断。**定位为本机脚本，不进 CI**，并在脚本头注释写明「断链时先怀疑驱动版本，不是产品坏了」——这条经验值得写下来，否则下次会被当成回归查半天。

---

### P1-3 · 无障碍最低线

**做什么**：三件小事，半天量级：
1. `<a href="#main" class="skip-link">跳到主要内容</a>` + 内容区 `id="main"` + `tabIndex={-1}`；
2. 全局 `:focus-visible` 兜底样式（现有令牌体系里加一条，不新增裸色值）；
3. 脚本扫「无可达名称的图标按钮」：`<button>` 内无文本且无 `aria-label` / `title`，输出清单后补齐。

**判据**：①②有单测或验收脚本断言存在；③的清单清零并进 `ui:check` 的棘轮（只降不升）。

### P1-4 · 更新失败自愈

**做什么**：Tauri updater 本身**不支持回滚**，不要假装能回滚。现实可做的是：
1. 更新源同时保留**上一个 stable 版本的完整安装包**，`check_update` 的返回里带一个 `prevStable` 字段；
2. 更新后首次启动若 60 秒内出现 Rust panic 或连续两次异常退出，状态栏提示「回到上一版」并给出安装包下载直链 + 校验值；
3. 更新失败的错误分类已很完整（`ErrorClass` + 验签阻断），**不动**，只补一个「连续失败 ≥3 次就隐藏自动检查，改为手动入口」，避免每次启动都撞同一堵墙。

**判据**：构造一次「安装后立即 panic」，重启后出现回退入口且链接可达。

### P1-5 · 大 payload 与大数据量的显式互锁

**做什么**（借 GitButler / Noir）：
1. 渲染侧：diff / 结果集超过阈值（行数或字符数）时**主动降级**——关语法高亮、关行内 diff、只渲染可视区，并在界面上**明说**降级了（学三态诚实原则，不许静默变差）；
2. 传输侧：跨 IPC 的单次 payload 上限设一个明确数字，超限改为「Rust 拿数据、给前端句柄 + 分页取」，不再整包过桥。

**判据**：构造 5 万行 diff，首屏可交互时间 < 1s，且界面出现「已简化渲染」标记。

---

### P1-6 · 重启无痛：把光标和滚动位置也恢复

**做什么**

`tabPersistence.ts` 现在只回答「哪些文件开着、哪个在前台、有没有分屏」（:10-14）。IDEA / VS Code / Noir 重启后连**光标停在哪一行、滚到哪、哪些折叠着**都还在——这是「专业工具」和「带标签的编辑器」的分界。

1. 快照扩三个字段：`{ cursor: {line, column}, scrollTop, folded?: number[] }`，按文件路径存，随标签快照一起写；
2. 上限从「20 条」改成**字节预算**（如 64 KiB）：20 条路径才 2 KB，数量上限既没防住配额，又在小工程里显得抠；
3. 补 `pagehide` 兜底：现在只有 400ms 防抖 + 卸载补写（`useTabSession.ts:70-91`），进程被强杀时最后一笔会丢；`dbHistory` / `sqlUsage` 已经有 `pagehide` 写法，照抄即可。

**判据**：把光标停在某文件第 120 行滚到中部 → 杀进程 → 重启，光标与滚动位置一致；单测断言超预算时按文件数从旧到新淘汰，而非直接截断。

**风险**：`folded` 是 Monaco 的折叠区号，文件改动后会漂。取舍是「恢复失败就不恢复」——宁可少恢复，也不要把光标扔到错误的位置。

### P2-1 · Isolation Pattern（现在不上，写清前提）

Tauri 官方强烈建议启用：在 WebView 与核心之间插一个沙箱应用，拦截并可用 AES-GCM 加密所有 IPC。代价是每次 IPC 都多一次加解密。

**我们的威胁模型不成立**：无插件市场、无远程内容、无第三方脚本、capability 已收窄到 12 个 permission 且有过测试盯「不许前端直授插件权限」。威胁主要来自供应链（构建期依赖），而这一层由 CSP + 锁文件 + 现有门禁覆盖。

**重启条件**（满足任一即重新评估）：引入任何远程加载的界面或脚本；引入插件 / 扩展机制；引入需要从外部 URL 驱动的自动化能力。

---

### P2-2 · 引擎与外壳解耦（只记录，不排期）

GitButler 的 `but-api` 与 Spacedrive 的 daemon 都在做同一件事：**让引擎能被 GUI 之外的入口调用**。价值在「CI 里校验 NC 工程」「批量任务脚本」「无头测试」。

**不排期的理由**：NC 开发是强交互场景，无头需求尚未出现；而拆 daemon 会重写进程模型、退出链路、单实例语义——与现有 `quitGuard` / `app_lifecycle` 的收益比不划算。若将来出现「NC 工程 CI 校验」的明确需求，再从「抽出纯函数库 + 一个薄 CLI」开始，而不是直接 daemon 化。

---

### P2-3 · 模块依赖方向约束（低优先）

GitButler 用两代 crate 前缀（`gitbutler-*` vs `but-*`）强制「新代码不许依赖旧代码」。我们是单 crate + 56 个 commands 模块，目前靠体量红线与人工 review。

**做法**：先只加一条静态检查——`commands/*.rs` 不许直接 `use` 另一个 `commands/*` 的内部实现（应走底层模块）。成本低，能挡住「命令模块互相调用」这种最常见的腐化。

## 五、明确不做

写下来是为了防止下次「对标」又把这些捡回来。每条都带理由，不是拍脑袋。

| 不做 | 理由 |
|---|---|
| 系统托盘 | 已有显式决策（`main.rs` 头注释、点 X 即退出）。托盘会引入「关窗不退出」的歧义，与现有 `quitGuard` 三选一冲突 |

## 九、落地记录（2026-11-17，第二批）

### P1-6 重启无痛：光标与滚动一起恢复 —— 已完成

| 东西 | 位置 | 说明 |
|---|---|---|
| 视图快照 | `src/lib/editorViews.ts` | 只存 `cursorState` + `{scrollLeft, firstPosition, firstPositionDeltaTop}`；**不存折叠**（见下）；64 KiB 字节预算，超了按最旧淘汰 |
| 上报 | `EditorPane.tsx` | 光标 + 滚动节流 300ms；切文件 / 卸载时 `flush` 立即落 |
| 恢复 | 同上 | `pickRestoreView(内存, path)` → 内存优先，进程重启后退到磁盘 |
| 兜底 | `useTabSession.ts` | 标签快照补 `pagehide`（原来只有 400ms 防抖 + React 卸载补写，强杀时两条都不跑） |

**四个判断，都是实测出来的而不是推出来的：**

1. **`scrollTop` 存不得，必须用 `firstPosition`。** Monaco 的 `reduceRestoreState` 分两支：有 `firstPosition` 就按「视口首行的模型位置」反算偏移（文件行数变了会自动夹住），没有则走老格式兼容分支读 `scrollTopWithoutViewZones`。只给 `scrollTop` 时读到的正是 `undefined` —— 界面直接滚回顶部。所以 `trimViewState` 的规则是「`firstPosition` 不在就整条不存」。

2. **折叠状态（`contributionsState`）刻意不恢复。** 它存的是视图行号，文件一改就指到别处。恢复成 `{}`（全部展开）比恢复出一堆用户没折叠过的区域好。

3. **节流 300ms 是必需的。** `onDidScrollChange` 滚动时每帧回调，每次都 `saveViewState()` 会把主线程拖进无谓计算。

4. **`pagehide` 不能省。** 进程被强杀 / 关窗口时 React 清理函数不一定有机会跑，防抖里那一笔就永远丢了。

**实测（不是单测）**：临时 `probe-views.html` + playwright 在真 Monaco 上跑——
- 400 行文档停在第 300 行第 7 列、`scrollTop=5471` → 序列化 → 新建编辑器 → 恢复后**完全一致，`scrollDelta=0`**。
- 边界：把同一份快照恢复到只剩 50 行的文档 → 光标被夹到第 50 行末列、`scrollTop=931 ≥ 0`、不抛错。
探针跑完即删，不进仓库。

**单测 15 条**（`editorViews.test.ts`）钉住：`firstPosition` 缺失不存、损坏存储不抛错、位置不变不重写、超预算按最旧淘汰（而不是整份丢）、上报器节流与 `flush`、内存优先于磁盘。

**一处没做，说明理由**：方案原本要把标签快照（`tabPersistence.ts`）的「最多 20 个标签」也改成字节预算。这次只在新写的视图快照上用了 64 KiB 预算，标签快照保持 20 条——因为那 20 条被 4 条既有测试钉着（超限时前台与分屏各自保槽位、工作区保留 20 份），改语义要连带重写这些断言，而收益只是「能恢复 21 个以上标签」，不抵风险。视图快照是新增代码，没有历史包袱，所以直接按字节来。

### P0-2 跨 IPC 类型生成 —— 打通一个模块

**偏离方案一处：用自研生成器，不用 ts-rs。** 理由写在 `scripts/lib/ts-mirror.mjs` 头部：
- `tauri-specta` 要在 `invoke_handler` 处再声明一份 `collect_commands![...]`，等于**第二份命令清单**——正是 `gen-command-contract.mjs` 在消灭的东西；
- `ts-rs` 导出要么挂在 `cargo test` 上（每次测试都写文件），要么单开 export bin，且版本间 API 变过几轮；换来的能力与「解析我们自己主动标记的少量结构体」几乎相同。

沿用现有脚本这一套（同一份源码、同一套门禁），只补「结构体 → TS」这一层，零新依赖。

| 东西 | 位置 | 说明 |
|---|---|---|
| 标记 | `config.rs` / `system.rs` | `// @ts-mirror response`（出参）/ `// @ts-mirror request`（入参） |
| 生成器 | `scripts/lib/ts-mirror.mjs` | 类型映射 + `serde` 属性；不支持的形式**报错不猜** |
| 产物 | `src/lib/bindings.generated.ts` | 4 个结构体 / 59 字段，入库 |
| 契约断言 | `src/lib/bindings.check.ts` | 纯类型，无运行时代码；tsc 阶段红 |
| 棘轮 | `scripts/bindings-baseline.json` | 已镜像结构体不许消失、字段数不许减少 |
| 门禁 | `gate-plan.mjs` | `bindings` 进 frontend scope + pre-commit（实测 0.9s） |

**方向必须区分**：`Option<T>` 在出参是 `T | null`，在入参是 `field?: T`。混用会写出「传 null 表示不改」这种后端不认的类型。`// @ts-mirror request` 就是为此存在的。

**打通模块立刻抓到一处真漂移**：手写 `AppConfig` 比 Rust 少 **12 个字段**（`client_heap_mb` / `svn_user` / `db_conns` / `patch_out_root` …）。补齐后断言才绿——这就是本项目最直接的「手写类型会漂」证据。

**红灯验证两条**（都做，不靠推断）：
- 改生成物里一个字段名 → tsc 三条断言红（键集合 + 双向兼容）；
- 给 `AppConfig` 插一个字段不重新生成 → `bindings:check` exit 1。还原后 diff 只剩 3 行注释。

**没做的**：`DbConnConfig` 与前端 `DbConn` 不做相等断言——`DbConn` 是另一个命令的出口（带 `hasPassword`、`env` 是联合类型），不是同一份结构。

**当时留下的**：方案里的「错误类型收敛 `AppError`」原计划下一批做，理由是要动 439 处签名。实际做的时候发现**这个判断只对了一半**：建类型 + 建门禁不碰存量命令，只有「批量迁移」才需要动 439 处。见第十节——补上了。

所以「439 处签名」是迁移的代价，不是建立契约的代价。混在一起判断，会让一个本来一天能收口的事被无限推迟。

**`src-tauri/src/app_error.rs`**：`AppError { code, class, detail, hint? }`，序列化成**对象**过 IPC。四条约束都有理由，不是凑字段：

- `code` 是**契约**（前端按它查表），`detail` 是**证据**（排障看原文）。两者混在一句里，前端就又只能靠正则猜。
- `class` 五档（input / environment / unavailable / data / internal）：区分「用户改一下就能成」和「我们的 bug」。只看 detail 分不出来。
- `Display` **只输出 `detail`**：`log::warn!("{e}")` 会用到它，把 code 拼进去等于给每条日志加一段噪音。
- `From<io::Error>` 按 `ErrorKind` 分流（NotFound / PermissionDenied / TimedOut / AlreadyExists / InvalidInput）。这是「结构化」相对字符串的唯一实际收益——`AlreadyExists` 归 `input`（换个名字就行），不是 `environment`。

**前端这一步最容易踩空**：后端改成返对象后，所有 `catch` 分支里的 `String(e)` 会变成 `[object Object]`，**错误信息当场消失且不报任何错**。所以 `src/lib/tauri.ts` 的 `invoke` / `invokeOrToast` 统一过 `toIpcError`：对象 → `IpcError extends Error`（`message = detail`），字符串与既有 `Error` 原样透传。判据只看**形状**（有没有 `code` + `detail`），不维护「哪些命令已迁移」的名单。

`friendlyError` 改成**结构优先、正则兜底**：认识的 `code` 直接出人话；不认识的 code 有 `hint` 用 `hint`、没 hint 退回原来那十几条正则。这样后端新增 code 而前端还没加文案时，行为与改造前一致，不会变更差。

**迁移示范 6 条**（都是本批新增过的命令，本来就符合「新命令」口径）：`diagnostics_preview` / `export_diagnostics` / `diagnostics_reveal` / `frontend_log_append` / `frontend_log_read` / `frontend_log_reveal`。其中 `diagnostics_preview` 顺手**去掉**了 `Result`——它只 stat 白名单里的固定路径，没有可失败的输入，套一层 `Result` 只是给前端多一个永远走不到的 `catch`。

门禁 `npm run error:check`：扫 `#[tauri::command]` 的返回类型，`Result<_, String>` 记进 `scripts/error-contract-baseline.json`（**277 条**），新增即红。比较分两路——`added` 红、`migrated` 只提示；只提示不红是因为红了会逼人「为过门禁去改基线」，与只许减的方向相反。

**红灯验证**（做了，不靠推断）：临时加一个 `probe_legacy_error() -> Result<(), String>` 命令 → 门禁 exit 1 并指出文件与命令名；删掉后回到 277 条、exit 0。

### 顺带 · `useTreeLoad` 拆分 —— 已完成

`component-size` 卡在 `useTreeLoad.ts` 305 行（超出 300 红线 5 行）。拆出 `useTreeReveal.ts`：**「把任意路径展开到可见」是独立职责**——`toggle` / `expand` 只动 `expanded` 集合、假定用户顺着树点；`reveal` 要从工程根逐层读盘，还要抹平压缩中间包、包目录、多工程根三种结构。两种节奏缠在一个文件里，本来就该分开。

拆的过程踩到一个真 bug，值得记：依赖里传内联箭头 `clearFilter: () => setFilteredTree(null)`，**每次渲染都是新引用**，把 `useCallback` 的恒定性打掉了，`useTreeLocate` 的 effect 跟着反复重跑，4 个定位测试当场红（「从 A 跳到 B 时展开真实目录」找不到行）。改成直接传 `setFilteredTree`（`useState` 的 setter 天然稳定）后 52 条全绿。**这一条也写进了 `useTreeReveal.ts` 的注释**——拆分时传函数给 hook，稳定性是契约的一部分。
