当前样式约束为：结果身份条最小高度 40 px，结果工具条最小高度 36 px，SQL 结果状态条最小高度 30 px。执行带最小高度 48 px；文档容器宽度不超过 1420 px 时分成上下文与操作两组，不超过 820 px 时继续分组。这些是代码中的布局规则，**不是所有视口下的实测高度**。

输出窗在宽视口使用两列并分别滚动设置与预览，在窄视口切为单列，并提供“查看预览”入口。浅色、深色和强制颜色模式使用既有主题语义；两种主题的实际文字对比度与裁切情况仍需运行画面核验。

## 第一批：主工作台

- 主动作区分“执行当前语句”和“执行选中 SQL”，显示真实行范围与语句数量。按钮、Ctrl+Enter 与执行器共用编辑器目标列表，空 SQL 的禁用原因直接可读；整个脚本、执行计划、回放等能力保持可达。
- 执行时冻结本次范围，编辑器后续改动不会把正在执行的范围改成下一条 SQL。停止沿用实际会话槽与既有取消反馈，不提前假定数据库已经停止。
- 会话提交模式与连接级只读范围可见。没有待提交写入时，提交 / 回滚进入会话菜单；待提交、会话丢失和事务结果未知状态保留在事务条。
- 结果在请求开始时保存不可变的连接目标、来源、Schema、SQL、编辑范围 / 版本与时间。改动相关 SQL 后显示“结果尚未更新”；改动其他语句时避免误报；重复文本无法可靠定位时提示核对来源。
- 旧结果的来源显示使用执行快照。SQL 和表页在连接目标或 Schema 变化后显示提示；表页写回和服务端重查核验来源，文件重查传递冻结来源。
- 普通续取失败在当前结果页脚保留原因与“重试加载”；会话 / 游标失效和内存上限不反复重试，已加载行继续可读。
- 查询结果与隐式结果集标签支持方向键、Home / End 和面板关联。网格中 Ctrl+F 打开本地筛选，Escape 清除并返回网格；表头提供可发现的列菜单及键盘入口；检查器关闭后返回原单元格。

## 第二批：比对文档

结果工具条中的“比对”为分体入口。没有 A 时主动作固定当前结果；已有 A 时主动作打开 A / 当前结果 B。菜单提供更新 A、查看来源、清除 A 和原有关联记录入口。

共享 A 摘要持续显示来源、Schema、时间、行数与部分 / 完整状态。摘要为单行按钮，完整 SQL 与来源进入详情窗口，避免展开摘要挤压结果网格。

比对范围为两份全部已加载数据，包含隐藏列。固定和打开比对时复制并冻结快照；超过行数、单份内存或工作台可用预算时拒绝整个操作，不静默截断。对照仅在当前进程内保存。

比对页保留复合键、NULL 键、重复键、重复字段与字段不一致校验，按字段名对齐两份结果。新增、删除、修改使用文字标识；缺失记录、数据库 NULL、空字符串、空白、0 和字面量 `~` 分别表达。

网格提供双轴虚拟化、类型筛选、按键查找、只看变化字段及完整原值检查。颜色只标记变化单元格；唯一键冻结。任一来源不完整时持续提示“仅比较已加载数据，不能代表全表差异”。

“导出全部差异”输出完整比较模型及范围 / 来源信息，不受当前类型筛选、键搜索、隐藏的变化字段或虚拟视口影响。

保活范围是进入比对前最近使用的 SQL 或表文档。正常“返回查询”恢复该来源的编辑器、筛选、选区和滚动位置；后台查询失败不会移动隐藏编辑器的光标。返回和关闭比对优先选择 B 来源，B 已关闭时选择 A；两边来源均关闭时说明返回不可用。显式发起新比对会替换当前比对文档。

## 第三批：复制与输出

快速复制按钮显示实际行 × 列；有选区使用选区，无选区使用当前筛选视图。格式菜单的范围摘要与主动作一致，切换格式不扩大数据范围。

输出窗口提供“当前选区 / 当前筛选结果 / 已加载全部行 / 重新查询导出全部”。顶部、预览与底部使用同一份范围摘要；多结果集 Excel 输出使用创建任务时的结果集摘要。字段选择、字段顺序、高级编码 / NULL / 引用 / SQL 选项、预设与 NC 迁移入口继续可用。

重新查询显式说明：独立只读会话，预览为样本，不使用网格本地筛选、排序或未保存修改，也看不到主会话未提交数据。前后端核验冻结的连接地址 / 账号 / 引擎 / 来源标识；普通重查在独立导出会话中先设置冻结 Schema，再设置只读并查询。连接改名不会被误判成另一个目标。

NC 专用迁移沿用既有路径，并要求当前 Schema 与读取结果时一致后进入其范围复核步骤。连接目标变化时，已加载数据仍可复制和导出，重查给出明确原因。

保留任务进度、停止、完成文件阶段保护、后台运行、部分结果、失败设置恢复、重试与原生保存能力。长值预览可以省略，复制和文件输出保留原值。

## 尚待实机确认的布局效果

此前用户已允许重试本地浏览器验收，自动审批服务随后仍拒绝浏览器验收路径，返回 **`content-blocked / review failure`**。本轮没有切换到其他浏览器、CDP 或网络路径绕过拒绝。审批反馈未提供可用于判断脚本不安全的具体证据，但浏览器动作仍未获执行。

因此本报告不把设计稿或旧截图当作当前运行截图，也不宣布核心面积增加 10%、可见行数提升或所有缩放下无裁切。方案中的面积目标保留为待实测指标。

后续实机验收使用同一窗口、Windows 缩放、字号、密度、数据和面板状态：

1. 在 1366 / 1440 / 1920 宽窗口和 100% / 125% / 150% 缩放下，检查浅色、深色执行带，确认环境、范围、停止和异常事务状态可读。
2. 固定相同 SQL 与结果，分别记录编辑器可视面积和数据行区域面积；表头、工具条、页脚不计入数据行区域。用相同面板状态比较升级前后，核验“核心总可用面积增加至少 10%”，不通过调小字号达标。
3. 检查长中文连接名、长 Schema、多结果标签、A 摘要、复制计数、筛选输入及页脚是否互相挤压；确认分组断点符合实际内容。
4. 打开长值检查器与完整来源，检查窄结果区域下覆盖、滚动与关闭后的原格焦点。
5. 从 SQL 和表页进入比对并返回，核验实际 Monaco 光标、网格横纵滚动和选区；后台查询完成 / 失败时保持当前比对阅读位置。
6. 用部分 A / 完整 B、多字段、复合键、大量差异与超长值，检查双轴滚动、冻结键和范围说明。
7. 在窄窗和低高度窗口切换输出范围、格式、字段与高级选项，确认顶部、预览、底部摘要同步，主动作始终可达。
8. 在真实只读测试库核验冻结 Schema 的独立重查、保存、停止、部分输出、失败重试与 NC 迁移入口。
