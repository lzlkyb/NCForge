# SQL 多语句结果展示升级方案

## 目标与现状

一次选中或执行两条用分号分隔的 SELECT 后，每条查询得到独立结果页，两份数据都可切换查看，并可一键双栏同时查看。每个结果保留自己的筛选、排序、滚动、选区和加载状态。

方案已确认并落实到代码；实现和测试记录见[《SQL多结果查询实施与验收-2026-11-11》](SQL多结果查询实施与验收-2026-11-11.md)。以下现状记录保留为升级前的依据。数据库验证使用离线代理，未连接真实数据库执行用户 SQL。

源码核查发现：

- `SqlEditor.tsx` 已支持选中多条 SQL、执行整个脚本；未选中时默认执行光标处的一条。
- `SqlToolbar.tsx` 的“执行整个脚本”在下拉菜单中，主按钮默认执行当前语句。
- `dbActions.ts:runStatements` 会逐条执行、累计保存查询结果，但每条完成后都把当前页切到最新结果。
- `ResultPanel.tsx` 已存在“数据 1 / 数据 2”标签；数据区通过 hidden 属性切换，一次只显示一个结果表。
- 前端 `dbStore.ts`、Rust 引擎 `db_rust.rs`、JVM 桥均使用同一会话的单个活动查询游标。下一条查询会影响上一条结果的续取，前面的结果仍保留已读取数据。

这些是源码确认的现状；用户本次到底是只执行了一条，还是两个结果页未显示，需要在实施开始时复现。不能将“已有多个结果标签”当作现场问题已经解决。

## 方案比较

| 方式 | 适合情况 | 取舍 |
| --- | --- | --- |
| 独立结果标签 | 日常查看多条查询 | 空间利用最好，但一次看一张表 |
| 默认多表铺开 | 总是同时看两条查询 | SQL 多时挤压表格和编辑器，窄窗口不适合 |
| 独立标签，加按需双栏 | 日常查看与两份数据对照 | 推荐；默认紧凑，需要对照时一键切换 |

采用第三种，沿用数据库工作台的外观与交互，不新增主导航。

## 执行入口与批次反馈

1. 只保留一个“执行”主按钮：没有选区时执行全部 SQL，有选区时只执行选中内容，不常显执行条数。下拉菜单提供“执行当前语句”和“执行整个脚本”。Ctrl+Enter 与主按钮一致，Ctrl+Shift+Enter 仅执行光标处语句，Alt+X 执行全部。保留稿子中的较大执行按钮，其余工具栏按现有 SqlToolbar / DbContextBar 的图标、顺序、紧凑尺寸和连接布局还原。此处为设计稿拟定行为，生产代码接入时同步更新快捷键。
2. 同一批 SQL 使用同一会话按脚本顺序执行，保持事务、临时表、包变量与会话设置的语义。
3. 开始时为识别到的每条语句建立状态项：等待、执行中、成功、失败、已停止、未执行。SELECT 完成后将结果绑定到它自己的状态项。
4. 第一份查询数据返回时展示第一份结果；后续完成更新标签与计数，不抢走用户正在看的页。失败位置可从状态项定位。
5. 使用已有 SQL 分句规则，以分号为普通 SQL 的分隔符；字符串、注释、Oracle q 引号及 PL/SQL 内部分号不得误拆。不能靠遇到第二个 SELECT 关键字拆句，因为子查询与 UNION 都会包含 SELECT。

## 结果展示

- 结果区标题显示“查询结果（2 个）”，顶部为“查询 1 · 表名 · 行数”“查询 2 · 表名 · 行数”“执行日志”。多表查询使用简短 SQL 摘要；悬停可看完整 SQL，单击来源可定位编辑器。
- 单条查询返回零行仍保留自己的结果页，显示列名与“查询成功，0 行”。相同 SQL 执行两次也拥有不同结果身份。
- “标签 / 双栏”入口常显。双栏模式选择两份结果，各有自己的标题、工具栏、滚动和选区；复制、导出、筛选和加载更多绑定当前操作的那份结果。
- 两条 SELECT 可一键同时查看；超过两条时挑选任意两份对照。窄窗口采用上下排列，或回到标签模式，避免多张表被压成窄条。
- 多结果标签较多时保留结果总数与完整列表入口，不能仅依赖横向滚动发现其它结果。

## 每份结果的续取与资源管理

将游标绑定到结果 ID，后续读取明确携带结果 ID 和来源会话。Rust 与 JVM 桥两条路径同步支持，保持原有会话串行调度。执行第二条 SELECT 后，第一条仍可在自己的游标上加载更多，追加数据不得混入另一张表。

关闭结果、读完、关闭 SQL 页、断开连接与失效会话时释放对应资源。结果沿用现有 16 MiB 单结果 / 64 MiB 总结果数据预算，并设置有界游标数量；达到上限要显示可操作的提示。不能为了保留结果，默认把所有 SELECT 的全量数据拉进前端内存。

事务、取消和写入保护沿用现有约束。第二条失败时保留第一条成功数据；停止执行时保留完成结果，剩余语句标记为未执行。多条 UPDATE/INSERT 的摘要继续放在执行日志，避免大量写语句占满数据标签栏。

## 实施顺序与验收点

1. 先复现并锁定回归：分别验证“选中两条”“执行整个脚本”、两条相同 SELECT、零行结果，以及两条结果的数据身份。
2. 出可交互 HTML 稿，覆盖执行入口、结果标签、等待与失败状态、双栏和窄窗口，确认效果后再修改界面代码。
3. 接通批次状态与常显执行入口，改进结果标题和焦点策略。验证第二条完成时不抢页，错误或取消不丢第一条结果。
4. 实现两种引擎的结果游标管理。验证两份超过首批行数的结果能分别续取，关闭和断开释放游标，取消不影响其他 SQL 页。
5. 接入双栏真实结果组件，完成浅深色、窄窗口和较多结果标签验收。验证切换与双栏不丢筛选、排序、选区和滚动，复制、导出作用于正确结果，并通过现有 SQL 执行/事务/编辑回归检查。

最小验收 SQL：

```sql
select 1 as query_one from dual;
select 2 as query_two from dual;
```

无选区点击“执行”或选中两条后执行，必须出现两份结果，第一份值为 1，第二份值为 2；切换与双栏均正确。通过下拉菜单“执行当前语句”时，只执行光标所在一条；选中一条后点击主按钮，只返回对应的一份结果。工具栏不再显示“全部 N 条 / 选中 N 条”。

大结果续取、首条成功后次条失败、执行中停止和资源释放需要另设回归场景，不能只用以上各返回一行的示例验收。
